### 1c. Planner's choices (the simplest option the sources allow)

- **P1 Files.** One pure file for the check and the runner type (`preflight-checks.ts`), one service (`preflight.service.ts`), one controller (`preflight.controller.ts`), and one edit of the pure helper file (`markdown-text.ts`). The layout follows CEX-04 P1.
- **P2 One fence rule.** `withoutFences` (`markdown-text.ts` lines 59 to 82) keeps only the lines outside fences, so it drops lines and cannot give line numbers. `plans/CEX-04.md` line 155 says CEX-05 "may reuse" it; this plan does not use it for line numbers. The fence state machine moves unchanged into an exported helper `fencedLines(lines: string[]): boolean[]` that returns one flag per line (the opening fence, the lines inside it and the closing fence are flagged; an unclosed fence flags every line to the end). `withoutFences` is rewritten on top of it with the same output: `const lines = text.split(/\r\n|\n|\r/); const flags = fencedLines(lines); return lines.filter((_, i) => !flags[i]).join('\n');`. `maskCode` (P3) uses it too. The file's header (lines 1 and 2) requires one fence rule, so no second copy is written.
- **P3 `maskCode(text)`.** Returns text of the same length with the same line terminators. It splits the text with the capturing pattern `/(\r\n|\n|\r)/`: the even items are the lines (given to `fencedLines`), the odd items are the terminators, kept as they are. A flagged line has every character replaced by a space. The parts are joined again, and then every match of `INLINE_CODE` (`markdown-text.ts` line 14, the constant `citationIds` uses) over the whole text has every character other than CR and LF replaced by a space. Offsets and line numbers of the input hold in the output. (Checked with a one-off `node` script on the C1 fixture, section 7a.)
- **P4 Scanned text: the body.** Each file is scanned after its YAML front matter, as `splitFrontMatter(content).body` (CEX-04 P2). The unit scans "the assembled manuscript files" (line 18), and the assembled document has no per-file front matter (CEX-04 S2); the citation scan also reads the body (CEX-04 P10). Front matter is not prose (criterion 1 asks for "exactly the prose occurrences"). C1 pins this with a `TODO` in `drafts/b.md`'s front matter. Open point 1 (settled).
- **P5 Positions.** `offset` is an index into the file text as `FilesService.read(...).content` returns it; `length` is the match length. The body starts at `content.length - body.length`, because the body is a suffix of the text (`splitFrontMatter`, `markdown-text.ts` lines 25 to 55). `line` is 1 plus the number of line terminators (`/\r\n|\n|\r/`) before `offset`.
- **P6 Messages.** Fixed texts, with no token echoed: `Placeholder word left in the text.` for a word, and `Unrendered placeholder left in the text.` for a match that starts with `{{`.
- **P7 Severity.** Every placeholder finding has severity `error` (unit line 19).
- **P8 Check status.** Derived by the framework from the findings: any `error` gives `fail`; otherwise any `warning` gives `warn`; otherwise `pass` (`CHECK_STATUSES` and `FINDING_SEVERITIES`, `constants.ts` lines 66 to 70). A runner returns findings only.
- **P9 Registry.** `PREFLIGHT_RUNNERS` is an array in `preflight.service.ts` holding `placeholdersCheck`. `checks` lists the registered runners in array order. A check not yet built is not listed, because `CHECK_STATUSES` has no "skipped" value. CEX-06 and CEX-07 append to the array.
- **P10 Runner input.** A runner is `{id: PreflightCheckId; run(input: PreflightInput): Omit<PreflightFinding, 'check'>[]}`, synchronous like the services it reads through. `PreflightInput` is `{projectId, view, files}`: the active project id (P13), the `ManuscriptView` of step 6(b), and `files`, where each file is `{path, part, content}` for each view entry, in view order, with all three parts. The framework adds `check: runner.id` to each finding. `projectId` and `view` are already computed by the service and cost nothing; they give CEX-06 what it needs without a new read: the project for its artefact and graph reads, the stale entries (`view.warnings` of kind `staleEntry`) for orphan case (b), and each entry's `part` for case (c). The input is internal to the module (tests go through HTTP only, module line 58) and no unit names it, so CEX-06 or CEX-07 may add fields to `PreflightInput` that the service fills, or turn the array into an injected list if a runner needs a service. Open point 3 (settled).
- **P11 Clock.** `PreflightService.run(now: Date)` takes the time as an argument, as `AssemblyService.assemble(now)` does (CEX-04 P12). The controller passes `new Date()`. `ranAt` is `now.toISOString()`.
