## 1. Decisions this plan follows

### 1a. Settled by the unit, the module, the contracts, DECISIONS and earlier plans

- **S1. One disposable database per project (unit line 18).** At `${SCRIBA_BOOKS_DIR}/.scriba/index/<project-id>.db`, through built-in `node:sqlite` with FTS5 and no native addon. The file name is the project id percent-encoded. `ProjectStoreService.libraryRoot` (`project-store.service.ts` line 36) is the library root. Source: unit line 18; `plans/PLT-14.md` (FTS5 measured in the image, line 193 and line 343, host Node 26.13.0); F9 below.
- **S2. Indexed roots (unit line 19).** Exactly `sources/` and `entities/`. Never `drafts/`, `snapshots/`, `graphs/`, `logs/` or any other folder.
- **S3. Passages (unit line 20).** Paragraphs, that is blocks split on blank lines. Front-matter values are indexed as their own passage. Each passage records its file and its character offset. Tokenizer `porter unicode61`.
- **S4. Freshness (unit line 21).** The `(path, mtime, size)` manifest of PST-08 is reused. It is stored in the database and diffed against disk on activation and before each query. Only changed, added and removed files are re-indexed. The key is `mtimeMs` (`plans/PST-08.md` P15).
- **S5. Format and rebuild (unit line 22).** `PRAGMA user_version` different from the module's index-format constant triggers a rebuild on open. A full rebuild is a POST. Orphan indexes (from renamed or removed project folders) are pruned at startup.
- **S6. Query (unit line 23).** The author's text becomes a safe FTS5 query: each term quoted, joined with OR, ranked by BM25. `score` is the negated BM25 (higher is better). The snippet comes from FTS5's `snippet()`. The contract names no FTS5 concept.
- **S7. Search is a POST, on the in-process provider, subject to the active-project check (unit line 24; module line 46 and line 48).** Module line 48: a request naming a non-active project fails with "project not active". `propose` and `appendLog` are the only exemptions.
- **S8. Contract (published, unchanged by this plan).** `searchRequestSchema` `{query: string min 1, limit?: int >= 1, scope?: ('sources'|'entities')[]}`, `searchPassageSchema` `{path, offset: int >= 0, snippet, score}`, `searchResultSchema` (an array), `packages/contracts/src/project-store/search.ts` lines 4 to 24. `PROJECT_SEARCH_ROUTE` (`.../projects/:projectId/search`) and `PROJECT_REBUILD_ROUTE` (`.../projects/:projectId/rebuild`), `routes.ts` lines 31 to 34. The PST-01 route table (`plans/PST-01.md` line 72) gives the search route a search request and a passage array; line 73 gives the rebuild route **no input and no output**. Source: PST-01 plan, D14; DECISIONS 2026-11-13 (PST-01 rejections 2 and 4, lines 2266 and 2296).
- **S9. Manifest and walker (PST-08).** `EntityManifest.snapshot(root)` returns `{entries, entities, invalid}`, where `entries` is every regular file under the two roots as `{path, mtimeMs, size}` (`entity-manifest.ts` lines 146 and 153; PST-08 P2, P3, P10, P11). `EntityManifest.readText(root, path)` returns the decoded text, or `undefined` when the file is gone, over `FILE_SIZE_CAP_BYTES`, or not text (`entity-manifest.ts` line 204; PST-08 P11). PST-08 P11 and the hand-off (`plans/PST-08.md` line 151) exported both for PST-13. Which entries PST-13 indexes is PST-13's choice (PST-08 P10).
- **S10. Decoding rule (PST-08 P4(b), P12).** `decodeText` (`files.service.ts` lines 93 to 102) is exported on main and uses `ignoreBOM: true`, so a leading U+FEFF stays in the decoded text. A NUL byte or invalid UTF-8 gives `undefined`.

### 1b. Choices made by this plan

- **P1. The index file name.** `encodeURIComponent(projectId) + '.db'`, inside `${libraryRoot}/.scriba/index/`. The name is built only from ids of folders that `projects.find` has found, never from the raw request. Checked (F12): `Book One` gives `Book%20One.db`, `a%b` gives `a%25b.db`, `ünï` gives `%C3%BCn%C3%AF.db`. `(`, `)`, `'`, `!`, `*` and `~` stay literal, which is legal on Linux and APFS. Folder names cannot contain `/` or NUL, and dot folders are not projects, so no id can escape the directory.
- **P2. The directory.** Created on first use with `mkdirSync(dir, {recursive: true, mode: 0o700})`, the mode of `.scriba` (`installer-first-install.test.ts` line 114). Startup never creates it (P12).
- **P3. Indexed entries.** Every entry of `EntityManifest.snapshot(root).entries`, with no further filter. The walker returns only regular files under `sources/` and `entities/`, skipping dot-entries (`entity-manifest.ts` lines 16, 222 to 233; R2), which is exactly the unit's "exactly `sources/` and `entities/`" (unit line 19). A file that `readText` cannot return as text (binary, over the cap, gone) gives zero passages. Every file goes through the same chunking (P6, P7). Source: unit line 19 read literally; PST-08 P10 and line 151 leave the choice to PST-13 (open point 1, resolved).
- **P4. The schema, created in one transaction.** `CREATE TABLE files (path TEXT PRIMARY KEY, mtime REAL NOT NULL, size INTEGER NOT NULL)`; `CREATE VIRTUAL TABLE passages USING fts5(body, path UNINDEXED, char_offset UNINDEXED, tokenize = 'porter unicode61')`; `PRAGMA user_version = SEARCH_INDEX_FORMAT`. `SEARCH_INDEX_FORMAT` is a constant of `search-index.ts`, value `1`. Checked (F13): `user_version` round-trips on a file database.
- **P5. Opening.** The file is opened per operation and closed in a `finally` (no long-lived handle). Checked (F14): a file overwritten on disk is seen at once by an open handle, so a held handle would read the replaced content. If the file is missing, it is created. If it cannot be opened or its `user_version` differs (a zero-byte file reads 0, a corrupt file throws `file is not a database`, F14), the file and its `-journal` sidecar are deleted and the index is created anew, then filled.
- **P6. Passages, body.** The text is the `readText` result (BOM kept). Front matter is skipped as in S11. The body after the closing fence is split into blocks: a block is a maximal run of lines that are not whitespace-only. A passage is the exact substring from the first non-whitespace character of the block's first line to the last non-whitespace character of its last line. Its `char_offset` is the index of that first character. Blank lines and the `\r` of CRLF files are outside every passage. Passages with no text are not stored.
- **P7. Passages, front matter.** Each front-matter line that has a non-empty value gives one passage: the value text after `key:` (or after `- ` for a list item), trimmed, with `char_offset` at its first character. Keys, comments (a line whose first non-space character is `#`), fences, lines without a value and a value that is only a block-scalar indicator (`|` or `>`, with an optional `-` or `+`) give nothing. A line with no `key:` and no `- ` (a continuation line) gives its trimmed text. Quotes around a value stay in the passage. Source: unit line 20, "front-matter values are indexed as their own passage", read as one passage per value (open point 2, resolved): it keeps keys such as `type` out of the index and keeps every passage a contiguous substring of the file, which criterion 1 requires.
- **P8. Offsets.** Character offsets are JavaScript string indexes (UTF-16 code units) of the text that `readText` returns, BOM included. They are the positions the Shell's editor uses (CodeMirror). The test reads the file with `readFileSync(path, 'utf8')`, which keeps the BOM as well.
- **P9. Freshness procedure (`refresh`).** Inside one transaction: (a) for each stored `files` row whose path is no longer in the indexed entries, delete its passages and its row; (b) for each indexed entry whose stored `(mtime, size)` differs from `(mtimeMs, size)` or that has no row, delete its passages, call `readText` (undefined gives zero passages), insert the passages of P6 and P7, and write the row with the entry's `mtimeMs` and `size`. A file that vanished between the walk and the read is stored with zero passages. A change made between the stat and the read is seen by the next query, because the stored key is the old one.
- **P10. Query procedure (`search`).** (1) `requireActive` and `find` (S12). (2) Open the index (P5). (3) Refresh (P9). (4) Build the query (P11). If there are no terms, the answer is `[]`. (5) Run `SELECT path, char_offset, snippet(passages, 0, '', '', '…', 12) AS snippet, -bm25(passages) AS score FROM passages WHERE passages MATCH ? AND <scope> ORDER BY bm25(passages), path, char_offset LIMIT ?`. The scope is `substr(path,1,8) = 'sources/'` for `sources` and `substr(path,1,9) = 'entities/'` for `entities`, joined by OR. (6) Map the rows to `{path, offset: char_offset, snippet, score}`. Checked (F15): the rows come back best first, ties are sorted by path, and the snippet keeps the newlines of a multi-line passage. The snippet markers are empty strings, so a passage of at most 12 tokens comes back as its exact text (R1); the unit fixes no markers, and plain text needs no rendering rule in PST-14 or AGL-10 (open point 3, resolved; the simplest option).
- **P11. Safe query text.** Remove every U+0000 from the text (F16: a NUL gives `unterminated string`), split on whitespace, drop empty pieces, quote each piece as `"` + piece with every `"` doubled + `"`, and join the pieces with ` OR `. An empty result means no terms (F16: an empty MATCH string is a syntax error). Checked (F16): `NEAR`, `*`, `-`, `"`, `""""`, `(`, `^start`, `col:x` and `NOT` all run without error once quoted, and a quoted `NEAR` matches the word as text.
- **P12. Startup prune.** `SearchService` implements `OnApplicationBootstrap` (the pattern of `settings.service.ts` line 82). If `${libraryRoot}/.scriba/index` does not exist, nothing happens. Otherwise the kept names are `encodeURIComponent(name) + '.db'` and `… + '.db-journal'` for every non-dot entry name of `readdirSync(libraryRoot)`, whatever its type (the dot rule of `project-discovery.ts` line 23; no `project.yaml` read, no type check: a kept name for a non-project entry is harmless, and it is the simplest list). Every other entry of the index folder is removed with `rmSync(path, {recursive: true, force: true})`. If reading the library throws, nothing is removed.
- **P13. Activation handler.** Registered in the `SearchService` constructor with `store.onProjectSwitched`. It runs the refresh of P9 for `event.to`, looked up with `projects.find`, inside a `try` whose `catch` ignores every error. It never throws (S13). A failed refresh is repaired by the next query.
- **P14. Rebuild.** `SearchService.rebuild(projectId)`: `requireActive`, `find`, delete the index file, then the refresh of P9 on a new file. Route `POST PROJECT_REBUILD_ROUTE`, no body, `@HttpCode(204)` (PST-01 gives the rebuild route no output, `plans/PST-01.md` line 73). The contract is not changed (open point 4, resolved).
- **P15. Result limit and scope.** `limit` defaults to 20 when absent, with no maximum (the contract's `min(1)` only, `search.ts` line 7). `scope` absent or an empty array means both folders. Plan's choice: the unit and the contract fix neither (open point 5, resolved; the simplest option).
- **P16. In-process provider.** `SearchService` is exported from `project-store.module.ts`, and the module's entry file re-exports it (the pattern of `EntitiesService`, `project-store.module.ts` lines 18 to 22 and 54). Signatures: `search(projectId: string, request: SearchRequest): SearchResult` and `rebuild(projectId: string): void`. Both are synchronous: `node:sqlite` and the walker are synchronous, so each call runs to completion before another request runs.
- **P17. Errors.** A non-active project gives the existing `PROJECT_NOT_ACTIVE` through `requireActive`. An unknown id gives `PROJECT_NOT_FOUND` through `find`, as `EntitiesService.projectFor` does. Other failures (for example `ENAMETOOLONG`, P19) propagate to the Platform filter as 500. No new code.
- **P18. Test seam.** The composed app through `withProjectsApp` (`project-store-projects.kit.ts` line 89) against a temp library from `bookLibrary()` (`project-store-files.kit.ts` line 44). Every test builds its own files and never reads `examples/`. Requests are sent with `postJson` (`project-store-projects.kit.ts` line 111) and the project id is put in the URL with `encodeURIComponent`.
- **P19. Over-long names.** No fallback name. A project folder whose percent-encoded name exceeds the file system's name limit makes the open fail with `ENAMETOOLONG`; search and rebuild for that project answer the existing 500 (P17), and the activation handler ignores the error (P13). Plan's choice, the simplest option (open point 6, resolved). Source: unit line 18 makes the file name the percent-encoded id, and criterion 6 (unit line 32) tests that form, so a hashed name would depart from the unit; "safe" is read as "cannot leave the index folder or collide": `encodeURIComponent` is injective and its output has no `/` (F12), and dot folders are not projects. No legal id gives an unsafe file; an over-long one gives no file.
