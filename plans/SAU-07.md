13. **Sweep verdicts, chained.** `Violation` is `{ kind, method, path }`. `sweepGetHead` sends GET and then HEAD to every enumerated path, in route order, and sends the handshake once more with its token (decision 10), each with `sendRequest` and `until: 'headers'` (decision 5). HEAD `/events` resolves at the cap and counts as sent (decision 5). The handshake token request is sent last, after the route loop. A violation's `path` is the route template (for example `{*any}`): it equals the concrete path for parameter-free routes and keeps the setup token out of the handshake entry. Its verdict is one pass:
    1. `first := snapshotLibrary(library)`; `current := first`; `previous` is none.
    2. For each request r in order:
       - (2a) `late := observer.take(0)`. Any late block is an `event-emitted` entry for `previous`; before the first request, for r itself. If `previous` already has an entry, the block adds nothing.
       - (2b) Stop rule: if `previous` is on the same path as r and has an entry, r is not sent.
       - (2c) Otherwise send r (`until: 'headers'`), then `events := observer.take(EVENT_WAIT_MS)`, then `after := snapshotLibrary(library)`.
       - (2d) r's entry, at most one: `event-emitted` if `events` is not empty; otherwise `library-changed` if `after` differs from `current`. Then `current := after`; `previous := r`.
    3. Final: after the last request, `late := observer.take(0)`, attributed to `previous` as in (2a). Then `last := snapshotLibrary(library)`. If `last` differs from `current`, add `library-changed` for `previous` when it has no entry. Then, if `first` differs from `last` and the list is still empty, add `library-changed` for `previous`. A change already attributed adds nothing; the clause on `last` against `current` still catches a write after the last request. Checked against control N1 and rehearsal M1: the probe's GET is the only change, its entry is already in the list, so the final steps add nothing and each has exactly one entry.

An empty list means every path received GET and HEAD, because the stop rule skips a path only after it has an entry. `sweepMutations` has no windows: for each route it sends the requests of decision 11 with `until: 'end'`, and records the entries of checks (a) to (f).
