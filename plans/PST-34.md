### 2b. Planner's choices (small; recorded here, not in `plans/DECISIONS.md`)

- **PC1. The reference object is stable, and the mounted target is sticky.** `reference` is a computed `{projectId, path}` (or `undefined` when either is missing); it depends on `projectId` and `selected` only. `target` is a `linkedSignal` (already used in the Shell, `tool-call-card.ts` line 267) over `{reference: reference(), phone: phone()}` whose computation returns `source.reference` when it is defined and either the class is not phone or a target is already set (`previous?.value !== undefined`); otherwise it returns `previous?.value`. So the editor is first mounted on a non-phone class, then follows each new file, and keeps the last file when `?path=` is removed. A class change creates no new reference object, so the editor does not reload. Its type is a local `interface FileTarget { projectId: string; path: string }`, structurally equal to `EditorReference` (`FileReference` is `z.string()`, `packages/contracts/src/project-store/files.ts` line 9), because the barrel does not export `EditorReference` (F12).
- **PC2. Visibility.** `editorShown = computed(() => !phone() && selected() !== undefined && fileFailure() === undefined)`. The wrapper `<div class="editor" [hidden]="!editorShown()">` holds `app-editor-layout`; the page's own `app-markdown-preview` renders only when `!editorShown() && content() !== undefined`. The wrapper is a `div`, not the layout's host, because the layout's `:host { display: block; }` (`editor-layout.ts` lines 69 to 71) would override the `hidden` attribute; the page adds the CSS rule `.editor[hidden] { display: none; }` (D14, D15).
- **PC3. Test placement.** The new tests go into `files-page.spec.ts` in one new `describe`, with ids E1 to E5. The tablet viewport is 820 by 1180 (the size `device-class.spec.ts` uses). The desktop viewport is the spec's default, 1280 by 800.
- **PC4. The editor does not scroll to a search result's offset.** PST-14's anchor and scroll stay on the page's `section`. No criterion tests scrolling (unit line 22 is the only criterion). This settles the hand-off of `plans/PST-14.md` section 6, point 5.
- **PC5. The warning is the editor's status line and alert.** No second warning element is added (open point OP-F).
- **PC6. T6, T7 and T8 run at phone width.** Their assertions stay unchanged. They describe the page's own preview refresh and its no-preview rule. On desktop T7 would count the editor's read too, and T8 would find the hidden layout's `app-markdown-preview`; the desktop form of T8's rule is tested by E4 (D15), and the desktop refresh is open point OP-B.
