## 2. Decisions the plan obeys

- **D1. Tablet and desktop open a file in the Shell's editor with direct save.** The Files page mounts the Shell's `app-editor-layout` (EditorLayout, split view with live preview) for the file in `?path=`. A save goes through the file API `write` with `baseHash`. Sources: unit line 15 (Decisions, bullet 1) and unit line 19 (Scope); `plans/SHL-15.md` D1 (split view on tablet and desktop); `plans/SHL-14.md` D1 and D5 (direct save; base hash). [decision]

### 2b. Planner's choices (small; recorded here, not in `plans/DECISIONS.md`)

- **PC1. The reference object is stable.** `reference` is a computed `{projectId, path}` (or `undefined` when either is missing). `editing` is `reference()` on a non-phone class and `undefined` on phone. A change between tablet and desktop therefore creates no new reference, so the editor does not reload.
- **PC2. The editor is mounted for the selected file on tablet and desktop, whether or not the page's own read succeeded.** This is the default of open point OP-C.
- **PC3. Test placement.** The new tests go into `files-page.spec.ts` in one new `describe`, with ids E1 to E5. The tablet viewport is 820 by 1180 (the size `device-class.spec.ts` uses). The desktop viewport is the spec's default, 1280 by 800.
- **PC4. The editor does not scroll to a search result's offset.** PST-14's anchor and scroll stay on the page's `section`. No criterion tests scrolling (unit line 22 is the only criterion). This settles the hand-off of `plans/PST-14.md` section 6, point 5.
- **PC5. The warning is the editor's status line and alert.** No second warning element is added (open point OP-F).
- **PC6. T6, T7 and T8 run at phone width.** Their assertions stay unchanged. They describe the page's own preview refresh and its no-preview rule, which on tablet and desktop now belong to the editor (open points OP-B and OP-C).
