## 7. Open points

Points 1 to 7 need a decision before the code stage. Points 8 to 13 are low, and each has the plan's recommendation.

1. **`cold_open` and the spike (blocks the order of TRG-05 and TRG-06).** TRG-06 removes the only source of `cold_open`. The dev packs root has no tool until GNP-01 and GNP-07 land, so TRG-05's running check (its lines 17 and 21) fails if TRG-06 merges first. Options: (a) TRG-05 merges first; the module doc says the spike goes first (`modules/tool-registry.md` line 7), and the phase table says "Spike; deliberately first". (b) TRG-05's dev route runs with `SCRIBA_PACKS_DIR` at `apps/api/test/fixtures/packs`, which needs an edit of the root `dev` script (`package.json` line 24), shared with PLT-11. (c) `cold_open` becomes content in `packages/packs/core`; rejected, because pack content belongs to Genre packs (GNP-07). **Recommendation: (a), and (b) if (a) is not possible.** Decide: the driver.
2. **Faults at boot and empty folders (C1, C2).** The unit says "load error" and does not say whether boot stops. **Recommendation:** built-in faults stop boot, naming the file; missing folders are empty. Decide: the Navigator.
3. **Lint and validity (C3).** `valid` is structural at TRG-06, so a user file with a lint error (for example a `slider` on a string) is offered until TRG-07 links them. **Recommendation:** TRG-07 extends `valid` through a hook in `packs.ts`, so a user file with a lint error is listed invalid with `TOOL_INVALID` and its first lint message. Decide: the Navigator, because it changes what is offered.
4. **Rows for a shadowed built-in (C5).** TRG-01 covers only an invalid copy. **Recommendation:** one row per effective tool, plus the invalid copy's row beside its built-in; a valid copy shadows the built-in. The alternative keeps the built-in row too, and then TRG-13 shows both and GRR-11 must dedupe by name. Decide: the Navigator.
5. **Test seam before TRG-09 (C12).** The list, functions and entity-validator criteria are tested in-process, not over HTTP, which departs from the module's HTTP-first principle (`modules/tool-registry.md` line 50). **Recommendation:** accept for TRG-06; TRG-09 adds the HTTP list tests. Decide: the driver.
6. **Genre pack for offering (C6).** The unit line 25 says "the project's genre pack (from `project.yaml`)". **Recommendation:** the caller passes the genre-pack name; the Project store owns `project.yaml`, and TRG-09 and the Agent loop read it there (`FilesService.read`, exported by the Project store's entry file, with `projectYamlSchema`). The alternative makes the catalog read `project.yaml`. Decide: the Navigator, since the unit's wording names the file.
7. **`catalog-changed` for a host-side add (C8).** With no watcher, the change is seen only at the next list, get or call. TRG-10 line 27 requires the event "after … a host-side file add". **Recommendation:** accept. The event follows the next read, and TRG-10's test issues a GET after the add. The unit's "no watcher" makes the alternative out of scope. Decide: the driver, before TRG-10 is planned.
8. **Manifest granularity (A1).** `(path, mtime, size)` can miss a second write of the same size within the file system's mtime resolution. **Recommendation:** keep the settled rule. AC3 sets the mtime explicitly, so it is deterministic. Record the risk; add `ctimeMs` only if a real miss is seen.
9. **Error codes (C4).** **Recommendation:** `TOOL_INVALID` for parse and structure failures, and no new code (S12). Decide: the driver.
10. **Migration hook untested (C10).** **Recommendation:** accept. Decide: the driver.
11. **Warning wording and lint counts (C4).** "A warning" in unit line 22 is taken as the summary's `error` on the copy's row. `lintCounts` is zero until TRG-07. **Recommendation:** accept. Decide: the driver.
12. **Prettier on the YAML fixtures (step 9).** The fixtures must be Prettier-clean. The alternative is a `.prettierignore` entry, which changes a root file no unit owns. **Recommendation:** Prettier-clean fixtures.
13. **Nest through `validate.ts`.** `validate.ts` imports `ModuleError` from `platform.module.ts`, so the TRG-07 CLI that reuses `packs.ts` loads Nest code. **Recommendation:** accept now; TRG-07 decides whether to move the error import (a TRG-02 file).
