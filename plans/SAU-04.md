## 1. Decisions this plan follows

Each item gives its source. FACT means the planner checked it (how is in section 7a), or the item is a recorded decision or unit text. ASSUMED means a choice made here because the sources are silent (section 7b).

1. **One guard, one pre-parser hook.** The credential and Origin checks are `SetupAuthGuard`, registered as `APP_GUARD` in `SetupAuthModule`, so it is the default for every route. The Host check and the `frame-ancestors` header are one pre-parser hook, `hostFrameMiddleware(policy)`, registered with `app.use` in `bootstrap.ts` between `NestFactory.create` and `app.init()`, and only when `SetupAuthModule` is in the composed module list (`options.modules ?? COMPOSED_MODULES`). It is not Nest middleware. Reason: the body parser is registered inside `init()` (`@nestjs/core` 12.4.2 `package/nest-application.js` line 127), so middleware added before `init()` runs before it; and a Nest guard runs only for a matched route handler, so the static bundle and an unmatched path never reach a guard. Source: the Navigator decision (DECISIONS entry, commit 6cda8cb); unit line 18 (single global guard), lines 20 and 24 (Host check and CSP apply to static and errors), line 31 (static paths get the Host check). FACT for the order (section 7a). The APP_GUARD rule for route handlers is ASSUMED (criterion 1 tests it).
2. **Order per request.** (a) The middleware sets CSP, then runs the Host check on every path except `/healthz`. (b) The guard skips the credential for public routes and, for every other route, requires a valid cookie. (c) For every mutation (any method other than GET, HEAD, OPTIONS), the guard checks Origin, public or not. Source: unit lines 19 to 22. FACT (unit). The rule for public mutations is ASSUMED (no public mutation exists in this batch).
3. **Public set.** A route skips the credential check when it carries the public marker `@Public()`. SAU-03 applies it to the handshake and identity routes (`plans/SAU-03.md` section 2, row for `public-route.decorator.ts`, and its decision 2). `/healthz` is exempt by path inside the guard, not by a decorator on Platform's `HealthController`, because `Public` is not exported from `setup-auth.module.ts`, and importing it into Platform would create a cycle (the lint rule allows the entry file, `eslint.config.mjs` lines 51 to 58). Module line 41 lists 'the global guard with its public marker' among the in-process exports; this plan reads it as: the guard is the in-process export (it is registered as `APP_GUARD`), and the marker stays in `public-route.decorator.ts`, not re-exported, because the public set is fixed (unit line 18) and no other module may add a public route. Static needs no entry, because it sits outside the guard. Source: unit line 18 (the fixed set); `packages/contracts/src/setup-auth/routes.ts` lines 8 and 9 (`HANDSHAKE_ROUTE`, `IDENTITY_ROUTE`); `packages/contracts/src/platform/http.ts` line 8 (`HEALTHZ_ROUTE`); `apps/api/src/modules/platform/health.controller.ts` line 8 ("Unguarded on purpose"). FACT for the constants. The `/healthz` path exemption is the one in `plans/SAU-03.md` revision 3 (its decision 2). It is a choice of this plan because Platform's controller stays undecorated (open point 2).
4. **Public marker file.** SAU-03 creates `setup-auth/public-route.decorator.ts` with `PUBLIC_ROUTE_KEY` (the metadata key) and `Public()`, which is `SetMetadata(PUBLIC_ROUTE_KEY, true)`. The names are those of `plans/SAU-03.md` revision 3, section 2 (line 47). SAU-04 imports both and changes nothing in the file. The guard reads the key with `Reflector.getAllAndOverride` over the handler and the class. Source: unit line 18 ("explicit public marker"); `plans/SAU-03.md` section 2 (revision 3, done, merged at 183acd4). FACT for the names as written there; the file's exact contents are checked at step 0.
5. **Host allowlist.** The `Host` header must equal, as an exact string, one of `127.0.0.1:<SCRIBA_PORT>`, `localhost:<SCRIBA_PORT>`, or the `host:port` of a `SCRIBA_DEV_ORIGINS` entry. No wildcard and no short name. A missing Host is refused. Refusal: 403 `AUTH_HOST_REJECTED`. The tailnet name is added by SAU-18. Source: unit line 20; `packages/contracts/src/platform/env.ts` line 17 (`SCRIBA_DEV_ORIGINS` default empty, "never set in the image"). FACT for the list. The exact-match and missing-Host rules are ASSUMED.
6. **Expected Origin.** Each allowed Host maps to one origin: `127.0.0.1:P` to `http://127.0.0.1:P`, `localhost:P` to `http://localhost:P`, and a dev entry to its own origin as written (its scheme is kept). A mutation's `Origin` must equal the origin for its own `Host`, as an exact string with scheme, host and port. Absent, `null`, foreign or wrong-scheme: 403 `AUTH_ORIGIN_REJECTED`. Source: unit line 22; PLT-02 unit line 50 (`SCRIBA_DEV_ORIGINS` is a list of full origins); `modules/setup-auth.md` line 69 (the reference guard's http-only origin must not be copied). FACT for the cases. The exact-string comparison (no trailing-slash tolerance) is ASSUMED.
7. **Dev origins.** `SCRIBA_DEV_ORIGINS` is a comma-separated list. Each entry must parse as an `http:` or `https:` origin with an explicit port and no path, user or query. Otherwise `buildRequestPolicy(env)` throws a `BootError` before `NestFactory.create`, with the text `Invalid SCRIBA_DEV_ORIGINS "<raw>": ...`. `bootstrap.ts` calls it before any Nest code runs, so a refusal makes `dist/main.js` exit 1 with the message on stderr and nothing on stdout, as the settings refusal does. This revision replaces the mechanism named in the revision 2 DECISIONS entry (commit d6fb211, which named `RequestPolicy.onApplicationBootstrap`): the check is `buildRequestPolicy`, called from `bootstrap.ts`. The driver records the change in DECISIONS (rejection 2, commit 6490a25). This is an addition the unit does not ask for; it is recorded in `plans/DECISIONS.md` (SAU-04 revision 2 entry) and tested by spawning `main.js` (section 4, extra). Source: unit line 25 (dev mode); PLT-02 unit line 50; `apps/api/src/modules/platform/boot/env.ts` line 129 (the variable is read as plain text there, with no check). The validation and its wording are ASSUMED.
8. **Credential.** A valid session cookie is a cookie named `scriba_setup_<SCRIBA_PORT>` (the name from `SetupCookieSigner.cookieName()`) whose value `SetupCookieSigner.verify()` accepts. The header is read with `cookieValue(header, name)`, which returns the first match or undefined, from `setup-auth/setup-session.cookie.ts`, which SAU-03 creates. SAU-04 imports it unchanged (section 2, row 6). Source: unit line 21 ("a valid session cookie (verify via SAU-02)"); `modules/setup-auth.md` line 47 (port-suffixed names); `apps/api/src/modules/setup-auth/setup-cookie.signer.ts` lines 18 to 20 (`cookieName`) and 28 to 43 (`verify`); `plans/SAU-03.md` line 46 (the helper's name). FACT for the cookie name and `verify`. The first-match rule is as `plans/SAU-03.md` revision 3 writes it (line 46).
9. **Tailscale header ignored.** The guard never reads `Tailscale-User-Login`. Source: unit line 21 and AC line 33. FACT (unit).
10. **Refusals.** Missing or invalid credential: `ModuleError` with `SETUP_AUTH_ERROR_CODES.REQUIRED` (`AUTH_REQUIRED`) and status `SETUP_AUTH_ERROR_STATUS.AUTH_REQUIRED` (401). Host refusal and Origin refusal use `HOST_REJECTED` and `ORIGIN_REJECTED`, with status 403. Platform's filter writes the base shape `{error: {code, message}}`. Source: unit lines 20 to 22; `packages/contracts/src/setup-auth/errors.ts` lines 3 to 23; `apps/api/src/modules/platform/errors/platform-exception.filter.ts` line 43 (the `ModuleError` branch); `apps/api/src/modules/platform/platform.module.ts` line 16 (`ModuleError` is exported from the entry file). FACT. The message wording is ASSUMED.
11. **The hook writes its own refusal.** `hostFrameMiddleware` is an express handler registered with `app.use`, not a Nest middleware and not a route handler. Nest's router proxy (`@nestjs/core` 12.4.2 `router/router-proxy.js` lines 10 and 22) wraps route handlers and Nest middleware, not an express handler added with `app.use` (FACT). An error thrown by the hook still reaches Platform's filter, through Nest's root error handler: `@nestjs/platform-express` 12.4.2 `adapters/express-adapter.js` line 169 (`setErrorHandler`) applies the global filters, and `PlatformExceptionFilter` is a global `APP_FILTER` (`platform.module.ts` line 34). The hook writes its own 403 `AUTH_HOST_REJECTED` in the base shape `{error: {code, message}}`, with the CSP header, because the Navigator decided that refusal shape (DECISIONS, commit 6cda8cb), not because an error would be lost. Source: the Navigator decision (commit 6cda8cb); `packages/contracts/src/setup-auth/errors.ts` lines 3 to 23 (codes and statuses). Criterion 2 checks the body.
12. **Path source.** The hook and the guard read the path from `req.originalUrl` and drop the query. Express changes `req.url` for each mounted layer, so `req.url` is not reliable inside a mounted handler. The hook is registered at the root with `app.use`, and `originalUrl` keeps the full request path. Source: express 5.3.0 with router 2.2.0, `router/index.js` lines 184 (`originalUrl` set), 195 to 202 and 323 to 327 (`req.url` changed), npm cache. FACT.
13. **Mutations.** "Mutation" means every method except GET, HEAD and OPTIONS. Source: unit line 22. FACT (unit).
14. **No CORS.** Nothing sets `Access-Control-*`. An `OPTIONS` request gets Platform's 404 `PLATFORM_NOT_FOUND`, on a matched path as on an unmatched one, because Nest's catch-all 404 handler (`@nestjs/platform-express` 12.4.2 `adapters/express-adapter.js` lines 181 to 215, `setNotFoundHandler`) answers before Express's own OPTIONS answer. Neither response carries CORS headers, so a cross-origin preflight fails. Source: unit line 23. FACT (npm cache). Criterion 5 checks the header and does not assert the OPTIONS status.
15. **Anti-framing.** `Content-Security-Policy: frame-ancestors 'none'` is set by the pre-parser hook (decision 1) on every request it sees, before the body parser and before any route handler. So it reaches static files, the SPA fallback, 401s, 403s, 404s, `/events`, `/healthz`, and the refusal of a malformed or oversize body (criteria 2 and 5). Node keeps a header set with `setHeader` when `writeHead` is later called, so the SSE response keeps it. Source: unit line 24; `modules/setup-auth.md` line 46 (settled). FACT for the order (`@nestjs/core` 12.4.2 `package/nest-application.js` line 127) and for `setHeader` (checked with `node -e`, section 7a).
16. **Platform's guarded routes.** `/events` (`events/events.controller.ts`), `/api/platform/version` (`version.controller.ts`) and `/api/platform/echo` (`events/echo.controller.ts`) need no code change: the global guard covers them. Source: unit line 26. FACT (read). Their existing tests change (decision 19).
17. **Request-identity accessor.** `RequestIdentity` is a parameter decorator in `request-identity.ts`. It returns the identity that the guard attached to the request: `{via: 'loopback'}` when the cookie verifies, the loopback shape of `identitySchema`. The decorator is re-exported from `setup-auth.module.ts`, because in-process exports go through the module entry file (`modules/setup-auth.md` line 41). Source: unit line 27; `packages/contracts/src/setup-auth/identity.ts` lines 5 to 6 (`identitySchema`, loopback). FACT for the shape. The placement and the re-export are ASSUMED. No criterion tests the accessor directly. SAU-03 does not use it (it checks the cookie itself; SAU-03 decision 17), so its first user is SAU-18 (decision 21).

Requests go through `node:http`, so the test can set `Host` and `Origin`. Reason: `createTestApp` listens on 127.0.0.1 at an ephemeral port (`apps/api/test/create-test-app.ts` line 57), so `fetch` would send a Host the allowlist refuses. An explicit Host is sent as given (checked, section 7a). Source: `modules/setup-auth.md` lines 65 to 66 (external behaviour, composed app). FACT.

ASSUMED: this is the planner's choice (open point 1).

The helper `sessionCookie(app, libraryDir)` gets the cookie the way a browser does: it reads `<libraryDir>/.scriba/setup-url` (SAU-02's file, one line), sends a GET for that URL's path and query to the app's address with `Host: 127.0.0.1:8080` through `node:http`, and keeps the first `set-cookie` value. Invalid cookies are made by editing that value (a changed timestamp, a wrong name). No test calls `SetupCookieSigner` or copies its derivation, as `modules/setup-auth.md` line 65 requires. Source: the Navigator decision in commit dc1047c (`plans/DECISIONS.md`, entry, the test-cookie paragraph); `plans/SAU-03.md` revision 3 decision 10 (the handshake issues the cookie on `127.0.0.1`, port ignored); unit line 32 (criterion 3). FACT for the decision. The helper's wording is ASSUMED.
