# TRG-15 plan — Live previews beside the tool editor, and render of an inline source

Revision 1, draft, written at main `b377601` by the planner. Revision 2, by the reviser at main `7568ec2` (only this plan changed since `b377601`). Corrections: the three code assumptions of section 1b are checked (lint, Project store, CodeMirror text replace); a stale-preview defect is fixed (the editor emits `linted` for the loaded text too, and the list resets the panel, D3a); the node preview passes no handle template, so each port has one `[data-port]` (D13); E2 also chooses the required `person`, without which render answers 422; E1 checks the state before the edit; the TRG-16 and TRG-14 test names are corrected; the TRG-17 demo-2 path after a Customize save is corrected; the e2e runs use `--trace off`; section 8 "Review parts" is added. No unit was changed. Status stays `draft` until the orchestrator sets it.

Summary: the Source tab of a tool's detail gets a live panel beside the YAML editor. The panel has four tabs: form, node, function schema and rendered prompt. It is fed by the editor's `linted` output (the views of each lint or save answer). The rendered prompt uses the render endpoint, which gains one optional field: an inline `source`, so an unsaved text renders. Nothing is saved, and no file is written.

## 2. Decisions the plan obeys

- **D1 Placement.** The live panel sits beside the editor in the Source tab, not in the outer tab strip. Source: unit line 18 ("Preview tabs beside the editor"). Acceptance criterion 1 (unit line 21) needs the node preview to change while the author types. An outer tab would unmount the editor and lose the unsaved text (`tools-list.ts` tab `@if`). `plans/TRG-14.md` section 6 says TRG-15 needs "the tab strip for its preview tabs". This plan reads that as the panel's own strip, which sits inside the Source tab. `plans/TRG-13.md` line 118 foresaw TRG-15's previews "in the tab strip of C3". The unit's later wording ("beside the editor") and criterion 1 (live while typing) decide for the panel's own strip. The outer strip is unchanged. Neither plan is changed: both are `done`, and both left the place of the previews to TRG-15 (`plans/TRG-14.md` section 6: "Not provided, and TRG-15's own work: the form, node, function schema and rendered-prompt tabs").
- **D2 The four preview tabs** are form, node, function schema and rendered prompt, as unit line 18 lists them. The panel's strip is `div role="tablist"` of `button role="tab"` with `data-live-tab="form|node|function|prompt"`. Form is first and selected by default.
- **D3 Views from the editor.** The panel's views come from the editor's `linted` output. The browser parses no YAML. Source: unit line 18; TRG-14 C16. This plan adds one field to that output: `source`, the text that was linted or saved (D7 needs it, so that the rendered prompt uses the text whose views are shown). The addition is additive.
- **D3a No stale views.** In the branch where the editor skips the lint (not a draft, text equal to the loaded text), the editor now also emits `linted` with `{lint: <the last diagnostics>, views: null, source: <the text>}`. The list treats a row's answer whose `source` equals the row's baseline source (`sourceOf(row).source`) as a reset: `live` becomes undefined, and the panel shows the baseline views. Any other answer sets `live`. A draft has no reset (it never takes the skip branch, and its baseline has no views). The list also resets `live` in `openRow`, `openDraft`, `showTab` and `customize`. Reason: section 1a (`tool-editor.ts`); without this, criterion 1's preview would show an older text's ports after an undo or a tab switch.
- **D4 A row's first views** come from its source read: `GET …/builtin` for a built-in, `GET …/user` for a user copy (`ToolSourceView.views`). The Source tab never reads `GET /tools/:name`. Source: TRG-14 C2, and the TRG-05 e2e check (a).
- **D5 A draft** has no views until its first lint. The editor lints a draft once after the start delay (TRG-14 C10). Until then the panel says there is nothing to preview.
- **D6 The TRG-05 Preview tab stays unchanged.** It reads `GET /tools/:name` and validates through `validate`. `tools-preview.spec.ts`, the TRG-05 e2e and TRG-13 C3 depend on it. Source: `plans/TRG-13.md` line 118 ("TRG-13 does not change them").
- **D7 Render accepts an optional inline `source`.** The source is the YAML text, parsed by the server. The plan reads the unit's "inline spec" as the spec in its YAML form: the browser holds only the text and the views (no spec), and may not parse YAML; the unit does not name a representation, so no unit change is needed. The render request gains `source: z.string().optional()`. The change is expand-only (`units/README.md` contract rule). Sources: unit line 18 ("if needed, render accepts an inline spec in addition to :name, an expand-only change to /tool-registry"); `plans/TRG-12.md` line 218; `plans/TRG-10.md` line 124. Text rather than a parsed spec, because the browser parses no YAML (unit line 18).
- **D8 Meaning of an inline source.** When `source` is present: the path segment `:name` is not looked up, because a draft is not saved; the author's enabled switch is ignored, because unsaved text has no switch; the source is linted with `lintToolSource(source, {entityKinds})` with no file name. A lint error answers `TOOL_INVALID` (422), with the first error's line and message. Warnings do not block. `compileSource` takes `spec` and `views` from the lint result and compiles with `compileTool(spec, createAjv())`; it does not call `checkTool`, whose name-equals-stem rule does not apply to an unsaved text. Execute ignores `source`: its schema strips unknown keys, and it is not changed.
- **D9 Rendered prompt inputs.** Sample values are the Form tab's values (the defaults prefilled by `ToolForm`, and what the author types). Entities are resolved in the browser through the Project store's resolution GET (`entityResolvePath`), with `ref = id`, as TRG-16 C6. An empty style field takes the project's style profile first (`projectFilePath`, `styleProfileOf`), as TRG-16 C4 to C8. Source: unit line 18 ("the preview form's values and entities resolved through the Project store").
- **D10 No write.** Render writes nothing, and the panel never saves. Source: `modules/tool-registry.md` ("it writes no files"; "agent/recipe writes still always become pending changes").
- **D11 Pickers.** The picker reads the kinds from the field descriptor reactively (section 1a, `entity-picker.ts`; `plans/TRG-04.md` P3). Criterion 1's second clause is therefore met by passing the new views to the Form tab. The node layout has no picker: its ports are rows with handles.
- **D12 Shared helpers.** The four pure helpers of `tools-try.ts` are exported (`isEntityField`, `isStyleField`, `idsOf`, `isEmpty`) and reused. The resolve chain is written again in the panel (about 40 lines). The chain is a component state machine with its own tests (TRG-16 Y1 to Y8), so it is not moved. This is the simplest option that changes no behaviour of TRG-16.
- **D13 Node layout.** The panel's Node tab is `app-tool-form` with `layout="node-body"`, `[ports]` and no handle template: the live panel has no drag source, and a handle would put a second `[data-port]` in each row (section 1a). The tests count `li[data-port=…]`.
- **D14 Conventions.** HTTP under `/api/tool-registry`; the render command stays a POST; errors use the `TOOL_*` codes (`units/README.md`, Conventions; `modules/tool-registry.md`, HTTP).
- **D15 Testing.** External behaviour only. API seam: `create-test-app` with `EXECUTOR_PACKS`. UI seam: Angular's Vitest runner with the Shell fakes (`createShellTestDoubles`, `respond(method, path, body)`), as in `tools-try.spec.ts`. The two acceptance criteria are checked in the running app with Playwright (section 5). Sources: `units/README.md`, Testing; `modules/tool-registry.md`, Testing principles.
- **D16 Unit history.** The unit has no change notes (section 1a), so no change of the unit needs to be applied.
- **D17 Order.** Blockers TRG-03, TRG-12 and TRG-14 are done. TRG-16, the parallel unit, is merged (section 1a). TRG-15 is built on main as it is.
