### 1d. Choices this plan makes

- **C1 Components.** `TailscalePanel` in `tailscale-panel.ts` (selector `app-tailscale-panel`) is shown in the wizard's Tailscale step and in a "Tailscale" section of the settings page, placed after "This device". `AllowlistPanel` in `allowlist-panel.ts` (selector `app-allowlist-panel`) is shown in an "Allowlist" section placed after "Tailscale". Each section is a `<section>` with an `h3` of that exact text. Reason: the unit names the same states for both places.
- **C2 Loaders.** `setup-contract.ts` gains `loadTailscaleContract()` (`TAILSCALE_STATUS_ROUTE`, `tailscaleStatusSchema`, `SETUP_AUTH_ERROR_CODES`) and `loadAllowlistContract()` (`ALLOWLIST_ROUTE`, `allowlistSchema`, `SETUP_AUTH_ERROR_CODES`). Both read the module as the existing loaders do (`mod.default ?? mod`), because the production import has only `default` (`setup-contract.ts` header; `settings-contract.spec.ts` Y1; `setup-contract.spec.ts` X5). The header comment of `setup-contract.ts` names the two new loaders. The panels import no other contract value at run time; type imports are allowed. (`allowlistUpdateSchema` is not loaded: the web builds the body `{enabled}` itself and the server validates it.)
- **C3 Polling.** `tailscale-panel.ts` exports `TAILSCALE_POLL_MS = 5000`. The panel loads the contract once, then reads the status once at once if the document is visible, and then every `TAILSCALE_POLL_MS` with one `setInterval` while the document is visible. On `visibilitychange` to `hidden` it clears the interval; on `visibilitychange` to `visible` it reads at once and starts a new interval. On destroy (`DestroyRef.onDestroy`) it clears the interval, removes the listener and marks itself destroyed; a read whose contract load or previous `await` ends after destroy sends no request. Each read's subscription handles its error (C8), so a failed read never throws out of the panel. 5 s is above the 2000 ms server cache, so each poll reads the socket. Pattern: `apps/web/src/app/shell/sse-client.ts` lines 62 and 63 (visible check), 89 (listener), 238 to 240 (teardown).
- **C4 Texts and links.** Unavailable (`available: false`): the paragraph "Tailscale is unavailable." exactly, because two e2e checks match it (`e2e/specs/journey.e2e.ts` line 78; `e2e/specs/setup-phone.e2e.ts` line 235). Logged out (`NeedsLogin`, no `authURL`): "Tailscale is logged out." Waiting for login (`NeedsLogin` with `authURL`): "Tailscale is waiting for login." and the link "Log in to Tailscale" to `authURL`. Running: "Tailscale is running." and the link "Open Scriba over the tailnet" to `tailnetURL` (only when `tailnetURL` is present). Other states (OP2): "Tailscale state: <name>." with no link. Hints (OP3): "MagicDNS is off. Turn it on in the Tailscale admin console." and "HTTPS certificates are off for this tailnet. Turn them on in the Tailscale admin console.", each a paragraph followed by the link "Tailscale admin console" to `https://login.tailscale.com/admin` (OP4). Links are `<a>` elements with `target="_blank"` and `rel="noopener"`. The unavailable state shows no link and no hint.
- **C5 No button in the panel.** On /setup the panel adds no `<button>`. W1 asserts the exact button list of the Tailscale step (`setup-page.spec.ts` lines 509 to 516), and `setup-phone.e2e.ts` line 238 finds the Skip button by role. The skip is the wizard's own Skip (OP7).
- **C6 Allowlist panel.** One `mat-slide-toggle` from Angular Material (`MatSlideToggle`, as `apps/web/src/app/features/tool-registry/tools-list.ts` lines 139 to 143 use it), with the label text "Allow only listed Tailscale logins", `[checked]` bound to the saved `enabled`. The state comes from `GET`. A change sends `POST {enabled: <new value>}` only. On 200 the panel stores the answer as the saved list and clears the lockout text. On an error it keeps the saved list and sets the switch back with `event.source.checked = saved.enabled` (`MatSlideToggleChange.source`), because the `[checked]` binding does not change and so does not reset the switch by itself. Under the toggle, the saved logins are shown read-only as a `<ul>` with one `<li>` per login, or the paragraph "No logins are listed." when the list is empty (OP8). No control adds or removes a login.
- **C7 Lockout text.** Keyed by `SETUP_ALLOWLIST_LOCKOUT` in `allowlist-panel.ts`, shown in a `<p role="alert">` inside the panel: "This change would leave this Tailscale login out of the allowlist, so it was refused. Make the change from the computer that runs Scriba." The server text is not shown (D14). The text names no list editor, because this unit has none (OP8, OP9).
- **C8 Other errors.** In both panels, a tailnet code shows `tailnetExplanation` (`sign-in-notice.ts`). Any other error shows its message in a `<p role="alert">` inside the panel. Each panel has its own small `messageOf`, because the one in `settings-page.ts` (line 269) and the one in `setup-page.ts` are file-local; no shared helper is added.
