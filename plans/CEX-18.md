### 1b. Choices of this plan

- **C1 Files.** Six new files and two edited files (section 2). Each UI part is a standalone component in its own file, as CEX-17 P15 and CEX-19 P1 did. The preflight component also holds the export buttons (C3).
- **C2 Confirm dialog.** `window.confirm`, as the snapshots panel uses for restore (`apps/web/src/app/features/compile-export/snapshots-panel.ts` line 183; `plans/CEX-19.md` section 1b, P2). The unit names the text, not the form. The text is `1 error. Export anyway?` for one error and `N errors. Export anyway?` otherwise. The criterion does not quote the text.
- **C3 One component for preflight and export.** `PreflightPanel` (selector `app-preflight-panel`) holds the last preflight result, the four export buttons and the last export result, because the confirm needs the last preflight. Labels: `Run preflight`, `Export md`, `Export docx`, `Export epub`, `Export pdf`.
- **C4 Check labels and markup.** `placeholders` is "Placeholders", `unsupported-claims` is "Unsupported claims", `orphan-scenes` is "Orphan scenes", `entity-links` is "Entity links", `banned-phrases` is "Banned phrases". Each check is listed in the response's order, with its status word and its findings, or "No findings.". Each check section carries `data-check="<id>"`, and each finding item carries `data-finding`. The finding items carry no `data-path` or `data-part`, because the page spec selects `li[data-path]` (`manuscript-page.spec.ts` line 290). No finding text contains "Graph order" (the page spec counts it at line 287).
- **C5 Held results follow the project.** The panel holds each result with the id of its project. It shows the result, and counts its errors, only while that id equals the active project's id (`ActiveProjectSignal.projectId()`). Reason: `download` serves the newest export of the active project (`export.service.ts` lines 227 and 228), and one route serves every project (A4). Test R8.
- **C6 Settings changes.** The baseline is the effective settings of the last GET or of the last write answer. A field is changed when its value differs from the baseline, where an absent key counts as the empty string. Only the changed keys are sent. A cleared text field is sent as `''`, which the server turns into a removed key (D6). The bibliography select never sends `''`. Save is disabled when nothing has changed.
- **C7 Settings revision and conflict.** The panel holds the revision of its last GET or write answer. A 409 `COMPILE_ORDER_CONFLICT` shows the server's message and a `Reload settings` button, as the page does with `Reload manuscript` (`manuscript-page.ts` line 152).
- **C8 Copy-default paths.** The suggested paths are `reference.docx` (docx), `epub.css` (epub) and `template.typst` (pdf), all in the project root. The author may change them. The tests type `custom-reference.docx`, also in the root, so that no test suggests a new folder. Copying does not set the override field. The message reads `Copied the built-in <format> template to <path>.`. An empty path disables the button, and the path is sent trimmed.
- **C9 Settings refresh.** The settings panel refetches on `files-changed` for `project.yaml` only. This is the rule of the page's `touchesManuscript` (`manuscript-page.ts` line 62), narrowed to `project.yaml`, so that a change of the drafts does not reread the settings.
- **C10 Request bodies.** Preflight `{}`; export `{format}`; settings write `{revision, settings}`; copy default `{format, path}`.
- **C11 Export result.** Shows the `fileName`, the `bytes`, the export's own preflight error count, its `warnings`, and an anchor `<a [href]="downloadUrl" download>` whose text is `Download <fileName>`.
- **C12 Failures.** The message of an `ApiError`, or "The request failed." when the error is not one, shown in a `role="alert"` inside the panel (the page's `failureMessage` pattern). No in-flight lock (CEX-17 D11 has none).
- **C13 Panels inside the view's `@if`.** The panels appear once the manuscript view has loaded, as P15 places them (`manuscript-page.ts` line 157). A failed manuscript read hides them.
- **C14 Test harness.** The new specs copy the page spec's small helpers. They render `provideRouter([{ path: 'projects/:projectId/manuscript', children: manuscriptRoutes }])` with `createShellTestDoubles()`, as `plans/CEX-19.md` P11 and P12 do.
- **C15 Request list of M4.** The list is compared sorted, as `METHOD path` strings, with three GETs: the manuscript, the snapshots and the settings. Sorting removes the dependence on creation order (A1, A2). The set of requests is still compared exactly, so the assertion is not weaker.
- **C16 Finding links (O1, settled).** The link is `/projects/<projectId>/files` with the query `path=<finding.path>`, then `line=<finding.line>` when the finding has a line, then `offset=<finding.offset>` when it has an offset. Built with `routerLink` and `queryParams`. The files page is not changed: it opens the file from `path`, and scrolls to the passage from `offset` where there is one (`files-page.ts` lines 469 to 480); it ignores `line`. Source: the unit gives the link form ("`/projects/:projectId/files?path=…` with line", line 15), and criterion 2 is about the link. The contract makes `line` optional (F21); a finding with no line links with `path` only. Making the files page scroll to a line is a Project store change that no unit asks for, so it is out of this plan (option A of O1 is not taken). CEX-20 demo step 3 (the placeholder error) gets a link that scrolls, because placeholder findings carry an offset (F8).
- **C17 "The last preflight has errors" (O2, settled).** The last result the panel holds, while it is for the active project (C5), with `summary.errors` greater than 0. No preflight is sent before an export. Source: the unit's text, "when the last preflight has errors" (line 16); export runs its own preflight and reports it in its answer (D2).
- **C18 Phone (O3, settled).** On the phone class, `Run preflight` and the four export buttons are enabled, and the download anchor is shown. The settings panel reads on every class; on the phone its fields, Save and the copy buttons are disabled, and its methods return without a request. Source: the unit allows downloads on the phone (line 16), and a download needs an export answer on that page (`downloadUrl`, D3); preflight writes nothing and export writes only under the state folder (module lines 40 and 53), not the project files. The settings writes change `project.yaml` and the project's files, so they follow the read-only phone rule of the host page (CEX-17 D14) and of the snapshots panel (`plans/CEX-19.md` P9). No criterion and no downstream unit depends on the phone rule (CEX-20 has no phone step).
