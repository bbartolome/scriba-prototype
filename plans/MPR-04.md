## 1. Decisions this plan follows

### 1a. Settled by the unit, the module, or the repo

- **SDK, target, confinement.** Built on the official `openai` SDK with explicit `baseURL` and `apiKey`, with a placeholder key for keyless providers. The client takes a resolved target `{config, key?, model}`; resolution is MPR-05. The SDK is used only in the providers module, and the client never falls back to `OPENAI_API_KEY` or `OPENAI_BASE_URL`; no other SDK environment variable changes a request (S25). Sources: unit line 18; `modules/providers.md` lines 33 and 34.
- **Request.** Messages (system, user, assistant with tool calls, tool results), optional tool function schemas passed through, optional tool choice, the target, an abort signal. It sends `temperature` and `max_tokens`. `contextSize` is metadata and is not sent. Sources: unit line 19; `packages/contracts/src/providers/config.ts` lines 6, 12 and 14.
- **Tool schema shape.** `{type: 'function', function: {name, description, parameters}}`, the Tool registry's model function schema. Source: `units/TRG-02-emission-validate.md` line 20.
- **Events.** `text-delta`; `tool-call` `{id, name, arguments}` with the raw argument string, assembled by index and never parsed or validated; `finish` with `reason` in `stop | tool-calls | length | aborted`; `usage` when reported. Sources: unit line 20; `modules/providers.md` line 40 (in-process types).
- **Collect helper.** Gathers the stream into `{text, toolCalls, finishReason, usage?}`. Source: unit line 21.
- **Errors.** The client throws PROVIDER_UNREACHABLE, PROVIDER_UNAUTHORIZED, PROVIDER_MODEL_NOT_FOUND, PROVIDER_TIMEOUT, PROVIDER_RATE_LIMITED, PROVIDER_BAD_RESPONSE, PROVIDER_ABORTED and PROVIDER_NOT_CONFIGURED (unit line 22). It throws Platform's `ModuleError` with the status from `PROVIDER_ERROR_STATUS` (`packages/contracts/src/providers/errors.ts` lines 36 to 49). The status table is the Navigator's decision: one status per code, no PROVIDER code at 401 (DECISIONS line 1765). Keys never appear in messages (unit line 22; `modules/providers.md` line 36).
- **Retries.** Owned by the client. Connection errors, timeouts before the first byte, 408, 409, 429 and 5xx are retried, up to `retries` with exponential backoff that honours Retry-After, and only before the first streamed chunk. Other 4xx and abort are never retried. Source: unit line 23. The Agent loop adds no retries of its own (`modules/agent-loop.md` line 51).
- **Timeout.** `timeout` (ms, `config.ts` line 15) bounds the wait for the first byte and every idle gap between chunks. A value of 0 means 300 000 ms (S15; coordinator decision at c49e944, DECISIONS line 1902, superseding line 1889). Source: unit line 24.
- **Abort.** Abort mid-stream ends with PROVIDER_ABORTED, and the mock sees the connection close. Source: unit line 34; PLT-12 record field `closedByClient` (`server.d.mts` line 13).
- **Mock.** Scenarios are one file each in `e2e/fixtures/mock-openai/scenarios/`. The client tests import `startMockOpenAI` with a static relative import, typed by `server.d.mts`. Sources: unit line 26; `units/PLT-12-mock-openai-server.md` line 25; `plans/PLT-12.md` lines 211 and 239.
- **SDK pin.** `openai` 7.55.0 is pinned in apps/api, the same version as `e2e/package.json` line 15, so the repository keeps one copy. Source: DECISIONS line 669.
- **Imports across modules.** The client imports `ModuleError` from the Platform entry `apps/api/src/modules/platform/platform.module.ts` (line 16), as setup-auth does (`apps/api/src/modules/setup-auth/setup-auth.guard.ts` line 14). The boundary rule allows another module only through its `*.module.ts` entry file (`eslint.config.mjs` lines 50 to 59).
- **Navigator decisions (DECISIONS lines 1867 to 1880).** Decision 1 (commits dd644ab and c8e4262; DECISIONS line 1878): the client keeps its resolved-target input. MPR-05 adds a resolve step (project id to `{config, key?, model, contextSize, source, warning}`), and its criterion 4 test resolves first, then calls `streamChat`. Decision 2 (commits 24e961c and c8e4262; DECISIONS lines 1867 to 1875 and 1879): a persistent 503 beyond `retries` is PROVIDER_BAD_RESPONSE. The widening to any status 500 to 599 is recorded at DECISIONS line 1886 (f2260eb) (S8). The retry list is unchanged, and `PROVIDER_ERROR_STATUS` is unchanged (BAD_RESPONSE is 502).
- **Module shape.** `apps/api/src/modules/providers/`. Sources: `modules/providers.md` line 33; `units/MPR-02-registry-seeding.md` line 18.
- **No HTTP route and no SSE in MPR-04.** `modules/providers.md` line 39. Testing principles: external behaviour only (module lines 42 to 46).

### 1b. Small decisions made here (the unit and module do not settle them)

- **S1 Plain functions.** `streamChat(target, request)`, `listModels(target, signal?)` and `collectStream(events)` are plain exported functions, not a Nest provider. Reason: MPR-02 owns the module wiring; MPR-05 and MPR-06 wrap them when they need injection.
- **S2 Names and wire shape.** In-process names are camelCase (`toolCalls`, `toolCallId`, `promptTokens`). The client maps them to wire names (`tool_calls`, `tool_call_id`, `prompt_tokens`). An assistant message with tool calls and no text sends `content: null`.
- **S3 Tool choice.** `'auto' | 'none' | 'required'`. A named-function choice is not offered, because no caller needs it.
- **S4 Event order.** Text deltas stream as they arrive. When the stream ends the client emits the tool calls in index order, then `usage` if a chunk reported it, then `finish`. A successful stream therefore always ends with `finish`.
- **S5 Retry boundary.** A retry is allowed only while no SSE chunk has arrived from the provider. Any chunk closes the boundary, not only a text delta, because a retry after the provider has started could repeat output.
- **S6 Attempts.** `retries` counts retries after the first attempt, so `retries: 2` allows three attempts. This matches unit line 31 ("503-then-200 succeeds within retries (mock sees two attempts)").
- **S7 Backoff.** Before retry n (n = 1, 2, …) the client waits `min(500 × 2^(n-1), 8000)` ms, with no jitter. A Retry-After header (seconds or an HTTP date), read from the SDK error's headers, raises the wait to at least its value. The wait is not counted against `timeout`, and a caller abort ends it.
- **S8 Status mapping.**
  - 401 and 403: PROVIDER_UNAUTHORIZED, not retried.
  - 404 on chat, or 400 whose error body says the model was not found: PROVIDER_MODEL_NOT_FOUND, not retried. Ollama answers an unknown model with 404. On the models list a 404 means the endpoint is missing, so it is PROVIDER_BAD_RESPONSE.
  - 429: PROVIDER_RATE_LIMITED after the retries. Retried.
  - 408: PROVIDER_TIMEOUT after the retries. Retried.
  - 409: PROVIDER_BAD_RESPONSE after the retries. Retried. The unit lists 409 as retried, and no code fits its exhaustion better.
  - Any status 500 to 599 that persists beyond the retries (for example 500, 502, 503 and 504): PROVIDER_BAD_RESPONSE, per Navigator decision 2 (DECISIONS lines 1867 and 1879; commit 24e961c). The widening from 503 to any 5xx is recorded at DECISIONS line 1886 (f2260eb); its reason is that the server answered. Retried. The test covers 503; the mapping is the same for the other 5xx codes. Open point 5 is closed.
  - Other 4xx (for example a 400 that is not about the model): PROVIDER_BAD_RESPONSE, not retried.
  - An SDK `APIConnectionError` that is not a timeout (refused, reset, no response): PROVIDER_UNREACHABLE. Retried before the first chunk.
  - Client timeout (the client's own timer, first byte or idle gap): PROVIDER_TIMEOUT. Retried before the first chunk only.
  - An SDK `APIConnectionTimeoutError` (openai `core/error.js` lines 78 and 88: it extends `APIConnectionError`), or an undici timeout code (`UND_ERR_HEADERS_TIMEOUT` or `UND_ERR_BODY_TIMEOUT`, on the error or its cause): PROVIDER_TIMEOUT, the same as the client timeout. Retried before the first chunk only. Checked before the connection case, so a timeout is never reported as UNREACHABLE.
  - Connection lost after the first chunk: PROVIDER_UNREACHABLE, not retried. The SDK rethrows a body error that is not an abort, without wrapping it (openai `core/streaming.js` line 141; an abort returns silently, lines 136 to 139), so the client reads the undici code on the error or its cause: a transport code that is not a timeout (for example `UND_ERR_SOCKET`, the cause of the `TypeError` `terminated`) is PROVIDER_UNREACHABLE (assumption A10).
- **S9 Stream shape.** When the SDK's stream iterator ends normally, with or without chunks (DECISIONS line 1915, commit 5b693d2; widened at line 1921, commit f25977a), the client first checks the caller's abort (ABORTED), then its own timer (TIMEOUT; retried only if no chunk had arrived, S5 and S8). Only if neither fired: no chunk at all is PROVIDER_BAD_RESPONSE, not retried; otherwise the finish rule below applies. The SDK returns silently on an abort (openai `core/streaming.js` lines 136 to 139 and 499 to 514), so a silent end must not become a finish (S11). A stream that ends after chunks without a finish reason gets finish `stop`. Finish reasons map as `stop` to `stop`, `tool_calls` and `function_call` to `tool-calls`, `length` to `length`, and anything else (for example `content_filter`) to `stop`.
- **S10 Tool-call fragments.** A call with no name is PROVIDER_BAD_RESPONSE. A call with no id gets `call_mock_<index>`, the same pattern the mock uses (`server.mjs` lines 355 to 357; the id is built at line 356). A fragment whose `type` is present and is not `function` is ignored. Argument fragments are concatenated and never parsed.
- **S11 Error precedence.** The first match wins, in this order: (1) the caller's abort, which gives ABORTED; (2) the client's own timer, which gives TIMEOUT; (3) an `APIConnectionTimeoutError`, or an undici timeout code (`UND_ERR_HEADERS_TIMEOUT`, `UND_ERR_BODY_TIMEOUT`) on the error or its cause, which gives TIMEOUT; (4) an `APIConnectionError`, or another undici `UND_ERR_` transport code on the error or its cause, which gives UNREACHABLE; (5) an HTTP status, which S8 maps. Check (3) before (4), because the timeout class extends `APIConnectionError`. An SDK error that matches none of these is PROVIDER_BAD_RESPONSE and is not retried; its message is not copied. A malformed chunk, or an in-stream error event, falls here (openai `core/streaming.js` lines 115 and 124 to 127). When the SDK iterator ends normally (with or without chunks; DECISIONS lines 1915 and 1921), the same first two checks, (1) and (2), run before S9 applies (S9).
- **S12 Messages.** Each code has one fixed English message. Messages carry no upstream text, no key and no `details`.
- **S13 Keyless placeholder.** The fixed value `scriba-keyless` is used only when no `key` is given. It is not `sk-` shaped, so MPR-03's redaction does not read it as a key. A given `key` is always sent, even when the config has no `keyRef` (MPR-07 relies on this for a draft config with a test-only key).
- **S14 NOT_CONFIGURED before any request (DECISIONS line 1887 for the streamChat-only rule).** Thrown when the target's resolved `model` is empty, or when `config.keyRef` is set and `key` is not given. No request is sent. The empty-model check applies to `streamChat` only: `listModels` ignores `target.model`, so an empty model still lists the provider's models. MPR-05's auto path and the model-list proxy need this (test D4b). The keyRef check applies to both calls.
- **S15 Timeout options (coordinator decision at c49e944, DECISIONS line 1902, superseding line 1889).** The client's own timer always runs. Its limit is `config.timeout` when that is greater than 0. When `config.timeout` is 0 the limit is 300 000 ms, not 600 000 ms: the premise of the earlier decision was wrong, because the SDK's timer is cleared once the headers arrive and undici caps a silent wait at 300 s. The timer covers the wait for the first byte and every idle gap between chunks, for `streamChat` and `listModels`. The SDK's `timeout` option receives the same value. A value above 300 000 ms is still enforced by the client's own timer, but undici ends a silent wait at 300 s first, so the effective cap is 300 s. Undici's default is 300 000 ms for `headersTimeout` and `bodyTimeout` (undici 8.12.4, `lib/dispatcher/client.js` lines 318 and 319; the bundled version is checked at step 5 (vii)). Both undici timeout causes and the SDK's `APIConnectionTimeoutError` map to PROVIDER_TIMEOUT (S8, S11). The SDK's own timer covers only the wait for response headers (client.js lines 1091 and 1118), and a stream skips the SDK's parse timer (client.js lines 614 to 618). For the test, `streamChat` accepts an optional `zeroTimeoutLimitMs` in its request (default 300 000; used only when `config.timeout` is 0; production code never passes it). Test D11 sets it to 300 ms so the test stays short; it replaces the 300 000 default only in the test, and it is the only injected value.
- **S16 SDK retries off.** The SDK is built with `maxRetries: 0`, so the client owns the retry policy. PLT-12's test uses the same setting (`e2e/fixtures/mock-openai/test/mock-openai.test.ts` line 85).
- **S17 Usage.** `stream_options` is not sent, and `usage` is emitted only when a chunk carries it. The mock never does (open point 8).
- **S18 listModels order.** Returns the ids in the order the provider sent them. Sorting belongs to MPR-05 (`units/MPR-05-model-resolution.md` line 20 says "returns sorted ids") and to the HTTP route (`packages/contracts/src/providers/model.ts` line 27).
- **S19 No aborted finish.** An abort is always thrown as PROVIDER_ABORTED (criterion 6), so the client never emits `finish` with reason `aborted`, although the unit's output definition names that reason (unit line 20). Open point 1.
- **S20 max_tokens.** Sent as unit line 19 says. The SDK type check in method step 5 decides whether the SDK marks it deprecated (open point 7).
- **S21 Early stop.** A signal already aborted at call time gives PROVIDER_ABORTED with no request. A consumer that stops reading early (`return()`) aborts the SDK stream, so the socket closes.
- **S22 No logging, no env.** The client writes no logs (MPR-03 owns log redaction) and reads no environment variable itself.
- **S23 Test isolation.** Each test file starts its own mock with `startMockOpenAI()`. Each test resets the scenarios it uses in `beforeEach`. Environment variables are restored in `afterEach`.
- **S24 Shipped scenarios reused.** `tool-call` and `malformed-tool-call` already match criteria 1 and 2 and are reused, not copied.
- **S25 SDK environment isolation (coordinator decision, DECISIONS line 1888).** The client passes explicit values so that no SDK environment variable changes a request. `baseURL` and `apiKey` are passed (section 1a). `adminAPIKey: null`, `organization: null`, `project: null` and `webhookSecret: null` are passed; each is a destructuring default that reads the environment only when the value is undefined (client.js line 184). `logLevel: 'off'` is passed; it is a valid level, so the `OPENAI_LOG` read (client.js line 248) is skipped. `OPENAI_CUSTOM_HEADERS` (client.js line 254) cannot be switched off through options. Its lines are merged into the default headers (client.js line 263), which the SDK sends after the auth header (client.js lines 1419 to 1421), so an environment `Authorization` line would replace the key. So the client passes its own `fetch` option: a wrapper, defined in `openai-compatible-client.ts`, that receives the SDK's final request headers, deletes every header whose name is not on the SDK's own list (step 5 (v): `Accept`, `User-Agent`, `Content-Type`, `X-Stainless-Retry-Count`, `X-Stainless-Timeout`, `X-Stainless-Lang`, `X-Stainless-Package-Version`, `X-Stainless-OS`, `X-Stainless-Arch`, `X-Stainless-Runtime`, `X-Stainless-Runtime-Version`), sets `authorization` to the client's own bearer value (the key, or the placeholder of S13), and calls the global fetch. `OpenAI-Organization` and `OpenAI-Project` are not on the list, so they are removed too. Header names compare case-insensitively. Residual: an environment header that uses a name on the list can change that header's value; no credential is affected, because `authorization` is always reset. The client's own timer uses `config.timeout`, or 300 000 ms when it is 0 (DECISIONS line 1902), and the SDK `timeout` receives the same value (S15). Undici caps a silent wait at 300 s (S15). Stop rule: step 5 (vi).
