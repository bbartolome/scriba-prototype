1. **Scope.** Register the `agent` section with Platform's hook, expose `GET` and `POST /api/agent-loop/settings`, and provide the reader that the loop uses at the start of each agent run. Source: unit lines 15 to 17. FACT.
2. **Section key and default.** `agent` is a fixed key of Platform's envelope (`packages/contracts/src/platform/settings.ts` lines 7 to 13, with `'agent'` at line 11). The default `{schemaVersion: 1, stepCap: 12, research: {enabled: false}}` is non-null, so boot writes it into a fresh library (`apps/api/src/modules/platform/settings/settings.migrate.ts` lines 82 to 88; `settings.service.ts` lines 82 to 95; unit line 15; `plans/PLT-07.md` line 166). FACT, with the fresh-library write confirmed by code reading only (A1).
3. **Contract, merged and not changed.** `agentSettingsSchema`, `AGENT_SETTINGS_DEFAULTS`, `agentSettingsUpdateSchema` and `AGENT_SETTINGS_ROUTE` are in `packages/contracts/src/agent-loop/settings.ts` (lines 5, 8 to 12, 16 to 23, 26 to 34, 36 to 37) and `routes.ts` line 11, exported through `index.ts` line 11. `plans/AGL-01.md` section 5 (line 124) confirms the slice for AGL-06. FACT.
4. **Validation rules.** `stepCap` is an integer of at least 1, and `searchEndpoint` is an http(s) URL or absent (unit line 16). The contract's schemas enforce both. The probe in section 7a (C6) ran them on the contracts' zod 4.6.7: `http://localhost:8888/search` is accepted; `ftp://x/y`, `javascript:alert(1)`, `research` without `enabled`, `stepCap` 0 and `stepCap` 1.5 are refused. The route uses `ZodValidationPipe` (`apps/api/src/modules/platform/errors/zod-validation.pipe.ts` lines 5 to 10), and the filter maps every `z.ZodError` to that code (`apps/api/src/modules/platform/errors/platform-exception.filter.ts` lines 52 to 60). The contracts' zod copy (4.6.7, `packages/contracts/node_modules/zod`) and the app's copy (4.6.6, `node_modules/zod`) differ, but zod's `instanceof` is trait-based (`node_modules/zod/v4/core/core.js` lines 112 to 117), and the probe showed that a 4.6.7 error is `instanceof` the 4.6.6 class (C7). The providers test E5 asserts this path for contract schemas (`apps/api/test/providers-api.test.ts` lines 538 to 561). FACT.
6. **Field-level merge that keeps unknown keys.** Unit line 16 says field-level merge. AGL-01 hand-off (a) says the section is a `looseObject`, so unknown keys must survive the merge (`plans/AGL-01.md` line 124). A settings write replaces the whole section key (`settings.service.ts` lines 64 to 80), so the merge belongs to AGL-06: read, merge, parse, write. The probe confirmed that the section schema keeps unknown keys at both levels and that the update schema strips unknown body keys (C6). FACT.
7. **Hook use only.** AGL-06 uses `SettingsService.register`, `read` and `write` through the platform entry (`apps/api/src/modules/platform/platform.module.ts` lines 17 to 25 and 40). It does not edit `apps/api/src/modules/platform/settings/` (`plans/PLT-07.md` line 166, the AGL-06 row of its section 5 table). FACT.
8. **Module shape and placement.** A NestJS `@Module` under `apps/api/src/modules/agent-loop/`; `GET` never mutates, and every command is a `POST` (`modules/agent-loop.md` line 49; `HTTP_METHOD_CONVENTION` in `packages/contracts/src/platform/http.ts` line 6). A factory with `inject: [SettingsService]` registers the section, as the providers and project-store modules do (`apps/api/src/modules/providers/providers.module.ts` lines 20 to 34; `apps/api/src/modules/project-store/project-store.module.ts` lines 17 to 23). FACT.

### 1b. Decisions this plan makes (the unit leaves them open)

- **D1 Files and names.** Four new files under `apps/api/src/modules/agent-loop/`: `agent-loop.module.ts` (the module and the entry file), `agent-settings.section.ts`, `agent-settings.service.ts` and `agent-settings.controller.ts`. The module file name follows `project-store.module.ts` and `providers.module.ts`, and the boundaries test names the same path as a target (`scripts/boundaries.test.mjs` lines 15 to 17). Names: `AgentLoopModule`, `AGENT_SETTINGS_SECTION_DEF`, `AgentSettingsService`, `AgentSettingsController`, and the registration token `AGENT_SETTINGS_REGISTRATION`.
- **D2 Response bodies and status codes.** `GET` and `POST` return the section object itself, typed `AgentSettings` (with `schemaVersion`), with no wrapper. This follows `setup-status.controller.ts` lines 22 to 34, which returns a single object directly. `GET` answers 200. `POST` is `@HttpCode(200)`, as in `providers.controller.ts` lines 81 to 88. No new contract type is needed.
- **D3 Absent section.** `current()` returns `AGENT_SETTINGS_DEFAULTS` when `settings.read('agent')` is undefined, and it writes nothing. The providers precedent is `providers.registry.ts` lines 104 to 115. `update()` on an absent section merges onto the defaults and writes.
- **D4 The merge.** A `stepCap` in the body replaces the stored one. `research` is merged key by key: `{...stored.research, ...body.research}`, so `{research: {searchEndpoint}}` keeps `enabled`. Unknown keys stored in the section survive, because `read` returns the stored object (`settings.service.ts` lines 58 to 62) and `write` keeps every key (`settings.migrate.ts` lines 29 to 39, `withSchemaVersion`). Unknown keys in the body are stripped rather than refused, which is what the contract's `z.object` does (C6).
- **D5 Validation at two points.** The body is checked by `agentSettingsUpdateSchema` in the pipe, so a bad body is refused with 400 before any code runs. The merged section is checked by `agentSettingsSchema.parse` before the write, so the file never receives an invalid section, even when the stored section was hand-edited (open point 1). For a valid body and a valid stored section, the second check cannot fail.
- **D6 The reader.** `AgentSettingsService.current(): AgentSettings` is the reader for AGL-03 and AGL-21. It reads the file on each call and caches nothing, so a change applies to the next run. A run takes its cap once, at its start (AGL-03's rule, `units/AGL-03-loop-core.md` line 23).
- **D7 Composition root.** `apps/api/src/app.module.ts` gets one import (in the block at lines 12 to 14) and one `COMPOSED_MODULES` entry (lines 17 to 22). Its comment at line 16 says that each feature module adds one import there. This is the only shared file the unit touches.
- **D8 Tests.** One new file, `apps/api/test/agent-settings-api.test.ts`, with two `it` blocks, one for each criterion. The service and controller get no separate unit tests, because the criteria are external behaviour.

## 6. Open points

1. **Hand-edited invalid section (Navigator).** Boot checks only the section's mapping and its `schemaVersion` (`settings.migrate.ts` lines 91 to 116), so a stored `stepCap: 0` boots. The default here follows the providers precedent and parses on read (`providers.registry.ts` lines 104 to 115). The effect is that `GET`, `POST` and AGL-03's run start return 400 `PLATFORM_VALIDATION_FAILED`, because the filter maps any ZodError to that code (`platform-exception.filter.ts` lines 52 to 60). The alternatives are a boot-time check (a change to `settings/`, which belongs to Platform) or a dedicated error code (AGL-01 D15 has four codes). Default if unanswered: parse on read.
2. **Upper bound for `stepCap` (Navigator).** The unit and the contract give only a minimum of 1 (unit line 16; `settings.ts` line 18). A large value lets a looping run go on for longer. Default: no maximum.
3. **Clearing `searchEndpoint` (Navigator; AGL-01 open point 1(e)).** A field-level merge cannot clear the endpoint (unit line 16; `plans/AGL-01.md` line 138). The plan follows the unit: a `null` is not accepted. The author removes the key from `settings.yaml`. No Navigator decision is recorded for this point (C13). Default: none.
4. **Response shape (driver).** D2 returns the bare section. If the driver prefers `{agent: ...}`, one line of the controller changes, and AGL-07 parses that shape.
5. **Unknown body keys (Navigator, minor).** They are stripped (D4), not refused. Refusing them would need a strict body schema, which is a contract change.
6. **Composition root (driver).** `apps/api/src/app.module.ts` is shared by every feature module. The change is the one line of D7; the driver confirms it.
