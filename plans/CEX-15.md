### 1c. Planner choices

- **D1 Files.** Four paths change (section 2). The unit names no test file. The obvious name `apps/api/test/compile-export-gate.test.ts` already exists (CEX-09's gate, commit `ae7df33`). So the new test file is `apps/api/test/compile-export-export-gate.test.ts`.
- **D2 Script name.** `scripts/export-smoke.sh`, next to `scripts/smoke-image.sh`, with its test `scripts/export-smoke.test.mjs`.
- **D3 One client inside the container.** The HTTP work runs in one Node program, sent on stdin to `docker exec -i <name> node -`. The runtime image has no curl (`Dockerfile` lines 52 to 64 install only ca-certificates and the Pandoc deb in the runtime stage), and `smoke-image.sh` already uses `node -e` with `fetch` (F24).
- **D4 Library.** The container gets `--tmpfs /books:rw,mode=1777`, as the `healthz` check does (`scripts/smoke-image.sh` line 78). No port is published; the client calls `http://127.0.0.1:8080` inside the container.
- **D5 Snapshot rule.** The client snapshots every file under `/books` (path, size, mtime, SHA-256) and skips only `.scriba/index`, the one derived-cache path `snapshotLibrary` skips (`apps/api/test/invariant-sweep.ts` line 190, `isDerived` at line 364).
- **D6 Checks per format.** `md`: UTF-8 without NUL bytes, non-empty. `docx` and `epub`: starts with `PK`, and the zip contains `word/document.xml` (docx) or `application/epub+zip` (epub). `pdf`: starts with `%PDF-`. Each download's `content-type` equals the format's entry in `CONTENT_TYPES` (`apps/api/src/modules/compile-export/export.service.ts` line 88), and its `content-length` equals the export result's `bytes`.
- **D7 Output.** One line per format: `PASS <format>: <fileName> <bytes> bytes`, or `FAIL <format>: <reason>`. The file name is `<slug>-<YYYYMMDD>-<HHMM>.<format>` (`export.service.ts` line 176), so the check is that it ends with `.<format>`.
- **D8 Wait for the app.** The client polls `GET /healthz` up to 60 times, one second apart (as `smoke-image.sh` does). `/healthz` is public (`setup-auth.guard.ts` line 71).
- **D9 Failure detail.** When the client exits non-zero, the wrapper prints `docker logs --tail 40` to stderr.
- **D10 Test seam.** T1 (criterion 1) runs in the apps/api Vitest suite through `withExport(files, {}, run)` (`apps/api/test/compile-export-export.kit.ts` line 88) and `itPdf` (line 68). It uses the test's own two-chapter fixture, not the sample.
- **D11 Tools for local runs.** Pandoc 3.13 and Typst 0.15.1 are copied from the local image `bbartolome/scriba:dev` as in CEX-13 step 10 and CEX-14 step 10 (F25).
- **D12 Stand-in tags.** `bbartolome/scriba:cex15-arm64` and `bbartolome/scriba:cex15-amd64`, built from HEAD with a clean tree. The existing `local-*`, `plt14`, `plt16-check` and `dev` tags are not touched.
- **D13 No product change.** The unit's scope is a smoke step and its tests. If a format fails inside the image, the implementer stops and reports it; no file under `apps/api/src` changes in this unit.
- **D14 Step shape.** The new step has no `if` and no `continue-on-error`. It sits in the `smoke` job, so the amd64 and arm64 matrix legs run it. `merge` already needs `smoke` (`publish.yml` line 152), so a failing export blocks every tag.
