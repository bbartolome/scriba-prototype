5. **The Shell front-matter rule: the Navigator's option A (decided).** Text (after an optional BOM) is front matter when all of these hold:
   - its first line, without its terminator, is `---` with optional trailing spaces or tabs;
   - the next line is not empty and not only spaces or tabs;
   - a later line, without its terminator, is `---` or `...` with optional trailing spaces or tabs; the first such line closes the block;
   - the first non-blank line between the fences is a YAML comment (`#`) or looks like a mapping key (`key:` followed by a space, a tab or the end of the line; regex `/^(?:#|[^\s#:][^:]*:(?:[ \t]|$))/`). This is the YAML-shape guard, in place of a YAML parser. With no such line (an empty block) the block is hidden.

   Anything else hides nothing. The Navigator decided this rule and its reason (`plans/DECISIONS.md` lines 3462 to 3465): exact alignment with the repo's `readFrontMatter` (options B and C) would change five criterion-1 tests: three from shown to hidden (the two blank-line tests and the prose test), and two from hidden to shown (the BOM row and the `...` row; `plans/DECISIONS.md` line 3389). It also needs a YAML parse, so a YAML library in `apps/web`; the Shell's rule is that it ships no runtime parser or schema library (lines 1084 to 1089, no runtime zod). The third option of the review of revision 5 (a `yaml` parse that hides only a mapping; `yaml` 2.9.1 is a root devDependency, `package.json` line 40) needs the same library in the Shell. The Navigator's entry does not name it, so this plan rejects it for the same reason and asks the Navigator to confirm (line 3389; open point 2).

   The repo's own rule, `readFrontMatter` in `scripts/examples-check/lib.mjs` lines 70 to 85 (PLT-20), needs an exact `---` first line, closes on the first `---`, has no blank-line test and no `...`, takes no BOM, and parses YAML. The two agree on an ordinary block (`---`, `key: value` lines, `---`). This rule differs on purpose: it accepts a BOM, trailing blanks and a `...` closer (what Pandoc accepts); it shows a block that opens with a blank line (a scene break) and a block whose first line is prose, because a pane that hides prose loses the author's text. The compile engine is Pandoc (`units/CEX-04-assembled-markdown.md` lines 18 and 25). The Navigator's correction (line 3467) says the Pandoc stripping need not match this rule in the prose-first case. Known limit: prose whose first line has the form `Word: text` is a mapping to Pandoc too, and is hidden. The Shell cannot import the API's parser (`modules/shell.md` line 43).
