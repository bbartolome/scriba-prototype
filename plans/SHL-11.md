3. **Hides a leading YAML front-matter block, for display only.** The component removes the block from the string it hands to the renderer. It has no output, no write path and no setter on its input, so nothing is written back. Source: unit line 19. [FACT F2]

4. **Input is a Markdown string; no file I/O.** The component injects nothing from the Shell (no API client, no SSE client) and does not use `ngx-markdown`'s `src` input, which would fetch over HTTP. Source: unit line 20; `modules/shell.md` line 43 ("shared components take Shell-local inputs"). [FACT F2, F5, F8]

5. **The Shell front-matter rule: Pandoc's block shape, with a YAML-shape guard in place of a YAML parser.** Text (after an optional BOM) is front matter when it starts with a line that is only `---` (trailing spaces or tabs allowed), the next line is not blank, a later line is only `---` or `...` (the first such line closes), and the first non-blank line between them is a YAML comment (`#`) or looks like a mapping key (`key:` followed by a space, a tab or the end of the line; regex `/^(?:#|[^\s#:][^:]*:(?:[ \t]|$))/`). Anything else hides nothing. The repo already has a front-matter reader, `readFrontMatter` in `scripts/examples-check/lib.mjs` lines 70 to 85 (PLT-20): an exact `---` first line, the first `---` line closes, no blank-line test, no BOM, no `...`, and a YAML parse that reports errors. The two agree on every ordinary block (`---`, `key: value` lines, `---`). This rule differs on purpose in these ways: it accepts a BOM, trailing blanks and a `...` closer (a reading pane should tolerate what Pandoc accepts); it shows a block that opens with a blank line (a scene break); and it shows a block whose first line is prose. The last two are because a pane that hides prose loses the author's text, where showing a few YAML lines is only untidy, and because the Shell cannot parse YAML (`apps/web` has no YAML library and no dependency is planned). The compile engine is Pandoc (`units/CEX-04-assembled-markdown.md` line 18, "One Pandoc Markdown document", and line 25, each file's YAML front matter is stripped; `units/CEX-02-effective-order-view-model.md` line 28 strips it for word counts), so the pane and the export agree on ordinary metadata. The Shell cannot import the API's parser (`modules/shell.md` line 43), so it keeps its own copy. Known limit: prose whose first line has the form `Word: text` is a mapping to Pandoc too, and is hidden. [DECISION] [FACT F6, F10, F19] [ASSUMED A4] Open decision 2 (open point 2).

3. **Green: the stripper (file: `markdown-preview.ts`).** Replace `body` with `computed(() => stripFrontMatter(this.content()))` and write the function. Algorithm, in order:
   1. Drop one leading BOM (the character U+FEFF; in code, `'\u{FEFF}'`), if present. The result is `source`.
   2. Split `source` into lines that keep their terminators (`\r\n`, `\n` or `\r`): `source.match(/[^\r\n]*(?:\r\n|\n|\r)|[^\r\n]+$/g) ?? []` (F10).
   3. If there are fewer than two lines, return `source`. In code, destructure `const [opening, second] = lines` and return `source` when either is `undefined`: `lines[0]` is typed `string | undefined` here (F19).
   4. If line 1 without its terminator does not match `/^---[ \t]*$/`, return `source`.
   5. If line 2 without its terminator is empty or only spaces and tabs, return `source`.
   6. For each line from the second on, if it without its terminator matches `/^(?:---|\.\.\.)[ \t]*$/` (the closing line): (a) take the first line between the opening line and this one that is not empty or only spaces and tabs; if there is one and it does not match `/^(?:#|[^\s#:][^:]*:(?:[ \t]|$))/`, return `source` (the YAML-shape guard of decision 5; with no such line the block is empty and is hidden); (b) otherwise return the lines after the closing line, joined with `''`, with the leading blank lines removed (`.replace(/^(?:[ \t]*(?:\r\n|\n|\r))+/, '')`).
