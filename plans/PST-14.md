### 1b. Choices made by this plan

- **P1. The result link.** Each result is a link `[routerLink]="[]"` with `[queryParams]="{ path, offset }"`, so the URL becomes `/projects/<id>/files?path=<path>&offset=<n>`. A tree link keeps `{ path }` only, so a tree click drops `offset`. The `offset` value is the number the search answered.
- **P2. Scroll, approximate (unit line 18).** The preview section gets an absolutely positioned zero-size anchor, placed at `top = offset / content.length` as a percentage of the section. After the content of the requested path is shown, the page calls `scrollIntoView({ block: 'center' })` on the anchor, once per `(path, offset)` request, in an `afterRenderEffect` (exported from `@angular/core`; F17). Reason: the preview renders Markdown with the front matter hidden (`shell/markdown-preview.ts` `stripFrontMatter`, PST-10 F10), so no offset maps to a rendered element. "Near" is what the unit asks. Open point 2.
- **P3. When a search runs.** Typed text is searched 250 ms after the last keystroke (`debounceTime(250)`). A scope change searches at once when the text is not blank. Blank text (empty or only spaces) sends nothing and clears the results. The request carries no `limit`, so the server default of 20 applies.
- **P4. Scope toggle.** A `mat-button-toggle-group` with `multiple` and `aria-label="Search scope"`, with two toggles, `Sources` and `Entities`, both on at the start (F16). The body carries `scope` only when exactly one toggle is on (`['sources']` or `['entities']`). With both on, the body has no `scope` key, which the server reads as both folders (S7). With neither on, no request is sent, and the panel shows `<p role="status">Choose at least one folder to search.</p>`.
- **P5. Results view.** An `<ol aria-label="Search results">`, one `<li>` per passage, with one link per passage holding the path and the snippet as text (Angular's text binding escapes it). The order is the order received, which is the server's ranking; the score is not shown. No passages give `<p role="status">No matches.</p>`. A failure gives `<p role="alert">` with the `ApiError` message or `The request failed.`. The results use an `ol`, not a `ul`, so the tree's selector (`ul[aria-label="Project files"] li`, `files-page.spec.ts` line 97) does not match them.
- **P6. The input.** `<input type="search">` with a `<label>` whose text is `Search the project`. Its role is `searchbox`.
- **P7. Project change.** When the active project id changes, the panel clears its text, results and failure, as `FilesPage` does (`files-page.ts` line 280 onward).
- **P8. No re-run on events.** The results are not searched again on `files-changed` or on a reconcile tick. The next query reads the index again (PST-13 P9). Open point 3.
- **P9. Layout.** The panel sits between the `Files` heading and the layout (`files-page.ts` lines 151 and 155). Its results list has `max-height: 50vh` and `overflow: auto`, so the tree stays reachable at 390 by 844.
- **P10. Copies in a new file.** The contract copies go in a new file, `search-contract.ts`, and not in `files-contract.ts`, so that the copies of PST-21 and PST-34 cannot collide with this one.
- **P11. Seams.** T1 and T2 are DOM tests under Angular's Vitest runner (module default, S8). T3 is a Playwright spec at 390 by 844 (S11). The DOM tests check what renders and what is sent; they make no layout claim.
- **P12. Test timing.** T1 and T2 wait 300 ms of real time after typing (the debounce is 250 ms), then settle the fixture. No fake timers.
