### 1b. Small decisions this plan makes (the unit leaves them open)

- **P1. The function takes a project root, not a project id.** `resolveProjectPath(projectRoot, path, options?)`. `projectRoot` is an absolute folder that the caller found by discovery (PST-03) or took from the active-project check (PST-04). Reason: S12, and discovery and the active check do not exist yet. The function realpaths the root itself (so a root reached through a symlink is fine). A root that does not exist, or is not a folder, gives `PROJECT_NOT_FOUND` (404, message with no path).
- **P2. Synchronous.** The function uses `lstatSync` and `realpathSync.native`, as `SettingsService` and the other app-state code use sync fs. It does a few syscalls per call. Open point 8.
- **P3. The result.** `ResolvedProjectPath = { relativePath, realPath, isRoot, exists }`. `relativePath` is the canonical project-relative POSIX form (the input with `.` segments removed; `''` for the root). `realPath` is the absolute real location (the real path of the target, or of its nearest existing ancestor plus the missing segments). It is for the caller's fs calls only and must never go into a message, a log or a response (a comment on the type says so). `isRoot` is true when `relativePath` is `''`. `exists` is true when the whole target exists. CEX-14 needs `exists` (unit CEX-14 line 16).
- **P4. `.` segments are removed, `.` alone is the project root.** The unit says "canonicalise" and does not list `.` as invalid, so `a/./b` becomes `a/b` and `.` is the root (`isRoot: true`), which PST-06's list of the project root needs. The empty string is still invalid (it is one empty segment). A trailing slash is an empty segment, so `drafts/` is invalid. A segment such as `a..b` or `..a` is not a `..` segment and is allowed.
- **P5. Reserved is checked twice.** (a) On the canonical relative path before touching the disk, so a reserved path need not exist and the disk is not probed. (b) On the relative path of the resolved real location, so a symlink inside the project that points into `.scriba/` or `drafts/.versions/` is also reserved. Without (b), a within-project link would reach the reserved folders. A path that is both reserved and outside reports reserved (the first check wins).
- **P6. The reserved comparison ignores letter case.** `.SCRIBA/x` and `Drafts/.Versions/x` are reserved. Reason: on a case-insensitive bind mount (S7) these reach the reserved folders. Cost: on a case-sensitive disk a folder spelled `Drafts/.versions` is also refused; harmless. This extends S7 from the prefix check to the reserved check. Open point 2. Comparison uses `toLowerCase()`, which is locale independent.
- **P7. Matching is by whole segment.** `.scriba` and `.scriba/x` are reserved; `.scribe/x`, `.scribax/x`, `drafts/.versions-old/x` and `sub/.scriba/x` (not at the project root) are not. The folder itself (`.scriba`, `drafts/.versions`) is reserved.
- **P8. A dangling or looping symlink in the path gives `PROJECT_PATH_OUTSIDE`.** When a path component is a symlink and `realpath` of it fails with `ENOENT`, `ELOOP`, `ENOTDIR` or `ENAMETOOLONG`, the check cannot show that the target is inside, so it refuses. A naive "walk up to the nearest ancestor that `realpath` accepts" would treat a dangling link as a missing file and let a write create a file outside; the component-by-component walk (section 1c) closes that. A dangling link whose target is inside the project is also refused (conservative). The message says "outside the project or through a link that cannot be resolved".
- **P9. A file as an ancestor is allowed.** `drafts/ch01.md/child.md`, where `ch01.md` is a file, resolves with `exists: false`. Path safety is about containment; the file operation reports its own error (`ENOTDIR`), which PST-06 must map (section 5).
- **P10. Other fs errors.** `ENAMETOOLONG` on a path component gives `PROJECT_PATH_INVALID`. Any other unexpected errno (for example `EACCES`, `EIO`) is rethrown as a plain `Error('The project path could not be checked (<errno>).')` with no path and no `cause`, so the Platform filter answers 500 `PLATFORM_INTERNAL` and its log line (which prints `error.message` and the stack, `platform-exception.filter.ts` lines 111 to 113) holds no library path (S8) (F11).
- **P11. Fixed messages, no echo, no `details`.** Every error message is a fixed string. The input path is never echoed, because an absolute input such as `/books/demo/x` would put a container path into the response. The messages are listed in section 1c. A caller already holds its own input.
- **P12. The exported provider is `ProjectStoreService`**, in `project-store.service.ts` (the file name `scripts/boundaries.test.mjs` already uses, F5). It has `libraryRoot` (a getter returning `SCRIBA_ENV.SCRIBA_BOOKS_DIR`, not realpathed) and `resolvePath(projectRoot, path)`, which calls the one function in public mode (reserved refused). Later units add methods (open point 4). The module's own later code (pending store, versions) calls `resolveProjectPath(..., { allowReserved: true })` from `path-safety.ts` directly; `allowReserved` is not on the exported provider, so no other module can reach reserved paths by DI. Both entry points run the one function (unit line 20). Open point 6 asks whether to keep `allowReserved` in PST-02.
- **P13. Containment is a string-prefix test on real paths, with a separator boundary.** `inside(rootReal, p)` is `p === rootReal || p.startsWith(rootReal + sep)` (not `startsWith(rootReal)`, which would accept `/books/book-2` for `/books/book`). No inode check (open point 1).
- **P14. Test layout.** One kit file holds the fixture builder, the case table and the test-only module, so that PST-12 can import the table and run it over the real file routes (PST-12 line 25). The table is exported as data (`PATH_SAFETY_CASES`).
- **P15. No new dependency.** `node:fs`, `node:path`, `@nestjs/common` and the contracts are enough. `package.json` and the lockfile do not change.

### 1c. The algorithm and the messages (the implementer follows this)

`resolveProjectPath(projectRoot: string, path: string, options: { allowReserved?: boolean } = {}): ResolvedProjectPath`

1. **Syntax.** Throw `PROJECT_PATH_INVALID` (400) when: `path` is not a string or is `''` (message A); it contains `\0` (B); it contains `\` (C); it starts with `/` (D); any `/`-separated segment is `..` (E) or is empty (F). Drop `.` segments. `segments` is what is left; `relativePath = segments.join('/')`.
2. **Reserved, lexical** (skipped when `allowReserved`). If `isReservedPath(relativePath)` throw `PROJECT_PATH_RESERVED` (400). `isReservedPath(rel)` lower-cases `rel` and tests each of `RESERVED_PATH_PREFIXES` (trailing slash removed) as `rel === prefix || rel.startsWith(prefix + '/')`.
3. **Root.** `rootReal = realpathSync.native(projectRoot)`; `ENOENT` or `ENOTDIR`, or a result that is not a directory (`statSync`), throws `PROJECT_NOT_FOUND` (404).
4. **Walk.** `current = rootReal`. For each segment `s`, `next = join(current, s)`. `lstatSync(next)`: `ENOENT` or `ENOTDIR` means the rest does not exist, stop (`remaining` is this segment and the following ones); `ENAMETOOLONG` throws `PROJECT_PATH_INVALID` (G); `ELOOP` throws `PROJECT_PATH_OUTSIDE`; any other error is the generic error of P10. If it is a symlink, `real = realpathSync.native(next)`; `ENOENT`, `ELOOP`, `ENOTDIR` or `ENAMETOOLONG` throws `PROJECT_PATH_OUTSIDE` (H); other errors are the generic error; if `!inside(rootReal, real)` throw `PROJECT_PATH_OUTSIDE` (H); `current = real`. Otherwise `current = next`. Because `current` is always a real path, no later `lstat` crosses a hidden symlink.
5. **Result path.** `realPath = join(current, ...remaining)`; `exists = remaining.length === 0`.
6. **Reserved, real** (skipped when `allowReserved`). `real = relative(rootReal, realPath)` with `sep` turned into `/`; if `isReservedPath(real)` throw `PROJECT_PATH_RESERVED`.
7. Return `{ relativePath, realPath, isRoot: relativePath === '', exists }`.

Messages (the contract has no message text; these are this plan's):

- A: `The path must be a non-empty project-relative string.`
- B: `The path must not contain a NUL byte.`
- C: `The path must use forward slashes, not backslashes.`
- D: `The path must be relative to the project, not absolute.`
- E: `The path must not contain a ".." segment.`
- F: `The path must not contain an empty segment.`
- G: `A name in the path is too long.`
- H (outside): `The path leads outside the project, or through a link that cannot be resolved.`
- reserved: `The path is reserved for the app and is not available through the file API.`
- not found (root): `The project folder was not found.`

Every `ModuleError` is built by one helper `fail(code, message)` that sets the status from `PROJECT_ERROR_STATUS[code]` and takes a string literal.

```ts
// project-store.service.ts
@Injectable()
export class ProjectStoreService {
  constructor(@Inject(SCRIBA_ENV) private readonly env: ScribaEnv) {}
  get libraryRoot(): string { return this.env.SCRIBA_BOOKS_DIR; }
  // The in-process path check. Reserved paths are refused.
  resolvePath(projectRoot: string, path: string): ResolvedProjectPath {
    return resolveProjectPath(projectRoot, path);
  }
}

export { ProjectStoreService } from './project-store.service';
```

## 6. Open points

1. **Case-insensitive mounts and the containment test.** The check is a string-prefix test on real paths (P13). On a case-insensitive mount, a symlink inside the project that is spelled with different letter case, such as `ln -s ../Book/x`, makes `realpath` return `.../Book/x`, which does not start with `.../book`, so the path is refused. That fails safe (a refusal, never an escape). A fallback comparing `dev` and `ino` up the ancestor chain would accept it, but it cannot be tested on this Linux disk (F25), and a filesystem with unstable inode numbers could make a false accept. Recommended: no fallback. The unit text itself says "compares real paths" (unit line 24). Decided by: the Navigator if it wants the inode check.
2. **Reserved comparison ignores case (P6).** Extends S7 from the prefix check to the reserved check. Cost: `Drafts/.versions/` is refused on a case-sensitive disk too. Recommended: keep. The Navigator confirms.
3. **No id-to-root helper (P1, S12).** PST-02 does not map a project id to a folder. Recommended: keep it out, as the DECISIONS hand-off says. If PST-03 wants one, it belongs in PST-03 and must look the id up in the discovered list.
4. **Growth of `ProjectStoreService` and `project-store.module.ts`.** PST-04 and PST-05 run in parallel, then PST-06 and PST-08, and each adds provider methods, providers and controllers to the same two files. Recommended: each later unit adds its own `@Injectable()` file and one line in the module's `providers` or `controllers`, and adds one delegating method to `ProjectStoreService` only for what other modules call. The orchestrator orders the merges and reconciles the text.
5. **`.` as the project root (P4).** Needed for `list`; AGL-02's optional `path` must be mapped to `.` by PST-06. The empty string stays invalid because the criterion says "empty segment". Confirm in PST-06's plan.
6. **The `allowReserved` option (P12).** Not required by a criterion. It follows from "only the module's own pending-change and version operations touch" the reserved paths (unit line 23). PST-15 could instead use plain fs under `stateDir` and PST-16 could use plain fs for versions, in which case the option is unused. Recommended: keep it, because it is one parameter and E1 tests it. Alternative: drop it and E1, and let PST-15 add it.
7. **Dangling symlinks inside the project (P8).** A dangling link whose target is inside the project is refused as outside. A more exact rule would resolve the link text lexically and check it. Recommended: keep the conservative rule.
8. **Sync API (P2).** If PST-06 prefers async, wrapping is trivial; the reverse is not. Recommended: keep sync.
9. **Hard links, mount points and races.** The check cannot see a hard link to an outside file or a bind mount inside a project, and there is a gap between the check and the use. See 7b A4 and A5. Accepted for a single-user local app; the module's callers use `realPath` immediately.
10. **Untested branch.** The "unexpected errno" branch of P10 is not covered by a test (the tests run as a user that can read every folder in the temp library, and the container user is typically root, so `EACCES` cannot be induced reliably). It is two lines. Recommended: accept, and review by reading (step 8).
11. **Name choices.** `ProjectStoreService`, `resolvePath`, `libraryRoot`, `resolveProjectPath`, `isReservedPath`, `allowReserved`, the result field names, the test-only route `/api/project-store-test/resolve`, and the messages are this plan's. No unit names any of them (F26). The later plans adopt them or the orchestrator reconciles.
