### 1b. Small decisions this plan makes (the unit leaves them open)

- **P1. The function takes a project root, not a project id.** `resolveProjectPath(projectRoot, path)`. `projectRoot` is an absolute folder that the caller found by discovery (PST-03) or took from the active-project check (PST-04). Reason: S12; and discovery and the active check do not exist yet. The function realpaths the root itself, so a root reached through a symlink works. A root that does not exist, or is not a folder, gives `PROJECT_NOT_FOUND` (404, a message with no path).
- **P2. Synchronous.** The function uses `lstatSync` and `realpathSync.native`, as `SettingsService` and the other app-state code use sync fs. It makes a few syscalls per call. Open point 8.
- **P3. The result.** `ResolvedProjectPath = { relativePath, realPath, isRoot, exists }`. `relativePath` is the canonical project-relative POSIX form: the input with `.` segments removed, `''` for the root. It is lexical; a link in the path is not replaced by its target. `realPath` is the absolute real location: the real path of the target, or of its nearest existing ancestor plus the missing segments. It is for the caller's fs calls only and must never go into a message, a log or a response (a comment on the type says so). `isRoot` is true when `relativePath` is `''`. `exists` is true when the whole target exists. CEX-14 needs `exists` (unit CEX-14 line 16).
- **P4. `.` segments are removed, and `.` alone is the project root.** The unit says "canonicalise" and does not list `.` as invalid, so `a/./b` becomes `a/b`, and `.` is the root (`isRoot: true`), which PST-06's list of the project root needs. The empty string is still invalid: it is one empty segment. A trailing slash is an empty segment, so `drafts/` is invalid. A segment such as `a..b` or `..a` is not a `..` segment and is allowed.
- **P5. Reserved is checked twice.** (a) On the canonical relative path, before the disk is touched, so a reserved path need not exist and the disk is not probed. (b) On the relative path of the resolved real location, so that a symlink inside the project that points into `.scriba/` or `drafts/.versions/` is also reserved. Without (b), a within-project link would reach the reserved folders. A path that is both reserved and outside reports reserved (the first check wins).
- **P6. The reserved comparison ignores letter case.** `.SCRIBA/x` and `Drafts/.Versions/x` are reserved. Reason: on a case-insensitive bind mount (S7) they reach the reserved folders. Cost: on a case-sensitive disk, a folder spelled `Drafts/.versions` is also refused; harmless. This extends S7 from the prefix check to the reserved check. Open point 2. The comparison uses `toLowerCase()`, which does not depend on the locale.
- **P7. Matching is by whole segment.** `.scriba` and `.scriba/x` are reserved; `.scribe/x`, `.scribax/x`, `drafts/.versions-old/x` and `sub/.scriba/x` (not at the project root) are not. The folder itself (`.scriba`, `drafts/.versions`) is reserved. Other dot-folders, such as `.notes/`, are not reserved.
- **P8. Every symlink in the path must resolve inside the project.** The walk of section 1c checks each component. When a component is a symlink, its real path must be inside the real project root, else `PROJECT_PATH_OUTSIDE`. This holds even when the rest of the path comes back into the project (`link-up/book/drafts/ch01.md`, where `link-up` points at the library): the unit rejects "a symlink inside the project pointing outside" (unit line 22). When `realpath` of a symlink fails with `ENOENT`, `ELOOP`, `ENOTDIR` or `ENAMETOOLONG` (a dangling or looping link), the check cannot show that the target is inside, so it refuses with `PROJECT_PATH_OUTSIDE`. A naive "walk up to the nearest ancestor that `realpath` accepts" would treat a dangling link as a missing file and let a write create a file outside; the component walk closes that. A dangling link whose target would be inside is also refused (conservative; open point 7). The message says "outside the project, or through a link that cannot be resolved".
- **P9. A file as an ancestor is allowed.** `drafts/ch01.md/child.md`, where `ch01.md` is a file, resolves with `exists: false`. Path safety is about containment; the file operation reports its own error (`ENOTDIR`), which PST-06 must map (section 5).
- **P10. Other fs errors.** `ENAMETOOLONG` from `lstat` of a path component gives `PROJECT_PATH_INVALID`. Any other unexpected errno (for example `EACCES` or `EIO`) is rethrown as a plain `Error('The project path could not be checked (<errno code>).')` with no path and no `cause`. The Platform filter then answers 500 `PLATFORM_INTERNAL`, and its log line, which prints `error.message` and the stack (`platform-exception.filter.ts` lines 111 to 114), holds no library path (S8) (F11).
- **P11. Fixed messages, no echo, no `details`.** Every error message is a fixed string from one constant map, `PATH_MESSAGES` (`as const`), and the helper `fail(code, message)` accepts only a value of that map, so the type checker refuses any other string. The input path is never echoed, because an absolute input such as `/books/demo/x` would put a container path into the response. The messages are listed in section 1c. A caller already holds its own input.
- **P12. The exported provider is `ProjectStoreService`**, in `project-store.service.ts` (the file and class names of F5). It has `libraryRoot` (a getter that returns `SCRIBA_ENV.SCRIBA_BOOKS_DIR`, not realpathed) and `resolvePath(projectRoot, path)`, which calls the one function; reserved paths are refused. Later units add methods (open point 4). There is no internal mode in PST-02: no `allowReserved` option. Reason (R1.1): a mode that only module-internal code can call could be tested only through a private helper, which the module's testing principles forbid (`modules/project-store.md` line 55). The units that read and write `drafts/.versions/` (PST-16, PST-18) add such a mode to `path-safety.ts` themselves and test it through their own routes (open point 6).
- **P13. Containment is a string-prefix test on real paths, with a separator boundary.** `inside(rootReal, p)` is `p === rootReal || p.startsWith(rootReal + sep)`. Plain `startsWith(rootReal)` would accept `/books/book-2` for `/books/book`. No inode check (open point 1).
- **P14. Test layout.** One kit file, `apps/api/test/project-store-path-safety.kit.ts`, holds the fixture builder `buildPathSafetyLibrary()`, the case function `pathSafetyCases(fixture)`, the test-only module `PathSafetyKitModule` and the request helper `postResolve(app, body)`. ### 1c. The algorithm and the messages (the implementer follows this)

`resolveProjectPath(projectRoot: string, path: string): ResolvedProjectPath`

1. **Syntax.** Throw `PROJECT_PATH_INVALID` (400) when: `path` is not a string or is `''` (message A); it contains `\0` (B); it contains `\` (C); it starts with `/` (D); any `/`-separated segment is `..` (E) or is empty (F). Drop the `.` segments. `segments` is what is left; `relativePath = segments.join('/')`.
2. **Reserved, lexical.** If `isReservedPath(relativePath)`, throw `PROJECT_PATH_RESERVED` (400). `isReservedPath(rel)` lower-cases `rel` and tests each entry of `RESERVED_PATH_PREFIXES`, with its trailing slash removed, as `rel === prefix || rel.startsWith(prefix + '/')`.
3. **Root.** `rootReal = realpathSync.native(projectRoot)`. `ENOENT` or `ENOTDIR`, or a result that is not a directory (`statSync(rootReal).isDirectory()` is false), throws `PROJECT_NOT_FOUND` (404). Other errors are the generic error of P10.
4. **Walk.** `current = rootReal`. For each segment `s`, `next = join(current, s)`, then `lstatSync(next)`:
   - `ENOENT` or `ENOTDIR`: the rest does not exist; stop. `remaining` is this segment and the ones after it.
   - `ENAMETOOLONG`: throw `PROJECT_PATH_INVALID` (G). `ELOOP`: throw `PROJECT_PATH_OUTSIDE` (H). Any other error: the generic error of P10.
   - A symlink: `real = realpathSync.native(next)`. `ENOENT`, `ELOOP`, `ENOTDIR` or `ENAMETOOLONG` throws `PROJECT_PATH_OUTSIDE` (H); other errors are the generic error. If `!inside(rootReal, real)`, throw `PROJECT_PATH_OUTSIDE` (H). Else `current = real`.
   - Anything else: `current = next`.

   `current` never contains a symlink: it starts as the real root, and it grows only by a component that `lstat` showed is not a symlink, or is replaced by the fully resolved real path of a symlink. So no later `lstat` crosses a hidden link.
5. **Result path.** `realPath = join(current, ...remaining)`; `exists = remaining.length === 0`.
6. **Reserved, real.** `real = relative(rootReal, realPath)`, with `sep` turned into `/`. If `isReservedPath(real)`, throw `PROJECT_PATH_RESERVED`.
7. Return `{ relativePath, realPath, isRoot: relativePath === '', exists }`.

Messages (the contract has no message text; these are this plan's), the values of `PATH_MESSAGES`:

- A: `The path must be a non-empty project-relative string.`
- B: `The path must not contain a NUL byte.`
- C: `The path must use forward slashes, not backslashes.`
- D: `The path must be relative to the project, not absolute.`
- E: `The path must not contain a ".." segment.`
- F: `The path must not contain an empty segment.`
- G: `A name in the path is too long.`
- H (outside): `The path leads outside the project, or through a link that cannot be resolved.`
- reserved: `The path is reserved for the app and is not available through the file API.`
- not found (root): `The project folder was not found.`

Every `ModuleError` is built by one helper, `fail(code, message)`, which takes one of the four codes and one value of `PATH_MESSAGES` and sets the status from `PROJECT_ERROR_STATUS[code]`. No `details` are passed.

```ts
// project-store.service.ts
@Injectable()
export class ProjectStoreService {
  constructor(@Inject(SCRIBA_ENV) private readonly env: ScribaEnv) {}
  get libraryRoot(): string { return this.env.SCRIBA_BOOKS_DIR; }
  // The in-process path check. Reserved paths are refused.
  resolvePath(projectRoot: string, path: string): ResolvedProjectPath {
    return resolveProjectPath(projectRoot, path);
  }
}
// project-store.module.ts (besides the @Module)
export { ProjectStoreService } from './project-store.service';
export type { ResolvedProjectPath } from './path-safety';
// project-store-path-safety.kit.ts (the handler)
@Post('resolve')
@HttpCode(200)
resolve(@Body() body: { project: string; path: unknown }) {
  const root = join(this.store.libraryRoot, body.project);
  // No validation here: a non-string path reaches the function's own check.
  const { relativePath, isRoot, exists } = this.store.resolvePath(root, body.path as string);
  return { relativePath, isRoot, exists };
}
```

## 6. Open points

1. **Case-insensitive mounts and the containment test.** The check is a string-prefix test on real paths (P13). On a case-insensitive mount, a symlink inside the project spelled with a different letter case, such as `ln -s ../Book/x`, makes `realpath` return `.../Book/x`, which does not start with `.../book`, so the path is refused. That fails safe (a refusal, never an escape). A fallback comparing `dev` and `ino` up the ancestor chain would accept it, but it cannot be tested on this Linux disk (F29), and a filesystem with unstable inode numbers could make it accept wrongly. Recommended: no fallback. The unit itself says "compares real paths" (unit line 24). Decided by: the Navigator, if it wants the inode check.
2. **Reserved comparison ignores case (P6).** Extends S7 from the prefix check to the reserved check. Cost: `Drafts/.versions/` is refused on a case-sensitive disk too. Recommended: keep. The Navigator confirms.
3. **No id-to-root helper (P1, S12).** PST-02 does not map a project id to a folder. Recommended: keep it out, as the DECISIONS hand-off says. If PST-03 wants one, it belongs in PST-03 and must look the id up in the discovered list.
4. **Growth of `ProjectStoreService` and `project-store.module.ts`.** PST-04 and PST-05 run in parallel, then PST-06 and PST-08, and each adds provider methods, providers and controllers to the same two files. Recommended: each later unit adds its own `@Injectable()` file and one line in the module's `providers` or `controllers`, and adds a delegating method to `ProjectStoreService` only for what other modules call. The orchestrator orders the merges and reconciles the text.
5. **`.` as the project root (P4).** Needed for `list`; PST-06 maps AGL-02's optional `path` to `.`. The empty string stays invalid, because the criterion says "empty segment". Confirm in PST-06's plan.
6. **No internal mode for reserved paths (P12).** Revision 1 had an `allowReserved` option; R1.1 rejected it because its test needed a private helper, and it is dropped. PST-16 (the first unit that writes a version, unit PST-16 line 24) and PST-18 (version list, read and restore, unit PST-18 lines 18 and 19) decide how the module's own code reaches `drafts/.versions/`: a plain-fs path built from an approved draft path, or a mode added to `path-safety.ts` with its own test through their routes. PST-15 needs no mode (section 5). Recommended: the mode, added by PST-16 and tested through the accept route. The orchestrator carries this into PST-16's plan.
7. **Dangling symlinks inside the project (P8).** A dangling link whose target would be inside the project is refused as outside. A more exact rule would resolve the link text lexically and check it. Recommended: keep the conservative rule.
8. **Sync API (P2).** If PST-06 prefers async, wrapping is trivial; the reverse is not. Recommended: keep sync.
9. **Hard links, mount points and races.** The check cannot see a hard link to an outside file or a bind mount inside a project, and there is a gap between the check and the use (A4, A5). Accepted for a single-user local app; the callers use `realPath` at once.
10. **Untested branch.** The "unexpected errno" branch of P10 has no test: the tests run as a user that can read every folder of the temp library, and a container user is often root, so `EACCES` cannot be caused reliably. It is two lines. Recommended: accept, and review it by reading (step 7).
11. **Name choices.** `ProjectStoreService` (also the class name of the lint fixture, F5), `resolvePath`, `libraryRoot`, `resolveProjectPath`, `isReservedPath`, `PATH_MESSAGES`, the result field names, the test-only route `/api/project-store-test/resolve` and the messages are this plan's. No unit names any of them (F30). The later plans adopt them or the orchestrator reconciles.
