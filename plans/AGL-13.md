## 1. Decisions this plan follows

### 1a. Settled by the unit, the module, earlier plans, DECISIONS and the code on main
- **D1. Target argument.** Only the narrative (registry) tools whose output is `draft`, `entity` or `graph` get an optional `target`. It must sit in the kind's folder (`drafts/`, `entities/`, `graphs/`). Source: unit line 18; module line 54.
- **D2. Draft.** Overlay at `target`, or a new `drafts/<tool-name>-<yyyymmdd-hhmm>.md` (UTC; `-2`, `-3` on collision). The grounding check after it is AGL-17. Source: unit line 19.
- **D3. Entity.** The same rule in `entities/`, default `entities/<tool-name>-<yyyymmdd-hhmm>.md`. Source: unit line 20.
- **D4. Graph.** Validated with the Graph runner's `graphFileSchema`. Valid goes to `graphs/` (default `graphs/<slug-of-name>.json`) as a pending change; invalid gives a readable error and the same retries. Source: unit line 21; `packages/contracts/src/graph-runner/graph.ts` lines 183 to 186.
- **D5. Claims and check.** Check is a card and no file (unit line 24). Claims: open point 1, settled by the Navigator (option (a)): a card only, no artefact.
- **D6. Provenance.** Draft provenance reaches the pending change through the overlay entry. Source: unit line 25; AGL-09 OP3 (`plans/DECISIONS.md` lines 5118 to 5122; `plans/AGL-09.md` line 201). `provenanceOf` gives provenance to drafts only (`agent-run.ts` lines 255 to 273), so entity and graph entries carry none.
- **D7. Flush and counting.** Overlay entries are proposed at run end by AGL-12's flush, unchanged (`agent-run.ts` lines 376 to 407). A refusal the model must fix is a `ToolArgumentError` raised in the handler, so the dispatcher counts it (AGL-02; `tools/tool-run.ts` lines 171 to 173; `plans/AGL-12.md` line 176).
- **D8. Graph file.** The file stem is the graph id and matches `GRAPH_ID_PATTERN` (`packages/contracts/src/graph-runner/constants.ts` line 22; GRR-01 unit line 17). The agent loop imports the contract (`@bbartolome/scriba-contracts/graph-runner`, `packages/contracts/package.json` line 30), never the Graph runner module (`eslint.config.mjs` lines 69 to 87, R2; module line 50). The agent loop already imports other contract subpaths (`narrative-tools.ts` lines 2 to 13), so the subpath import is not an R1 or R2 case.
- **D9. Test seam.** The composed app with Platform's mock OpenAI server (module lines 60 to 62). The unit has no seam parenthetical.
- **D10. Contracts.** No new event, route, error code or contract field. Tool-call events and transcript kinds keep their shapes. `written` (P3) is an internal field of `ToolHandlerResult` and `ToolOutcome` (`tools/tool-types.ts`), not a contract field.

### 1b. Decisions this plan makes (simplest option)
- **P1. Files.** A new `tools/output-routing.ts` with no Nest import: `routedFolder(kind)`, `stampOf(now)`, `withSuffix(path, n)`, `slugOf(name)` and `checkGraph(content)`.
- **P2. Where checks run.** The target checks (P4, P5) and the capture of an explicit target run in the narrative handler before the executor call; the content checks (P7, P9) and the default name (P8) run after it. A refused target never reaches the executor, so the model gets a readable line and no model call is spent.
- **P3. Return, then put.** The handler returns `written: {path, content}` on its result (new optional field on `ToolHandlerResult` and on the `result` variant of `ToolOutcome`). `dispatch` copies it into the outcome only when it is set, as it does `citations` (`tool-run.ts` lines 158 to 160), so the built-in outcomes keep their shape (`agent-loop-tools.test.ts` lines 140 and 182 use `toEqual`). `AgentRun.runCall` puts it into the overlay, `this.tools.overlay.put(written.path, written.content, callId, provenance)`, right after the provenance is built (after `agent-run.ts` line 292) and **before** any `tool-call-result` emit (line 306). The handler does not put it itself, because provenance is built in `runCall` (AGL-09 PC7).
- **P4. Issues at `/target`.** The dispatcher maps every `ModuleError` to `/path` (`tool-run.ts` lines 166 to 169). The handler therefore catches a `ModuleError` from `targetOf` or from `captureOf` (a target that is not a text file, or is over the cap, `builtin-tools.ts` lines 91 to 93) and raises a `ToolArgumentError` with one issue at `/target` and the error's message. A plain `Error` (project not found) is not caught, as AGL-12 P5 (b).
- **P5. Target checks, in this order.** The narrative tools have no Ajv validator in the dispatcher (`tool-types.ts` lines 73 to 87), so the handler checks the value itself. (a) A `target` that is not a non-empty string: issue at `/target`, `The target must be a file in <folder>/.` (b) `targetOf` (path safety, as AGL-12 P5). (c) The resolved `relativePath` must start with `<folder>/` and have at least one more character; otherwise the same message as (a). (d) For a graph, the `relativePath` must be `graphs/<id>.json` with no other `/` and `<id>` matching `GRAPH_ID_PATTERN`; otherwise `/target`, `The target must be graphs/<id>.json, where <id> is lower-case letters, digits and hyphens.` (e) `isFolder`: `/target`, `FOLDER_MESSAGE`. (f) `captureOf` (P6). Drafts and entities have no extension rule (the unit gives none).
- **P6. Captured base.** A routed path is captured with `captureOf` before it is returned (AGL-12 P3, D2): an explicit target in P5 (f), before the executor; a default path after the executor, when it is chosen (P8). Without it, an existing target would be proposed against `''` (`agent-run.ts` lines 412 to 417).
- **P7. Size.** Content over the cap (`isTooLarge`) is refused with one issue at `''` (shown as `arguments`) and `SIZE_MESSAGE`. The narrative tool has no `content` argument, so the issue is not put at `/content`.
- **P8. Default names.** `<folder>/<tool-name>-<stamp>.md` for drafts and entities, and `graphs/<slug>.json` for graphs. `stampOf` gives UTC `yyyymmdd-hhmm` from one `new Date()` per call. The suffix `-2`, `-3`, ... goes before the extension (`drafts/cold_open-20261116-0930-2.md`, `graphs/ada-2.json`) and is raised until the path is free: `targetOf(...).exists` is false and `run.overlay.contentOf(path)` is undefined. The same rule applies to graphs (open point 2, settled). An explicit `target` gets no suffix: a second write to it in the same run replaces the overlay text (AGL-12 D1).
- **P9. Graph checks.** `JSON.parse`, then `graphFileSchema.safeParse`. A parse failure is one issue at `/graph` with the message `is not valid JSON: <parser message>`. Each Zod issue is one issue at `/graph` plus its path, each key escaped as a JSON Pointer segment, so the model reads `graph/nodes/0/id: <zod message>`. The issues are raised as one `ToolArgumentError` (counted, same retries).
- **P10. Slug.** Lower case; each run of characters outside `a-z0-9` becomes one `-`; leading and trailing `-` are removed; `graph` when nothing is left. The result always matches `GRAPH_ID_PATTERN`, and so does a suffixed one (open point 3, settled).
- **P11. Schema copy.** For draft, entity and graph tools the schema the model sees is a copy of the registry's `parameters` with an optional `target` property `{type: 'string', minLength: 1, description: 'Optional. The file to write, in <folder>/. Left out, a new file is named for you.'}`. The registry object is not changed (`fn` is the cached `views.functionSchema`, `catalog.service.ts` lines 320 to 334; `emit.ts` line 121). A tool whose own inputs already have a `target` key gets no routing argument: it keeps its input and its output goes to the default path.
- **P12. Stripping.** For a tool that got the argument (P11), the handler reads `target` from the raw arguments and removes it from a copy **before** `filledArguments` (`narrative-tools.ts` line 145). The executor's full Ajv check refuses unknown arguments (`executor.service.ts` lines 118 to 121), so it never sees `target`.
- **P13. Check and claims (claims settled by the Navigator, open point 1, option (a)).** A `check` output gets no `target` property and no `written`; check output already creates no file on main, so AC3 is a regression guard. For `claims`, this rule is written for option (a) of open point 1: no `target`, no `written`, no artefact; the output rides the `tool-call-result` card unchanged, as at M2 (AGL-09 OP3).
- **P14. Tests.** One new file, `apps/api/test/agent-loop-output-routing.test.ts`, with its own helpers (AGL-12 P15 precedent). The check tool comes from a temp pack folder the test writes. The shared fixture packs stay as they are, because other tests compare the offered tools (`agent-loop-narrative.test.ts`).
- **P15. Kind source.** `narrativeDefinition` takes the tool's declared kind, `this.catalog.entry(name).spec.output` (`packs.ts` line 36; `spec.ts` line 59), read once in `startRun`. The routing uses the declared kind; the executor's `result.output.kind` is the same kind (`executor.service.ts` line 100).
- **P16. Entity (open point 4, settled).** Entity outputs follow the draft code path with folder `entities`. Their content is not checked (the unit names no check). No test: no criterion covers entities, and the plan gives one test per criterion.
- **P17. Collisions across runs (open point 5, settled).** The free-path check of P8 sees the disk and this run's overlay only. An open change of another run at the same path is allowed: `propose` folds only same-origin changes (`pending.service.ts` lines 70 to 76 and 376 to 381), and the first change accepted makes the other conflict through the Project store's recheck (`pending.service.ts` lines 89 and 245) and three-way check. No pending-queue lookup is added.
