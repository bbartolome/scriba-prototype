2. **Inputs: `reference` and `readOnly`.** `reference` is required, `{projectId: string; path: FileReference}`, where `FileReference` is the contract's project-relative path string (`packages/contracts/src/project-store/files.ts` lines 9 and 75; `plans/DECISIONS.md` line 2295 is the PST-01 review item on the file reference). `readOnly` is a boolean, default `false`. 3. **Outputs.** `contentChange` (string: the full text, emitted once after the load and then on every document change), `dirtyChange` (boolean: the text differs from the last loaded or saved text), `saveStateChange` (`SaveState`: `'saved' | 'saving' | 'unsaved' | 'failed' | 'conflict'`, the five values of unit line 18), and `errorChange` (string or `null`, the message of the last failed request). SHL-13 reaches `saved`, `unsaved`, `saving` (set during its manual save), `failed` (any error except a write conflict) and `conflict` (the write error code `PROJECT_WRITE_CONFLICT`, which is `packages/contracts/src/project-store/errors.ts` line 13 with HTTP status 409 at line 66, and is listed in `units/PST-01-contract-slice.md` line 52). Debounce, coalescing and the leave guards are SHL-14 (SHL-14 unit lines 19 and 22, `units/SHL-14-editor-saving.md`; these are not lines of this unit). Sources: unit lines 18 and 20. [decision]

4. **The file API goes through the typed client and its paths are copies.** The client is injected through `API_CLIENT` (`apps/web/src/app/shell/tokens.ts` lines 6 to 9). The read is `client.get(readPath, readCopy, {path})`, a `GET` whose `path` travels in the query (`apps/web/src/app/shell/api-client.ts` lines 61 to 67; `packages/contracts/src/project-store/routes.ts` lines 16 and 17). The write is `client.post(writePath, {path, content, baseHash}, writeResultCopy)` (`api-client.ts` lines 75 to 87; `routes.ts` lines 18 and 19; the request schema `files.ts` lines 42 to 46). Sources: unit line 18 ("Loads via the Project store file API read (through the typed API client)"); `modules/shell.md` line 43 (the Shell consumes the file-API read and write shapes of `/project-store`). [decision]

5. **No runtime zod in the Shell: the response copies are hand-written.** The read and write-result responses are checked by `readCopy` and `writeResultCopy`, added to `apps/web/src/app/shell/project-store-copies.ts` (which already holds `ACTIVE_PROJECT_PATH`, `PROJECTS_PATH`, `activeProjectCopy` and `projectListCopy`, lines 9 to 72). The rule: all contract imports in the Shell are type-only, except in tests. Sources: `plans/DECISIONS.md` lines 1084 to 1086 (Navigator decision, no runtime zod); `apps/web/src/app/shell/sse-envelope.ts` lines 6 and 7; `apps/web/src/app/shell/project-store-copies.ts` lines 9 and 10. The new copies are path constants `PROJECT_FILE_PATH` (`'/api/project-store/projects/:projectId/file'`) and `PROJECT_FILE_WRITE_PATH` (`'/api/project-store/projects/:projectId/file/write'`), two helpers `projectFilePath(projectId)` and `projectFileWritePath(projectId)` (replace `:projectId` with `encodeURIComponent(projectId)` and return an `ApiPath`), and the two guards. [decision]

6. **The line model is the dominant separator, which is this plan's reading of unit line 19.** The editor state's `EditorState.lineSeparator` facet is set to the separator the loaded text uses most, counted as the other local Shell prototype counts (section 7a, F13: `markdown-document.ts` lines 13 to 24). CRLF is the number of `\r\n` pairs. LF is the number of `\n` that is not preceded by `\r`, that is, the matches of `/\r?\n/g` that are not `\r\n`. The facet is `\r\n` only when CRLF is greater than LF, and `\n` otherwise (on a tie, and for a file with no line break). A lone CR is not counted and is not a separator. So `alpha\r\nbeta\r\n` has CRLF 2 and LF 0 and gets `\r\n`; counting every `\n`, the CRLF pairs too, would give a tie and the wrong facet. Because CodeMirror splits and joins on that one separator, the other separator stays inside its line's text and is written back unchanged. Unit line 19 says only "detect the file's line separator"; the word "dominant" and the counting rule are this plan's reading, not the unit's wording. The probe in section 7a (F12, rows 2 to 5) shows that a CRLF file and a mixed file round-trip byte for byte with either facet value. The unit's sentence "CRLF and mixed endings survive" is correct, so the unit needs no change for it. Cost: a minority-separator line carries a control character, and editing at its end has an effect that open point 1 records. [decision, checked by F12]

7. **The text sent is `state.sliceDoc()`, never `state.doc.toString()`.** `Text.toString` joins lines with LF, so it would rewrite every CRLF line (`@codemirror/state` 6.7.6 in `/tmp/md-roundtrip/node_modules`: `dist/index.js` line 179, where `sliceString` joins with `"\n"` by default, which is what `toString` uses; line 2779 for `lineBreak` and line 2698 for `sliceDoc`; probe row 8 in F12). Nothing else is applied to the text: no trim, no reformat, no added or removed trailing newline. Source: unit line 19. [decision, checked by F12]

8. **A BOM stays in the document as its first character (U+FEFF).** It is not stripped and not stored elsewhere. The write sends it, so the bytes match. Source: unit line 19 ("Keep a BOM if the file API returns one"). The preview of SHL-11 drops a leading BOM before it reads front matter (`plans/SHL-11.md` line 125 at HEAD `81ccdcb`; line 105 at `2c8e02f`), so the editor and the preview both handle it. Whether the file API returns the BOM at all is assumed (open point 4). [decision]

9. **Front matter, `_emphasis_` and `*emphasis*` are plain text.** The Markdown language only highlights them. No special node is added. Source: unit line 19 ("Front matter is plain text in the editor"). [decision]

10. **Read-only.** The state gets `EditorState.readOnly.of(readOnly)` and the view gets `EditorView.editable.of(!readOnly)`, both inside one `Compartment` that an `effect` reconfigures when the input changes. The Save button is disabled while `readOnly` is set or a save is in flight. CodeMirror sets the content element's `contenteditable` from the `editable` facet (`@codemirror/view` 6.43.15, `dist/index.js` line 8345, in the other local prototype's `node_modules`; F14). Source: unit line 25 (line 24 is the targeted edit); the same two facets as the other local prototype, `apps/web` `markdown-editor.ts` lines 58 to 60 (F13). The reconfiguration on a later change is not covered by a criterion. [decision, checked by F14]

11. **Saving in SHL-13 is one manual save.** The Save button sends `{path, content, baseHash}`, where `baseHash` is the hash of the last load or the last successful save (`files.ts` lines 42 to 46; unit line 20 of SHL-14 fixes the rule). The returned `hash` becomes the next base. A save is sent even when the text is unchanged, because criterion 1 asks for a write. The saved text is the `content` that was sent, not a later reading of the document. On success `savedText` becomes that `content`; `dirtyChange` is `documentText(state) !== savedText`, and `saveStateChange` moves to `saved` when that is `false` and to `unsaved` when it is `true`, which also covers a text that changed during the save. Source: unit line 23; SHL-14 unit lines 19 and 20. [decision]

12. **Load on reference change.** The effect that loads the file runs again when `reference` changes; it destroys the old view and loads the new file. Unsaved text in the old view is lost. SHL-14 adds the leave guard; until then, the consumer keys the component by file. Open point 5. [decision]

13. **Styling through CodeMirror's theme, not component CSS.** `EditorView.theme` sets the background and the text colour from `var(--mat-sys-surface)` and `var(--mat-sys-on-surface)`, the tokens of `apps/web/src/material-theme.scss` lines 37 and 38. Component styles are not used: with emulated encapsulation they would not reach the DOM that CodeMirror creates. The component adds no stylesheet of its own, so the 4 kB component style budget (`apps/web/angular.json` lines 39 to 42) is not touched. [decision]

14. **Editor extensions, one list.** `history()` and `historyKeymap`, `defaultKeymap` (from `@codemirror/commands`); `markdown()` (from `@codemirror/lang-markdown`); `syntaxHighlighting(defaultHighlightStyle, {fallback: true})` (from `@codemirror/language`); `highlightSpecialChars()` and `EditorView.lineWrapping` (from `@codemirror/view`), so that a stray CR or BOM is visible and long prose lines wrap on a phone; and `EditorView.contentAttributes` with `aria-label` set to `Markdown source for <path>`. The label answers the review advice of `plans/DECISIONS.md` line 3322 for this component; the accessibility pass as a whole is SHL-19's (`units/SHL-19-polish-gate.md` line 21 names the editor in its automated check). [decision]

## 6. Open points

1. **[NAVIGATOR] Editing at a CRLF line end in a mixed file whose LF lines dominate.** With the facet set to LF, a CRLF line's CR is the last character of its line text. Decision 6 gives `\r\n` to a file whose CRLF pairs outnumber its bare LF lines, so the case that reaches this limit is a mixed file with more bare LF than CRLF: fixture 5 (`alpha\nbeta\r\ngamma\ndelta\n`, facet `\n`) with `X` inserted at the end of its line 2 (`beta\r`) gives `alpha\nbeta\rX\ngamma\ndelta\n` (F12, row 15).
