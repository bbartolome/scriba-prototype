### 1b. Decisions this plan makes (the unit leaves them open)

- **D1 Files and names.** New `apps/web/src/app/features/agent-loop/grounding-chip.ts`: standalone `GroundingChip`, selector `app-grounding-chip`, required input `entry: ChatGrounding`. The pure types and helpers go in `chat-state.ts`. The literal `AGENT_GROUNDING_PATH` goes in `agent-contract.ts`. Tests: G1 to G5 appended to `chat-page.spec.ts`; X1 amended in `agent-contract.spec.ts`. No other name is chosen.
- **D2 Placement: beside the card, not in its slot.** A grounding chip sits in the turn after that turn's cards, outside the Shell card. Under S8 a chip in the slot would hide with a collapsed phone card, and unit line 18 asks for a summary chip per draft card. Outside the card, no Shell change is needed. Open point 2 asks the Navigator to confirm the reading.
- **D3 Grouping.** Each turn has one chip per grounding target (`targetPath`), in order of first appearance. Each chip holds the latest result for its path, or the latest `checking` state. A chip is not matched to a draft card on `main`, because no draft card carries its path (open point 1).
- **D4 Summary text.** `N supported · N weak · N unsupported`, with the middle dot as unit line 18 writes it. The counts are taken from the claims of the result, because the result has no summary field (`grounding.ts` line 33). While a check runs the text is `Checking <path>`.
- **D5 Verdict badge.** Text labels `Supported`, `Weak` and `Unsupported`. Icons (Material ligatures, as the Shell's status icons are, `tool-call-card.ts` lines 28 to 35): `check_circle`, `warning` and `cancel`, each `aria-hidden`. Colour tokens the web app already uses (CHECKED F13): supported `--mat-sys-tertiary-container` with `--mat-sys-on-tertiary-container`; weak `--mat-sys-secondary-container` with `--mat-sys-on-secondary-container`; unsupported `--mat-sys-error-container` with `--mat-sys-on-error-container`. Each badge has `data-verdict` set to the verdict. Contrast is left to SHL-19 (open point 6).
- **D6 Expansion.** The chip is a `button` with `aria-expanded` and `aria-controls`, as the card header is (`tool-call-card.ts` lines 165 to 167). Its default is collapsed on a phone (`DeviceClassService.deviceClass() === 'phone'`, `apps/web/src/app/shell/device-class.ts` line 71) and expanded on other devices. The state is a `linkedSignal` on that default, as the card does (`tool-call-card.ts` lines 258 to 269). Unit line 20 is read as "the list collapses; the chip shows" (open point 2).
- **D7 Claim rows.** Each row shows the verdict badge, the claim `text`, and, when the claim has a passage, a link to its `path` (S7) with the `snippet`. A claim with no passage shows `No source passage cited.` The claim's `span` and `reason` are not shown: unit line 18 lists four items, and `reason` stays in the contract.
- **D8 Check grounding.** A card whose `diffPreview.path` starts with `drafts/` shows a "Check grounding" button after the card (AGL-17 unit line 18 names `drafts/` paths; open point 7). The button is disabled while `running()`. It posts `{path}` to `AGENT_GROUNDING_PATH`, reply `startReply`. On success `applyStart` records the run with the intent label `Check grounding: <path>`; that label is not sent. A failure goes through `noticeOf` (`chat-page.ts` line 85). The button does not appear on `main`, because no draft card has a path there (open point 1; assumption A2).
- **D9 Grounding events.** `grounding-started` (`{targetPath}`) sets a `checking` entry for its path. `grounding-result` replaces the entry for its path with the result. Both apply under S12. `isChatEvent` accepts both, which reverses D18 of AGL-07. A grounding event asks for no run-state read.
- **D10 Run state.** `applyRunState` sets one entry per path from `groundingResults`, the last one winning. A `checking` entry whose path has no result keeps its place. History turns carry no grounding, because `conversationTurnSchema` has no such field (`packages/contracts/src/agent-loop/runs.ts` line 40; open point 5).
- **D11 Guards.** `isRunState` checks each `groundingResults` item with `isGroundingResult`, in place of the array-only check (`agent-contract.ts` line 175). `isGroundingResult` checks the fields the page reads: `schemaVersion` 1; `targetPath` a non-empty string; `claims` an array whose items have `text` a non-empty string, `verdict` one of the three values, and `passage` optional, with `path` non-empty, `offset` an integer of at least 0 and `snippet` a string. The other fields are checked by outer kind (AGL-07 D3). The event guards add the base `runId` and `seq`, and `targetPath` for `grounding-started`.
- **D12 Test seam and phone setup.** The chat route against the fakes, as AGL-07 D20. A phone test restores the stub and stubs 390 by 844 before it renders, as T4 does (`chat-page.spec.ts` lines 324 and 325).
