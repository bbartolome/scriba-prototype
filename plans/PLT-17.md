Both checks send their stdout to `/dev/null`, so the installer's stdout carries only its progress lines (D20; `command -v` and `docker info` print to stdout). Source: unit 25 (step 1) and unit 40. Current daemon: F33.
- **D9. Extraction.** If `docker image inspect "$REF" >/dev/null 2>&1` fails (its stdout, the JSON on success, and its stderr, `No such image` on a miss, both go to `/dev/null`), `docker pull "$REF"` runs with its stdout sent to stderr. Its progress goes to stdout (A5); the redirect keeps it off the installer's stdout, which carries only the installer's own progress lines (D20). On a normal first install the one-liner pulls only `bbartolome/scriba:latest`, so the pinned tag is not local and the probe's failure is the normal path, not an error; the probe is silent on both streams by design (D20). Then `docker run --rm --entrypoint tar "$REF" -C /opt/installer -cf - .` runs with stdin from `/dev/null`, and its stdout is piped into `tar -xf - -C "$TMP"`, where `TMP=$(mktemp -d)`. The archive is never extracted into the install folder: its `./` entry would set that folder's mode (F36: under umask 022, GNU tar set a 0700 folder to 0755). The script then moves the four named files, `compose.yaml`, `compose-version`, `installer-hint.txt` and `RUNBOOK.md`, from `$TMP` into the install folder with `mv`, and removes `$TMP`. Before the move, the script checks that all four exist in `$TMP` and exits 1 if one does not (added here). After the move, the script aborts unless `compose.yaml` and `compose-version` exist in the install folder. The compose file comes from this extraction; the installer writes no compose file of its own (unit 21 and step 5 of unit 29 name the same file). Sources: unit 21 and 26; F16 (line 60); F14 (`deploy/` holds `compose.yaml`, `compose-version`, `installer-hint.txt`, `RUNBOOK.md`); F36. Not checked here: bsdtar's behaviour on the Mac; U4 records the install folder's mode there.

Reason: Compose reads escapes inside double quotes, so a backslash in the library path would be written to `.env` corrupted. Limit (not a reason; the Navigator's decision of 2026-11-14, option ii): without a terminal the default `$HOME/Books` reaches the `.env` write (`scripts/entrypoint.sh` lines 118 and 168 on `main` at `bc46c38`) without this character check; a `$HOME` containing a double quote, `$`, a backtick or a backslash would be written unchecked. Sources: unit 27 and 38; F21 line 8 (the contract default `~/Books` is "absolute" for the host path).
- **D11. The install folder must not be the library or inside it.** Checked after the answers and before any library or `.env` write; exit 1 if it is. Reason: a `.secret` inside the library would be readable by the app through the library mount (F4, module line 38; unit 23). Not a criterion; covered by an extra test case.

Sources: unit 29; F11 lines 40 and 48 to 52.

Content: one line, `TS_AUTHKEY=<value>`. Written inside a subshell with `umask 077` (`( umask 077; … > .secret )` in the install folder) and given mode 0600 with `chmod`. The umask is set in that subshell only, so the other writes keep the caller's umask (the harness runs under umask 022, see the harness row of section 2). Sources: unit 29 and 37 (optional, mode 0600); F8 line 335 (`.secret` holds only `TS_AUTHKEY`); F30 (module line 78 says the installer writes the auth key; SAU-17 unit line 24 reads it). - **D16. Health wait.** The container ID comes from `docker compose ps -q scriba`. The script polls `docker inspect -f '{{.State.Health.Status}}'` every 2 seconds, for at most 60 polls (120 seconds). `healthy` succeeds. `unhealthy` fails at once. Any other state at the limit fails. The failure message goes to stderr, names `docker compose logs scriba` and `docker compose logs tailscale`, and exits 1. Only `scriba` is waited for, because `tailscale` has no healthcheck (F11, lines 57 to 68; F8 line 13). The script runs its own loop, not `up --wait`, so the tests can drive it with stubs (the stub `sleep` makes the loop instant). Source: unit 31.
- **D17. Setup URL.** After healthy, if `<library>/.scriba/setup-url` exists, its one line is printed. Otherwise the script prints `http://127.0.0.1:<port>` and the command `cat <library>/.scriba/setup-url`, to read the URL later. Source: unit 32; F30 (SAU-02 unit line 20; plans/SAU-02.md line 138).

- **D20. Output.** Progress goes to stdout; errors go to stderr; the exit code is 0 on success and 1 on failure. Source: unit 22 and 39.
- **D21. The emitted script is bash.** It starts with `#!/usr/bin/env bash` and `set -euo pipefail`. The entrypoint prints it with `sed` replacing one placeholder, whose value is the validated pin (D3; it has no `/`, so the substitution is safe). The emitted script uses only syntax that bash 3.2 accepts (no `mapfile`, `${var,,}` or associative arrays), because a Mac runs it with `/bin/bash` 3.2 (A14; U1). Source: unit 39 (`bash -n`).
- **D22. Guard cases are extra tests.** The root refusal (D5), the existing `.env` (D7), the install-folder guard (D11), the dev-build refusal (D3), the bad library path and the bad `TS_AUTHKEY` (D10, D14) each get an extra `it` block in the matching test file. - **C1 (`installer-first-install.test.ts`).** The stub `docker` answers `info` (exit 0), `compose version --short` (`2.30.0`), `image inspect` (exit 1, printing `[]` to stdout and `No such image` to stderr), `pull` (a progress line to stdout, exit 0), `run … --entrypoint tar` (writes a fixture tar with `compose.yaml`, `compose-version` containing `2`, `installer-hint.txt` and `RUNBOOK.md`, and a `./` entry with mode 0755, as `tar -cf - .` writes), `compose ps -q scriba` (an ID), `inspect -f …` (`healthy`) and `compose up -d` (exit 0; it writes a `setup-url` file under `$HOME/Books/.scriba/` when a flag is set, as the app's boot would).
