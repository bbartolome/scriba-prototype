## 1. Decisions this plan follows

1. **Component, inputs and place.** `DiffView` is a standalone component, selector `app-diff-view`, in `apps/web/src/app/shell/diff-view.ts`, exported from `shell/index.ts`. Inputs: `path` (required string), `base` (required string), `proposed` (required string), `conflict` (boolean, default `false`) and `conflictMessage` (optional string). It has no outputs and knows nothing about pending changes: callers feed strings. A new file's `base` is `''`. Source: unit line 18; `modules/shell.md` lines 42 (the Shell's own code lives outside `features/`), 43 (shared components take Shell-local inputs), 81 (the diff view is a Shell API) and 96 ("the diff view renders strings"); DECISIONS line 2746 (the Navigator's decision (A) on SHL-09: Shell code goes under `shell/`); `shell/index.ts` line 1 ("The Shell's entry for features"). [FACT F2, F4, F6, F7] [DECISION]

2. **Library and dependencies.** The view is built on `@codemirror/merge` only; no other diff library. The three packages `@codemirror/merge`, `@codemirror/state` and `@codemirror/view` are listed in `apps/web/package.json` `dependencies` at exact versions (no `^` or `~`), as every entry there is (lines 12 to 23 and 26 to 30). `state` and `view` are listed because the component imports them directly, and two copies of either break CodeMirror at run time, so step 2 checks that each resolves to one version. The code stage resolves the versions and records them; this plan names none. In this session the newest are `@codemirror/merge` 6.12.3 (it depends on `@codemirror/language`, `@codemirror/state` ^6.0.0, `@codemirror/view` ^6.17.0, `@lezer/highlight` and `style-mod`), `@codemirror/state` 6.7.6 and `@codemirror/view` 6.43.15 (it needs `state` ^6.7.0), the same as the Opus review of revision 1 found (DECISIONS line 2959). **Which packages to install** is read from the branch's own `apps/web/package.json`: step 2 installs only those of the three that this file does not list. On a branch made from the current `main` the file equals `main`'s; on a branch whose base is behind `main` (an earlier session stopped before its first commit) it is the base's, and `main` may list a package that the branch still needs. On the packages, `main`'s files serve two things only: the version of a package that `main` lists and the branch lacks (step 2 takes `main`'s exact version), and a package that both list at different versions (step 0 records both for the driver's rebase, open point 1). `node_modules` decides nothing here: on a resumed branch `npm ci` has installed the branch's own CodeMirror. Source: unit line 19; `modules/shell.md` line 98 (CodeMirror 6 only); DECISIONS line 3254 (the Opus review of revision 5, item 3). [FACT F12, F23] [ASSUMED A1] [DECISION]

3. **Two layouts, one default by device class, a toggle that overrides.** Unified is an `EditorView` whose document is `proposed`, with the `unifiedMergeView` extension and `original` = base. Side by side is a `MergeView` with `a` = base and `b` = proposed. The default follows `DeviceClassService.deviceClass()`: `phone` gives unified; `tablet` and `desktop` give side by side. A two-option `mat-button-toggle-group` (`aria-label="Diff layout"`, options "Unified" and "Side by side") sets an override signal. The layout is `override() ?? default`, so once the toggle is used the layout no longer follows a resize. The override is per instance and is not stored (open point 2). The selected option is always the effective layout. Source: unit lines 19 and 25; `plans/SHL-05.md` line 258 (the device-class signal is provided "for unified diffs on phones"); `device-class.ts` lines 71 and 99 to 103; `theme-toggle.ts` lines 16 to 24 (the toggle pattern). [FACT F8, F10, F21] [DECISION]

4. **Read-only, with no controls.** The component never changes a document and shows no accept, reject or revert control: `mergeControls: false` on the unified extension, no `revertControls` on `MergeView`, and `EditorState.readOnly.of(true)` and `EditorView.editable.of(false)` on every editor. Accepting or rejecting is the caller's action outside the view. Source: unit title (line 3) and line 21; SHL-16 unit lines 20 to 22 ("Read-only mode is unchanged"). [ASSUMED A2] [DECISION]

5. **Exact text, so that every difference is visible.** The component builds every document itself, as a `Text`: `Text.of(text.split('\n'))` for `doc` (unified), for `a` and `b` (side by side), and for `original` of `unifiedMergeView`. A raw string is never passed. Then a `\r` is an ordinary character of its line, `doc.toString()` returns exactly the string fed in, and an LF to CRLF change is a change on every line. What closes the trap of criterion 3 is this construction, not the line-separator facet: `EditorState.create` takes a `Text` document as it is and reads the `lineSeparator` facet only when it must split a string document, and `unifiedMergeView` splits a string `original` on `/\r?\n/` and ignores the facet. With raw strings, LF text and CRLF text give two identical documents and no marked line. All of this is UNVERIFIED until step 2 reads the installed package (A3). Every editor also carries `highlightSpecialChars()`, so a `\r` or a BOM inside a document line shows as a control mark, and `EditorState.lineSeparator.of('\n')`. The facet does not touch the documents built here; it affects only text inserted later (SHL-16's edits), so that inserted text keeps its `\r` too. In the unified layout the removed lines are a widget of plain text nodes, which `highlightSpecialChars` is not expected to mark (UNVERIFIED), so no control mark is required there for the removed side (section 4, D3a). Both layouts get the same extensions through one function. Source: unit lines 20 and 26; SHL-13 unit line 19 (a lossless editor sets the line-separator facet); SHL-16 unit line 21; DECISIONS line 2960 (the Opus review of revision 1, item 1). [UNVERIFIED A3] [DECISION]

6. **"No changes" is decided on the strings, not on the diff.** `identical = base() === proposed()`, a strict comparison with no trimming or normalising. When identical, the component shows the text "No changes", creates no editor and shows no toggle; the path stays. For any other pair the view must show at least one marked line. Source: unit lines 20 and 26. [DECISION]

7. **Front matter is plain text.** The view neither hides nor special-cases it, so a front-matter-only change is an ordinary changed line near the top. SHL-11 hides front matter only in reading panes; the diff view must not reuse that. Source: unit line 20; SHL-11 unit line 19. [DECISION]

8. **Conflict banner.** When `conflict()` is true, the component shows a banner (`role="status"`) with `conflictMessage()`, or the text "This change conflicts with the current file." when none is given. The diff is still shown. When `conflict()` is false no banner shows. Source: unit line 18. [DECISION]

9. **Header and label.** A header shows the `path` (wrapping anywhere, so a long path does not scroll a phone) and the toggle. The whole view is a `section` with `aria-label="Changes to <path>"`. Source: unit line 18 (the path is an input); SHL-19 unit lines 17 and 21 (labels and an accessibility check cover the diff). [DECISION]

10. **Designed for SHL-16.** One function builds the extensions of one side and takes the side's role; SHL-16 adds an `editable` input and an output without changing the inputs of decision 1. The SHL-12 spec uses only the inputs and the rendered DOM, so it keeps passing when SHL-16 extends the component. Source: unit line 21; SHL-16 unit lines 20 to 22 and 26. [FACT F20] [DECISION]

## 6. Open points

1. **Versions of the CodeMirror packages. Owner: the coordinator.** The plan names no version (decision 2). The code stage installs the newest (or `main`'s version of a package that `main` already lists) and records them. In this batch only SHL-12 changes `apps/web/package.json` and `package-lock.json` (section "Shared files"). `@codemirror/state` and `@codemirror/view` are later shared by SHL-13, SHL-16 and TRG-14 (TRG-14 adds `@codemirror/lang-yaml` and the lint extension, `units/TRG-14-yaml-editor-actions.md` line 15). 3. **Unchanged lines are not collapsed. Owner: the Navigator.** A long chapter shows every line. `@codemirror/merge` can collapse unchanged runs (`collapseUnchanged`). The unit does not ask for it, it adds behaviour and tests, and it can come later without changing the inputs.
4. **A carriage return shows on every line of a CRLF file. Owner: the Navigator.** Under decision 5, a file that is CRLF on both sides shows a control mark at every line end of the side-by-side layout and of the unified main editor. That is accurate but noisy. A refinement, to split both texts on `\r\n` instead of `\n` when both are uniformly CRLF, would hide the marks and still show a CRLF to LF change. Not done here.
5. **Line-separator handling in SHL-13 and SHL-16. Owner: those units' plans (not in this batch).** SHL-16 says it uses "the same lossless line-separator handling as SHL-13" (unit line 21). SHL-13 detects the file's separator and sets the facet to it (unit line 19); this unit builds the documents by splitting on `\n` only, so that `\r` stays a visible, byte-exact character, and sets the facet to `\n`. The two plans decide whether SHL-16 reuses SHL-13's handling or this one.
6. **Consumers' jsdom tests need the Range stub. Owner: the plans of TRG-14, PST-20, PST-21 and AGL-14.** Their component or route tests render the real `DiffView` in jsdom, which (if A5 holds) throws without `stubRangeRects()`. They import it from `shell/testing/dom-range.ts`. The alternative, a global setup file, would change `angular.json`, which this unit does not touch.
7. **Colour and contrast are checked by eye here. Owner: SHL-19.** The component sets the palette from Material variables and `light-dark()`, with underline and strike-through as non-colour cues (decision 11). jsdom does not compute CSS, so only M1 sees it; SHL-19's axe run is the check that counts. The same pass should check that a keyboard user can reach and scroll the diff text: the editors are `contenteditable="false"` (decision 4), and the page, not the editor, scrolls.
8. **The layout follows the device class, not the container width. Owner: the Navigator, if it matters for AGL-14.** A side-by-side diff inside a narrow container on a tablet (a chat card, for example) may be cramped. The toggle is the answer for now. A container-width rule would be a separate decision.
