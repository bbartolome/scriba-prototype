### 3.2 Choices made here (names, layout and shapes the unit leaves open)

- C-1 Files. Two pure modules with no library or Angular import: `story-view.ts` (the folder rule, the file choices, the path and relation setters, the relation options) and `layout.ts` (`arrangeOf`). Each has a spec. `canvas-page.ts` holds the page. `vflow-adapter.ts` is not changed: its `replaceNode`, `vflowEdgesOf` and `withPosition` cover the needs. `layout.ts` imports `nodeIdOfPort` from `./vflow-adapter` (a plain function; `vflow-adapter.ts` imports only a type from `ngx-vflow` and `signal` from Angular, which `layout.ts` does not use).
- C-2 Relation picker. A list of the story's edges, one row each (`data-story-edge="<edgeId>"`, with `from -> to` text and an `input` with `list="relation-options"` and `[value]` the edge's relation or `''`). A `<datalist id="relation-options">` holds `order`, `causality` and `containment`, and a line of text under the list gives their meanings (`order: from precedes to`, and so on, from `RELATION_OPTIONS`). The value applies on `change`, trimmed. An empty value removes the `relation` key. Any other text is kept as typed (free text). No selection is used, so the picker works without library selection.
- C-3 File picker. A list of the story's nodes (`data-story-node="<nodeId>"`, the label text, and a `<select data-path-picker>`). Its options: `""` labelled "No file", then the folder's file choices, then the node's current `path` when it is not among them (so a missing file stays selected and visible). Each option carries `[selected]="choice === (node.path ?? '')"` (A4). The value applies on `change`; an empty value removes the `path` key.
- C-4 Open file. A `<button type="button" data-open-file>` with the text "Open file" in the node's row, shown only when the node has a `path`. It calls `Router.navigate(['/projects', projectId, 'files'], {queryParams: {path}})`, with `projectId` from the page's `projectId` signal (C-16). Nothing happens when the id is `''`.
- C-5 Missing-file badge. In the canvas node template of a story node (inside the `@if (isStory())` branch), a `<span class="badge" data-badge="path-missing">File missing</span>` shows when the page's current issues hold a `path-missing` issue whose `nodeId` is that node. The issues come from the load (`get`) or from the latest validate answer. Its style rule uses the selector `[data-badge]`, not `.badge`, so it does not collide with GRR-13's status badges (also class `badge`).
- C-6 File list. `readFiles(graph, projectId)` returns `of([])` for a recipe or an empty project id; otherwise one GET of `projectFilesPath(projectId)` with `{path: '.', recursive: 'true'}` (the files page's and GRR-13's params), mapped to its `entries`, with `catchError` to `[]`. In `load()`, the `switchMap` after the graph read joins it with the tool reads: `forkJoin({ reads: this.readTools(detail.graph), files: this.readFiles(detail.graph, projectId) })`, and the `tap` sets a `files` signal. A file choice of a folder (`fileChoicesOf(entries, folder)`) is an entry with `kind` `file`, a path that starts with the folder and `/`, and no path segment that starts with `.`. Choices are sorted. The list is read once per load.
- C-7 Folder rule. `folderOfKind`: `scene` and `beat` give `drafts`; `entity` gives `entities` (`graph.ts` lines 33 to 38).
- C-8 Layout (`arrangeOf(file)`). Nodes are taken in file order; links with an unknown endpoint are ignored.
  - Story graph: the links are the edges whose `relation` is exactly `order` (from to to). The nodes form one sequence: Kahn's algorithm where, at each step, the ready node (no unplaced `order` predecessor) that comes first in file order is placed next; nodes left when no node is ready (on or after an `order` cycle) follow in file order. Each node gets its own column, its index in the sequence: `x = 40 + index * 320`, `y = 40`. This is the reading of open point 2: every node moves to its own column, so overlapping nodes are laid out left to right, `order` edges first, then insertion order.
  - Recipe: the links are the wires (their two node ids, from `nodeIdOfPort`). A node's layer is its topological depth (the longest path to it), from Kahn's algorithm with a first-in first-out queue that starts from the nodes with no incoming link, in file order. Nodes that Kahn never reaches form one extra column after the highest processed layer (column 0 when none is processed), in file order. Within a layer, nodes stack in file order: `x = 40 + layer * 320`, `y = 40 + rank * 200`.
  - Each node is copied with its `position` replaced, so the key order of the file is kept and nothing else changes. Edges are not touched.
- C-9 Arrange on the page. A `<button type="button" data-arrange>Arrange</button>` in the controls of both views.
