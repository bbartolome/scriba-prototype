### 1b. Decisions this plan makes

- **D1 Public API and entry file.** `ProvidersPanel`, selector `app-providers-panel`, standalone, no inputs and no outputs, is the exported component. It is exported from `features/providers/providers.routes.ts` (`export { ProvidersPanel } from './providers-panel';`), the only file another feature may import (S14). The entry file holds no `Routes` array. MPR-11 adds `providersRoutes` and the `/providers` entry in `app.routes.ts`. Reason: the route is MPR-11's (`units/MPR-11-providers-route-gate.md` line 17), and the panel must stay usable from `/setup` and `/settings` hosts (unit line 18). Open point 3.
- **D2 Components.** `ProvidersPanel` (list, app default, add buttons, hosts the form), `ProviderForm` (add and edit, one component, mode by whether it has a saved provider), `ModelPicker` and `KeyField` (presentational: inputs and outputs only), and `ProvidersStore` (component-scoped, provided in the panel's own `providers`, so each host gets fresh state). The panel injects only `API_CLIENT` from the Shell's entry (`apps/web/src/app/shell/index.ts` lines 3 to 5). It injects no `Router`, `ActivatedRoute`, `SSE_CLIENT` or `NoticesService`, and never navigates (criterion 4, D13).
- **D3 Contract access.** One file, `providers-contract.ts`, holds `loadProvidersContract()`: a single dynamic `import('@bbartolome/scriba-contracts/providers')`, typed with `Pick<typeof import(...), ...>` for the values the panel uses: the eight route constants (not `CONNECTION_TEST_ROUTE`, `EFFECTIVE_MODEL_ROUTE`, `PROJECT_MODEL_ROUTE`, `PROJECT_MODEL_CLEAR_ROUTE`), `providerListSchema`, `providerReadSchema`, `presetListSchema`, `appDefaultSchema`, `modelListSchema`, `PROVIDER_DEFAULTS` and `PROVIDER_ERROR_CODES`. Every other contract import is `import type`. The store awaits it before its first request. If the Navigator picks another route (open point 1), only this file, the store's call sites and one parity spec change.
- **D4 Controls.** Material `mat-form-field` with `matInput`, native `<select matNativeControl>` for every dropdown (the app default and the model list), Material buttons and `mat-icon`. No overlay component (`mat-select`, `mat-dialog`, `mat-menu`, `mat-autocomplete`). Reactive Forms (`@angular/forms`, already a dependency). Reason: native selects open the phone's own picker, and the tests drive plain DOM with no overlay container in jsdom (ASSUMED A2 to A3). `MatInput` accepts `select[matNativeControl]` (FACT, 7a).
- **D5 Load.** On creation the store loads three reads independently: `GET /api/providers`, `GET /api/providers/presets`, `GET /api/providers/app-default`. A failed read shows its own `role="alert"` message with a "Try again" button. The list and the default have no SSE events to follow (S11), so the store applies each command's response to its signals and does not re-read after a command, except after a 404 `PROVIDER_NOT_FOUND` (D10). A reload of the page is a new panel and a new load.
- **D6 Add flow.** "Add a provider" shows one button per preset from the presets response plus "Custom URL". A preset opens the form with the preset's `baseURL`, `model` empty, the five defaults from `PROVIDER_DEFAULTS`, and the preset's `hints` as notes. A key is required when `preset.keyRequired` (OpenAI, OpenRouter). Custom URL opens the form with an empty `baseURL`, the defaults, and a required Name field (sent as `label`, no `presetId`; it becomes the provider id and cannot change). Save sends `POST /api/providers` with every config field plus `presetId` or `label`, never a key. If a key was typed, a second request `POST /api/providers/key/set` `{providerId, key}` follows with the id from the create response. After both steps have finished, the form switches to edit mode for the new provider (it stays open) so the author can pick a model from its list; that switch is what requests the list (D9). If the create succeeds and the key call fails, the provider is kept in the list, the form switches to edit mode at once (the list is requested then), and the message says "The provider was saved, but its key was not saved. Paste the key again and save." (D12 copy). Retrying posts only the key.
- **D7 Edit flow.** Edit opens the same form prefilled from the saved provider. Save sends `POST /api/providers/:id/update` with the seven editable fields (`baseURL` and `model` as strings, the other five as numbers), then `POST /api/providers/key/set` only when a key was typed. The response replaces the row. The form stays open with a `role="status"` "Saved." line. "Close" discards unsaved edits. Only one form is open at a time.
- **D8 Key field.** `<input type="password" autocomplete="new-password" spellcheck="false">`. The typed text lives only in the form's control and is cleared after any successful key save and when the form closes. When `keySet` is true the field shows "Key set" and, when `keyHint` exists, the masked ending `••••` plus the hint (no hint: "Key set" alone), with "Replace" (shows the empty input; a second click cancels) and "Remove" (posts `POST /api/providers/key/clear` `{providerId}` at once, then shows "No key set"). When `keySet` is false the input is shown directly. `keyRef` is never displayed. The key goes into exactly one request body: `key/set`.
- **D9 Model picker.** One component with five states. `unsaved` (add mode): free text and "Save the provider to load its model list. Until then, type the model name." `loading`: a disabled select. `ready`: a `<select>` whose first option is "Automatic (the provider's first listed model)" with value empty, then the server's sorted ids; a stored model not in the list is kept as an extra option "<id> (not listed)". `empty` (a 200 `{models: []}`): free text and "The provider listed no models. Type the model name instead." `failed` (any error from the list: an `ApiError`, an `ApiSchemaError`, or a plain `Error` such as the one the fake client throws for a route with no canned response, `apps/web/src/app/shell/testing/test-doubles.ts` lines 90 to 93): free text, "The model list could not be loaded. Type the model name instead.", the error's `message` (a non-`Error` value gives no message line), and a "Try again" button. Each request is one `GET /api/providers/<id>/models`. The list is requested (a) when the form enters edit mode for a saved provider: opening Edit, or the switch after an add (D6); (b) once after each completed save sequence in edit mode (the update and the optional key call) and once after Remove (D8); (c) on Try again. It is never requested in add mode. The form holds the state and passes it down, so MPR-10 can read it (section 5).
- **D10 Delete flow.** Each row has "Delete". It turns into an inline "Delete <id>? Its key is deleted too." with "Confirm delete" and "Cancel" (no dialog, D4). Confirm posts `POST /api/providers/:id/delete`; the response schema accepts a null or absent body (a 204 gives `null` in both Angular backends, 7a) and the row is removed. A 409 with code `PROVIDER_DEFAULT_IN_USE` shows the exact text "Pick another default first." in a `role="alert"` and changes nothing. The button is never disabled for the default, so the server stays the authority. A 404 `PROVIDER_NOT_FOUND` shows "That provider no longer exists. The list was reloaded." and re-reads the list. Any other `ApiError` shows its message.
- **D11 App default.** A native select "App default" lists every provider as `<id>` or `<id> · <model>`, with the current default selected, and a "Default" badge on its row. When `appDefault` is null (the contract allows it: `packages/contracts/src/providers/model.ts` lines 32 to 35, `examples.ts` line 101 `appDefaultUnset`; an absent section reads as null, `providers.registry.ts` `current()`), or names a provider that is not in the list, the select shows an extra first option "No default" (empty value, `disabled`, selected) and no row has the badge; the option is not rendered once a default exists, and choosing it never posts. Changing the selection posts `POST /api/providers/app-default` with `{providerId, model: ''}` and takes the `{appDefault}` reply. The model is empty so the default follows the provider's own model (S10). If the stored default carries a model, the select still shows its provider and the model is left as stored until the author picks another provider. The default cannot be cleared (`plans/MPR-02.md` line 154, as `plans/MPR-06.md` D9 says). Open point 2.
- **D12 Copy and hints.** All visible strings of this plan sit in `providers-copy.ts`: the delete refusal, the three model-list explanations, the key texts, the key-save failure, the not-found text, the `contextSize` hint ("The model's context length in tokens. Scriba uses it to budget a prompt; it is not sent to the provider.") and the `timeout` hint ("Milliseconds. 0 means 300000 (5 minutes), not no limit. A wait with no data also ends after 300000 even if you set more."). The Ollama context-length and pull-a-model hints belong to MPR-10 and are not written here. The tests assert the literal strings.
- **D13 Validation mirrors the contract only.** `baseURL` parses with `new URL()` (the contract's `z.url()` accepts any scheme, `plans/MPR-01.md` open point 6); `temperature` is a finite number with no range (open point 8 of the same plan, unresolved and unchanged); `contextSize` and `maxTokens` are integers of at least 1; `timeout` and `retries` are integers of at least 0; the custom Name has an ASCII letter or digit. An invalid form disables Save and shows an inline message; nothing is sent. A server 400 shows its message.
- **D14 Layout.** CSS only: one column below about 40rem, wrapping rows, `min-width: 0`, `flex-wrap`; no use of `DeviceClassService`. Component styles stay far below the 4 kB per-component warning (`apps/web/angular.json` lines 39 to 41). Sections use `h2`; the host page owns the `h1`. jsdom has no layout, so the phone width is not testable here (open point 9).
- **D15 Tests.** Two spec files and one helper (section 2), described in section 4. The helper builds canned responses with the contract's read view and the 4 and 5 character hint rule; the specs re-register canned responses between steps because the fake is canned per path (7a).
- **D16 No other edits.** No change to the contract, the API, the Shell, `app.routes.ts`, `angular.json`, `package.json` or the lockfile. No unit file is edited by this plan; the criteria are ticked in the code stage's closing commit, as the earlier units did.

## 4. Acceptance criteria and tests

All tests run with `npm test -w @bbartolome/scriba-web -- --include <spec>` and are written first (step 3). Every test renders the panel through a host component and `createShellTestDoubles()` (S15); it never reaches the network. "Reload" means `fixture.destroy()` and a new `TestBed.createComponent`, which creates a new store and a new load. The dynamic contract import is not tracked by Angular's stability, so tests wait with `vi.waitFor` on a DOM condition (as `apps/web/src/app/shell/landing.spec.ts` does). The fake throws a plain `Error` for any route with no canned response (`test-doubles.ts` lines 90 to 93), and D9 turns that into the `failed` state, so a test that forgets a model list would silently see free text. Every test that opens a saved provider's form therefore registers that provider's `GET /api/providers/<id>/models` (through `installProvidersServer`, or `serveModels` for a provider the test creates), and the tests that assert the model-list requests (C1, C2) state their number and position.
