20. **Handshake response.** The handshake handler takes `@Res()` without passthrough, typed structurally (`status`, `setHeader`, `end`), because apps/api has no `@types/express`. It writes either the 303 (`Location`, `Set-Cookie`, `Referrer-Policy`) or the 401 HTML page (`Content-Type: text/html; charset=utf-8`, `Referrer-Policy`) itself. It uses no `@Redirect`. A `@Redirect` handler always redirects: a string URL is enough (`router/router-execution-context.js` line 253, `redirectResponse && isString(redirectResponse.url)`), and `@Redirect()` defaults the URL to `''`. So it cannot produce the 401 page. A handler with `@Res()` owns its response, and Nest does not reply to it (`isResponseHandled`, line 389 onward). Identity returns its body, or throws `ModuleError` for 401. Sign-out uses `@HttpCode(204)` and `@Res({passthrough: true})`, only to set `Set-Cookie`. The status flow, checked in `@nestjs/core` 12.4.2 (section 7a): the status is set before the handler runs (`router/router-execution-context.js` line 71, `setStatus`); `createHandleResponseFn` is called with three arguments (line 108), so `httpStatusCode` is undefined; and `apply` (line 308) calls `reply` with no status. The earlier reason, that `reply()` overwrites an earlier status, is withdrawn. Source: DECISIONS 2026-11-13, "SAU-03 — Opus plan review of revision 1", item 1, and "SAU-03 — Opus plan review of revision 2", item 4. FACT.
