## 1. Decisions this plan follows

### 1a. Settled by the unit, the module, earlier plans, DECISIONS and the code on main

- **D1. Which results carry a diff.** `tool-call-result` for `write_file`, `edit_file` and file-producing narrative outputs carries `diffPreview`. Source: unit line 15. A narrative output that writes no file gets none: `check` and `claims` (AGL-13 plan P13, line 38; `plans/DECISIONS.md` lines 5365 to 5369). Until AGL-13 routes narrative outputs, they have no file to diff (module line 80; `plans/DECISIONS.md` lines 5118 to 5122, AGL-09 OP3).
- **D2. Shape.** `diffPreview` is `{path, base, proposed}`, all strings. `base` is the empty string for a file that does not exist yet (`plans/AGL-01.md` line 42, D6; `packages/contracts/src/agent-loop/cards.ts` lines 9 to 13, `base: z.string()`). The contract does not change.
- **D3. What base and proposed are.** For a write or an edit, `base` is the path's captured base and `proposed` is the overlay text after the call. The captured base is the text at the first touch, so a second edit's diff is against the same base the pending change will use (unit `units/AGL-12-write-overlay.md` lines 18 and 19; `plans/AGL-12.md` P3 line 43 and section 5 AGL-14 row, line 177).
- **D4. Review link.** At `run-ended`, a link `/projects/<projectId>/review?run=<runId>` appears when pending change IDs exist (unit line 16; `units/AGL-07-chat-panel-ui.md` line 23). AGL-07 built it already: `apps/web/src/app/features/agent-loop/chat-page.ts` lines 370 to 372 (template) and 484 to 487 (`reviewHref`), tested by X4 (`chat-page.spec.ts` lines 469 to 486). AGL-14 keeps the href and adds the refresh of D5 (`plans/AGL-07.md` check A2 (b), line 130).
- **D5. Refresh on queue events.** Unit line 16 says "refresh it on the Project store's queue-update events". The queue events are `pending-created`, `pending-updated` and `pending-resolved`, each with `{projectId, pendingChange}` (`packages/contracts/src/project-store/events.ts` lines 6 to 10 and 24 to 40). A resolved change has status `accepted` or `rejected` (`apps/api/src/modules/project-store/pending.service.ts` lines 196 and 302 to 305; `packages/contracts/src/project-store/pending.ts` line 34). The reading of "refresh" is P9 and open point 3.

### 1b. Decisions this plan makes (simplest option)

- **P1. Lookup at the emit.** `AgentRun.runCall` builds the `tool-call-result` event with `...this.diffPreviewOf(callId, outcome)` inside the emit object (`apps/api/src/modules/agent-loop/agent-run.ts` lines 305 to 311). `diffPreviewOf` is a new private method placed after `provenanceOf` (after line 273). It reads `this.tools.overlay.entriesInOrder()` (`apps/api/src/modules/agent-loop/tools/write-overlay.ts` lines 52 to 54) and takes the entry whose `callId` is the call's. The lookup runs where the event is built, so any overlay put made earlier in `runCall` is already in the overlay. `WriteOverlay` does not change.
- **P2. No entry, no diff.** `diffPreviewOf` returns nothing (no `diffPreview` key) when the outcome is not a `result`, when no overlay entry has the call's `callId`, or when `overlay.baseOf(path)` is `undefined`. An `undefined` base means the base was not captured, so the diff is not guessed (it would show a file as new). A `null` base (a file that did not exist at its first touch) becomes `''` (D2).
- **P3. The transcript keeps no diff.** `diffPreview` is not added to `extras` (`agent-run.ts` lines 293 to 298), so the transcript `tool-result` line does not get it (lines 330 to 338). Reason: `TranscriptWriter.append` cuts every string to 8192 characters (`apps/api/src/modules/agent-loop/transcript-writer.ts` lines 80 to 83; `transcript-entries.ts` line 13). A longer draft would be stored with a cut `proposed`, and a reloaded card would show a wrong diff. The transcript payload schema allows the field (`transcript-entries.ts` line 65), but the writer cannot keep it whole. Open point 2.
- **P4. The live run state keeps it.** `AgentRun.apply` copies `data.diffPreview` into the card on `tool-call-result`, beside `sourcesUsed` and `provenance` (`agent-run.ts` lines 483 to 492). Reason: the page replaces a turn's cards with the run state's cards on each refresh (`apps/web/src/app/features/agent-loop/chat-state.ts` line 346, `applyRunState`), and it asks for a refresh on every `tool-call-started` (`plans/AGL-07.md` D12). Without P4 the diff would vanish at the next tool call.
- **P5. Web projection.** `chat-page.ts` adds `DiffView` to its imports (the `../../shell` import block, lines 23 to 31; the array at line 135). `CardEntry` (lines 82 to 89) gets a `diff` field taken from `card.diffPreview`. The card loop (lines 351 to 352) projects `<app-diff-view>` with `path`, `base` and `proposed` into `<app-tool-call-card>` only when `diff` is set. The grounding chip and the check button stay after the card element (lines 353 to 366), where AGL-18 puts them (`plans/AGL-18.md` D3, line 39, and D8, line 44).
- **P6. Projection cost accepted.** Angular builds projected content even when the host does not render its `ng-content` (SHL-12 A12, `plans/SHL-12.md` line 315, assumed). The projected nodes are attached to the page only while the card is expanded (`tool-call-card.ts` lines 179 and 229). SHL-10 left the cost to AGL-14 (`plans/SHL-10.md` open point 4, line 240). Settled: accepted, with no Shell change. The cost is one diff view per write card of a turn.
- **P7. Guards tightened.** `agent-contract.ts` checks `diffPreview` as `{path, base, proposed}` strings, through one new `isDiffPreview`, in `isCard` (line 199) and in the `tool-call-result` case of `isChatEvent` (line 393). This is the tightening that AGL-07 check A2 (c) asks for (`plans/AGL-07.md` line 130).
- **P8. Queue guard.** A new `isQueueEvent` in `agent-contract.ts` accepts a `project-store` envelope of the three queue types, with `data.projectId` a string, `data.pendingChange.id` a string, and `data.pendingChange.status` one of `pending`, `accepted`, `rejected`. Only the fields the page reads are checked, as AGL-07 D3 does for its guards.
- **P9. Queue state in the page.** The page keeps a signal `queue`: a map from change ID to the last status the queue events gave it, updated by each queue event of the active project. `resetView()` (`chat-page.ts` line 710) clears it. A turn's link shows when the turn has pending change IDs and at least one of them is not known to be `accepted` or `rejected`; an ID with no event counts as open. The page learns a run's IDs from its events: the flush proposes the changes before `run-ended` (`agent-run.ts` lines 360 and 370), and each proposal publishes `pending-created` (`pending.service.ts` lines 463 to 467).
- **P10. No Range stub.** The DiffView spec on main renders without a jsdom Range stub, because `apps/web/src/app/shell/testing/dom-range.ts` was deleted in `bff0cebee` ("the jsdom render does not need" it). The AGL-14 tests need no stub, and SHL-12 open point 6 (`plans/SHL-12.md` line 266) does not apply.
- **P11. Files and tests.** One new API test file, `apps/api/test/agent-loop-diff-preview.test.ts`, with its own helpers (the AGL-12 P15 precedent). The web tests go at the end of `chat-page.spec.ts`, with a `pushQueue` helper, because `push` (lines 148 to 156) hard-codes the module `agent-loop`. The two parity tests go in `agent-contract.spec.ts`. No contract, Shell or transcript file changes.
