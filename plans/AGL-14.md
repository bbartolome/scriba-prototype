### 1a. Settled by the unit, the module, earlier plans, DECISIONS and the code on main

- **D1. Which results carry a diff.** `tool-call-result` for `write_file`, `edit_file` and file-producing narrative outputs carries `diffPreview`. Source: unit line 15. The captured base is the text at the first touch, so a second edit's diff is against the same base the pending change will use (unit `units/AGL-12-write-overlay.md` lines 18 and 19; `plans/AGL-12.md` P3 line 43 and section 5 AGL-14 row, line 177).

- **D5. Refresh on queue events.** Unit line 16 says "refresh it on the Project store's queue-update events". The queue events are `pending-created`, `pending-updated` and `pending-resolved`, each with `{projectId, pendingChange}` (`packages/contracts/src/project-store/events.ts` lines 6 to 10 and 24 to 40). A resolved change has status `accepted` or `rejected` (`apps/api/src/modules/project-store/pending.service.ts` lines 196 and 302 to 305; `packages/contracts/src/project-store/pending.ts` line 34). ### 1b. Decisions this plan makes (simplest option)

- **P1. Lookup after the extras.** In `AgentRun.runCall`, one new line right after the `extras` block (after `apps/api/src/modules/agent-loop/agent-run.ts` line 298, before `if (family !== undefined)` at line 299): `const preview = outcome.kind === 'result' ? this.diffPreviewOf(callId) : {};`. `preview` is `{}` or `{diffPreview}`. It is spread into the `tool-call-result` emit object (`...preview` after `...extras`, line 310) and into the transcript `tool-result` payload (`...preview` after `...extras`, line 337; P3). The `extras` block itself (lines 293 to 298) is not edited, so AGL-13's put, inserted between lines 292 and 293, is not adjacent to any AGL-14 edit (section 5). `diffPreviewOf` is a new private method placed after `provenanceOf` (after line 273). It reads `this.tools.overlay.entriesInOrder()` (`apps/api/src/modules/agent-loop/tools/write-overlay.ts` lines 52 to 54) and takes the entry whose `callId` is the call's. `put` replaces a path's entry with the latest call's (`write-overlay.ts` lines 40 to 49), and the lookup runs right after that call's dispatch, so a second write to the same path finds the second call's entry. Any overlay put made earlier in `runCall` (AGL-13 P3) is already in the overlay. `WriteOverlay` does not change.
- **P2. No entry, no diff.** `diffPreviewOf` returns `{}` (no `diffPreview` key) when no overlay entry has the call's `callId`, or when `overlay.baseOf(path)` is `undefined`. An `undefined` base means the base was not captured, so the diff is not guessed (it would show a file as new). A `null` base (a file that did not exist at its first touch) becomes `''` (D2).
- **P3. The transcript mirrors the event (open point 2, settled).** The transcript `tool-result` line gets the same `diffPreview` as the event (`...preview`, P1; `agent-run.ts` lines 330 to 338). Source: AGL-04 D2, settled and done: each transcript payload "mirrors the stream event of the same name" (`plans/AGL-04.md` line 42), and the `tool-result` schema already has `diffPreview: diffPreviewSchema.optional()` "copied from the event" (`transcript-entries.ts` line 65; `plans/AGL-04.md` lines 50 and 190). The writer cuts each string to 8,192 characters with the D8 marker (`transcript-writer.ts` lines 80 to 83; `transcript-entries.ts` line 13; `plans/AGL-04.md` line 71: "only the transcript copy is truncated; the stream and the live state are not"). So a long `base` or `proposed` is stored cut, as a long `output` or `modelText` is today. No transcript file, limit or schema changes. The reader is not changed: it builds history cards with `summary` and `output` only (`transcript-reader.ts` lines 166 to 181; AGL-04 D13), as it already does for `sourcesUsed` and `provenance`. So a card rebuilt from a transcript (an older turn of the history, or the run state after an API restart, `agent-runs.service.ts` lines 146 to 148) shows no diff. The latest run's state is served from memory, ended or not (`agent-runs.service.ts` lines 143 to 145), so it keeps the diff (P4). The unit asks for the diff on `tool-call-result` (unit line 15), not on history cards.
- **P4. The live run state keeps it.** `AgentRun.apply` copies `data.diffPreview` into the card on `tool-call-result`, beside `sourcesUsed` and `provenance` (`agent-run.ts` lines 483 to 492). Reason: the page replaces a turn's cards with the run state's cards on each refresh (`apps/web/src/app/features/agent-loop/chat-state.ts` line 346, `applyRunState`), and it asks for a refresh on every `tool-call-started` (`plans/AGL-07.md` D12). Without P4 the diff would vanish at the next tool call.
- **P5. Web projection.** `chat-page.ts` adds `DiffView` to its imports (the `../../shell` import block, lines 23 to 31; the array at line 135). `CardEntry` (lines 82 to 89) gets a `diff` field taken from `card.diffPreview`. The card loop (lines 351 to 352) projects `<app-diff-view>` with `path`, `base` and `proposed` into `<app-tool-call-card>` only when `diff` is set. The grounding chip and the check button stay after the card element (lines 353 to 366), where AGL-18 puts them (`plans/AGL-18.md` D3, line 39, and D8, line 44).

The projected nodes are attached to the page only while the card is expanded (`tool-call-card.ts` lines 179 and 229). SHL-10 left the cost to AGL-14 (`plans/SHL-10.md` open point 4, line 240).
