## 1. Decisions this plan follows

### 1a. From the unit, the module, the README and the CEX-04 unit

- **U1 Flag.** `--to=docx --reference-doc=<template>`. The template is the built-in reference DOCX unless the project sets an override (CEX-14). Source: unit line 15; CEX-14 unit line 16 (`docxReferenceDoc`).
- **U2 Built-in reference.** A reference DOCX ships in the image with the module. It encodes Times New Roman 12 pt, double spacing, 1-inch margins, a running header of surname / short title / page number, chapter headings on a new page, a first-line indent, and a title page with the contact block and the rounded word count. Source: unit line 16.
- **U3 Criteria.** Three checkboxes, all structural (unzipped): unit lines 19 to 21. Every criterion needs one test (section 5).
- **U4 Matter and order.** Chapters in effective order; front and back matter placed by `part`; the title page and the dedication from export settings; no new folders. Source: module line 51 (settled decisions) and line 7 (DOCX is its own unit over one shared runner).
- **U5 Title-page metadata.** "Title page from metadata; standard manuscript layout also needs the contact block and an approximate body word count rounded to the nearest 1,000 (passed as metadata for the reference DOCX)." Source: `units/CEX-04-assembled-markdown.md` line 28. The rounding is already in code (F14).
- **U6 Pandoc invocation.** Shared by CEX-11 to CEX-13: an argument array with no shell, a temp working folder, `--resource-path` set to the project root, a wall-clock timeout (120 s) that gives `COMPILE_PANDOC_TIMEOUT`, an output cap, never `--filter` or Lua filters from project content, one export per project at a time, and the stderr tail on `COMPILE_PANDOC_FAILED`. Source: `units/CEX-10-pandoc-runner-md-export.md` line 18.
- **U7 Storage and download.** Output under `stateDir(projectId, 'compile-export')/exports/`, written with plain `fs`; the latest file per format is kept; `fileName` is `<title-slug>-<yyyymmdd-hhmm>.<ext>` in UTC. The GET streams with `Content-Disposition: attachment; filename=<fileName>` and changes nothing. Source: CEX-10 unit lines 16 and 17; module lines 41 and 53; `units/README.md` line 132 (a GET never mutates).
- **U8 Testing.** External behaviour only (HTTP, files on disk), never Pandoc's argument list. The primary seam is the module in `create-test-app`, with Setup & auth's guard. DOCX is checked structurally (XML, styles), never by byte goldens. Pandoc tests use real Pandoc 3.13, skip locally with a message when it is missing, and a CI flag turns the skip into a failure. Source: module lines 58 to 60; `units/README.md` line 139.
- **U9 Markdown unchanged.** The md format is the assembled Markdown, with no Pandoc call (CEX-10 unit line 19). This plan does not change the assembled Markdown, so the md goldens of CEX-04 and CEX-10 keep passing.

### 1c. Choices of this plan

- **D1 Asset location and path.** The reference lives at `apps/api/assets/compile-export/reference.docx`. `apps/api/src/modules/compile-export/builtin-assets.ts` exports `BUILTIN_REFERENCE_DOCX = resolve(__dirname, '..', '..', '..', 'assets', 'compile-export', 'reference.docx')`. The same relative path resolves from `src/modules/compile-export` (tests and dev) and from `dist/modules/compile-export` (image), because both are three levels below `apps/api`. No `SCRIBA_*` name is added: the list is fixed (F16), and CEX-10 D9 gave the same reason.
- **D2 Image.** One line in the build stage of the Dockerfile, after line 43: `cp -a apps/api/assets /out/app/apps/api/`. The runtime copy (line 57) then places the folder at `/opt/scriba/app/apps/api/assets`. `.dockerignore` excludes nothing under `apps/api/assets` (F15). Whichever of CEX-11, CEX-12 or CEX-13 merges first adds this line; the others find it there (section 6).
- **D3 Runner change.** `PANDOC_TARGET_ARGS.docx` stays `['--to=docx']`. A new table `PANDOC_FILE_FLAGS: Partial<Record<PandocFormat, string>>` holds `{docx: '--reference-doc'}`. `runPandoc` takes a sixth optional parameter `file?: string`. When the format has a flag and `file` is set, it appends `<flag>=<file>` after the target arguments. Reason: the reference is per run (the built-in file, or the CEX-14 override), so a constant table entry cannot hold it. Leaving the three target entries unchanged, and adding one table line per format, lets CEX-12 (`--css`) and CEX-13 (`--template`) add their lines without touching the docx line, so the three units merge in either order. The comment at `pandoc-runner.ts` lines 12 and 13 is updated to say so.
- **D4 Title block placement.** A DOCX-only block, rendered from the same `MetadataValues` the YAML uses, placed directly after the YAML metadata block and before the front matter. It is placed there so that the first block of the input stays the CEX-04 metadata block and the md output is unchanged; Pandoc also reads a YAML block that is not at the start (F25 PR5), which D5 uses. This is option A of O1, settled in section 7.
- **D5 Title block text.** Each non-empty line of `contact` is one paragraph in the style `Contact Block`. Lines are separated by blank lines, because a single newline is a soft break in Markdown. The block is omitted when `contact` is unset, as `renderMetadata` omits unset keys. The word count is one paragraph in the style `Word Count`, reading `About <n> words`, where `<n>` is `wordcount.toLocaleString('en-US')` (F27 gives `3,000`). A raw OpenXML page break follows the block, so the front matter starts on a new page (A3). After the page break, a second YAML block holds the running-header values of D14: `surname` (omitted when `author` is unset) and `shorttitle`, each written with the `scalar` quoting of `renderMetadata`.
- **D14 Running header (O3).** The reference's header part holds three fields, separated by ` / `: `DOCPROPERTY surname`, `DOCPROPERTY shorttitle` and `PAGE`. Pandoc writes every metadata key that is not a core property into `docProps/custom.xml`, including keys of a later YAML block (F25 PR5), so the fields read the values of D5. `surname` is the last whitespace-separated word of `author`; `shorttitle` is `title` up to its first `:`, trimmed (the whole title when it has no colon). No export setting and no contract key is added. The reference's `word/settings.xml` holds `<w:updateFields w:val="true"/>`, which Pandoc keeps (F25 PR6), so Word refreshes the fields when the file opens. These are choices of this plan: a name, a derivation, and a file layout.
- **D6 Optional arguments.** `renderDocument(metadata, parts, titleBlock?)` takes an optional third argument, placed after the metadata block. `AssemblyService.assemble(now, titlePage = false)` takes an optional second argument. The default leaves the md, EPUB and PDF output unchanged.
- **D7 Export call.** `ExportService.export` calls `assemble(now, format === 'docx')`. In the Pandoc branch it passes `this.templateOf(format)` to `runPandoc`. `templateOf(format)` returns `BUILTIN_REFERENCE_DOCX` for docx and `undefined` for epub and pdf until CEX-12 and CEX-13 add their case; CEX-14 changes only that method (section 6a).
- **D8 Reference DOCX build.** A committed binary, built once from Pandoc 3.13's default reference (`pandoc --print-default-data-file reference.docx`) with the edits of procedure step 2. No generator script is added. The commit message names the source. The reviewer checks the XML parts with `unzip`, and E1 checks the settings.
- **D9 Zip reader.** A test helper in the new kit reads the zip with `node:zlib`: the end-of-central-directory record, the central directory, and each local header. Method 8 uses `inflateRawSync`; method 0 is stored. No zip library is in `node_modules`, and none is in `apps/api/package.json` (F17), so no dependency is added.
- **D10 XML reading.** The DOCX XML is read with regular expressions over `<w:p>`, `<w:pStyle w:val>` and `<w:t>`, with the entities `&amp;`, `&lt;`, `&gt;`, `&quot;` and `&apos;` decoded. `apps/api` has no XML parser dependency (F17).
- **D11 Binary GET.** The kit's `send` returns the body as text (F20: `Reply.body` is a string), which would corrupt DOCX bytes. The new helper makes the same loopback request with `node:http`, sends the same Host and cookie as `downloadOf`, and collects Buffers.
- **D12 Fixtures and clock.** The fixtures follow the C1 shape of `compile-export-assembly.test.ts` (F21): `export:` keys, `order:` entries with `part`, and word counts from repeated `word` tokens (P4). The clock is `vi.useFakeTimers({toFake: ['Date']})` with `vi.setSystemTime(new Date('2026-11-19T12:00:00Z'))`, both before the app boots, as CEX-10 D27 does. So `fileName` is `book-20261119-1200.docx`. Every DOCX fixture sets `bibliography: off`, because the kit's default pack is `nonfiction`, whose default turns on a bibliography, and `renderBibliography` keeps its heading even with no entry (`assembly.ts` lines 63 to 71).
- **D13 Files.** The tests are in `apps/api/test/compile-export-docx.test.ts`, and the helpers in `apps/api/test/compile-export-docx.kit.ts`. E3 is the only test that does not use Pandoc.
