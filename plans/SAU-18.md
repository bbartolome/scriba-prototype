## 3. Decisions the plan obeys

- **D1 Tailnet entry** (unit line 18; C5, C6). A Host is a tailnet Host when status has `available: true`, `backendState` `Running`, and a `dnsName`, and the Host equals `dnsName` or `dnsName:443` exactly. Every other state gives loopback entries only. This plan reads "logged out" as any state other than `Running`. An unknown Host triggers at most one `refresh()` (`tailscale-status.service.ts:91-96`, the SAU-17 rate limit) before rejection. **Refresh rule (revision 2, settles the planner's open point 6; option a).** For a Host that is not a static loopback or dev entry, `admit` first reads `status()` (2 s cache), and only when that gives no match calls `refresh()` once. This agrees with the unit's "at most one rate-limited refresh": a request causes at most one socket read (when `status()` reads, `refresh()` then finds a read younger than 1 s and reads nothing), and unknown Hosts cause at most one read per 1000 ms in total. It uses SAU-17's `refresh()` as it was built for SAU-18, and keeps no second copy of the tailnet name in the policy, so a logout is seen within the 2 s cache. Option (b) (a cached tailnet name in the policy) was not chosen: it adds state and a second path for logout.
- **D2 Peer rule** (unit line 19; module line 47). The header is trusted only when the Host is a tailnet Host and `req.socket.remoteAddress` is exactly `127.0.0.1` or `::1`. The dedicated listener is not built (C18). **An untrusted header is treated as absent (revision 2, settles the planner's open point 5).** The unit settles the answer: the header is the only credential on the tailnet Host (unit line 19), and a cookie is not one (unit line 21), so a request with an untrusted header is "a tailnet request without the header" (unit line 20) and gets 403 `AUTH_TAILNET_IDENTITY_MISSING`. No new error code and no contract change. Criterion 2 says only "isn't trusted"; test 2 asserts this code.
- **D3 Missing identity** (unit line 20; C7). A tailnet Host with no trusted header gets 403 `AUTH_TAILNET_IDENTITY_MISSING`. The message is "Sign this device in to Tailscale as a user (a tagged device has no user identity)." It matches the wording of SAU-06's explanation (`plans/SAU-06.md:94`). **The status stays 403 (revision 2, settles the planner's open point 4).** Unit line 20 and `errors.ts:19` say 403, and SAU-06 (done) keys its explanations on the code, not the status (C26). The `/setup` page shows the explanation through its identity read, which gets this 403 (D8). No Shell file changes; whether the Shell should also send 403 tailnet codes from other pages to `/setup` is SAU-06's own open point 2 (`plans/SAU-06.md:266`), not a change of this unit.
- **D4 A cookie is not a credential on a tailnet Host** (unit line 21; module line 60; SAU-03 decision 10, `plans/SAU-03.md:22`). When the admitted entry is a tailnet entry, the guard does not read the cookie. On every other admitted Host (loopback and dev entries) the cookie rule of SAU-04 is unchanged. This closes the gap in C1 for the tailnet Host. (Revision 2 narrowed the draft's "only on a loopback Host" to the unit's text, so SAU-04's behaviour for dev Hosts is not changed.)
- **D5 Origin on tailnet mutations** (unit line 22). The expected origin is `https://<dnsName>`, compared exactly, so the scheme is compared. A `:443` Host gets the same origin. A refusal is 403 `AUTH_ORIGIN_REJECTED`.
- **D6 Identity** (unit line 23; C7). The guard attaches `{via: 'tailnet', login}`. The identity route returns it, and `RequestIdentity` reads it.
- **D7 Guarded controllers use the guard's identity** (SAU-05 hand-off, `plans/DECISIONS.md:1524-1527`; C10). `requireSession` and the identity route accept "the guard attached an identity", not "a cookie verifies". This closes the hand-off, and the status and Continue routes accept tailnet callers.
- **D8 "A tailnet request"** (unit line 20; criterion 4). **Settled by the criterion text (revision 2, the planner's open point 2).** Criterion 4 says "a tailnet request", with no exception for public routes, so every request on a tailnet Host that reaches the guard, without a trusted identity, gets 403 `AUTH_TAILNET_IDENTITY_MISSING`: the guarded routes and the public handshake and identity routes alike. This agrees with unit line 21: the handshake on the tailnet Host still redirects without a cookie when the header is present (the handshake code is unchanged, C8). It is also what SAU-06 needs: the identity read on the tailnet answers the tailnet code, not 401 (C26). Two paths are outside it, as SAU-04 (done) fixed them: `/healthz`, which the Host check and the guard exempt by path (SAU-04 criterion 2); and the static Angular bundle, which never reaches a guard (C25) and must stay served, so that `/setup` loads on the tailnet and can show the explanation.
- **D9 Module invariants** (module lines 3, 44, 47; `plans/DECISIONS.md:1529`). Default-deny guard, no CORS, `frame-ancestors 'none'` (module line 3). The Host check before the body parser (the Navigator's SAU-04 decision, `plans/DECISIONS.md:1529`). Identity is for display and logs only: the login is attached and never used to partition data (module line 44). The peer-address check (module line 47).
- **D10 Test seam** (module lines 65-69; SAU-04 decision 18). External behaviour only, through `createTestApp`, which boots the composed app. The fake LocalAPI socket is the only Tailscale double.
- **D11 One policy instance** (C3). The hook takes the policy from the Nest container, so the hook and the guard share it.
- **D12 Early BootError kept** (SAU-04 decision 7). `checkDevOrigins(env.SCRIBA_DEV_ORIGINS)` runs before `NestFactory.create`, so a bad value still exits before any Nest code.
- **D13 Simplest choices, recorded.** Names: `admit`, `HostEntry`, `TailnetSource`, `checkDevOrigins`, `listenHost`. No new production file. One new test file. Test names begin with `criterion N:`. The guard's `canActivate` becomes `async`.
- **D14 Peer match is exact** (unit line 19). The IPv4-mapped form `::ffff:127.0.0.1` is not added, because C13 shows the listeners bind IPv4 only. If a later bind uses `::`, the rule must accept the mapped form too. Noted, not built.
- **D15 Order of checks.** The identity step comes before the Origin check, so a mutation is first checked for identity and then for Origin.
- **D16 Test seam for a non-loopback peer (revision 2, settles the planner's open point 1; option a).** Test 2 boots the app with `listenHost: '0.0.0.0'` (row 8) and sends from the machine's first non-internal IPv4 interface address that is not in `100.64.0.0/10` (A6, C17), to `http://<address>:<port>` with `send` (C27). Reason: it is the simplest seam that makes the peer a real non-loopback address, through the composed app (D10). Option (b), `127.0.0.2`, is rejected: that address is a loopback address (`127.0.0.0/8`), so it would not test "a non-loopback peer", and macOS needs an alias for it. Option (c), a skip, would leave the criterion unrun. If no such address exists, the test fails with a message naming the cause; it does not skip (step 14).

The logic, in prose and in outline:

- `admit(host)`: `undefined` for a missing Host. A static loopback or dev entry, if one matches. Otherwise `tailnetEntryFor(await source.status(), host) ?? tailnetEntryFor(await source.refresh(), host)`. `tailnetEntryFor` applies D1 and returns `{origin: 'https://<dnsName>', tailnet: true}`.
- Hook: set the CSP header. For every path except `/healthz`, if `await policy.admit(host)` is `undefined`, answer 403 `AUTH_HOST_REJECTED` as today. Otherwise call `next()`.
- Guard, `canActivate` (async): if the path is `/healthz`, return `true` (as today: public, GET only; no status read). Otherwise `entry = await policy.admit(host)`. `tailnet = entry?.tailnet === true`. If `tailnet`, the identity is `{via: 'tailnet', login}` when the header is a non-empty string and the peer is `127.0.0.1` or `::1`; the cookie is not read (D4). Otherwise the identity is `{via: 'loopback'}` when the cookie verifies (SAU-04's rule, unchanged). Attach the identity when there is one. Throw 403 `AUTH_TAILNET_IDENTITY_MISSING` when `tailnet` and there is no identity, public or not (D8); throw 401 `AUTH_REQUIRED` when not `tailnet`, not public, and there is no identity. For a mutation, the expected origin is `entry?.origin`. Throw 403 `AUTH_ORIGIN_REJECTED` when it is missing or differs from the Origin header.
